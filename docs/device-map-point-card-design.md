# 设备地图「点位卡片」交互设计

> 可点击原型：`docs/device-map-point-card-prototype.html`（顶部「现状 / 新设计」对照）。
> 本文只回答三件事 —— **点一下之后出现什么 / 卡片上放什么 / 轨迹怎么展现**。
> 每一条先给现状证据（`file:line`），再给结论。

## 0. 本文件的位置与边界

用户口径：**「点击这个坐标点我感觉应该是出现一个悬浮的卡片而不是现在的抽屉，然后可以进行播放、
轨迹查询什么的」**。

**本文要做的**：点位浮卡的信息结构、就地动作的取舍、播放的承载形态、轨迹查询的完整交互与画法。

**本文不改的（把范围钉死）**：

| 不改 | 理由 |
| --- | --- |
| 点位**能不能显示出来** | 三条可见性契约已定（首轮不带视野 / `mapMarkerMinZoom` 上下互斥 / 单点 fit 钳 16），见 `device-map.md` |
| 聚合算法与气泡分级 | `count==1` 不聚合 + 4 档气泡，2026-09-21 已落地 |
| 标记点视觉（22px 水滴 pin / 在线青灰） | 已落地，本文只加一个 **selected** 态 |
| 列表视图的交互 | 列表语境是"管理一批"，地图语境是"看一个点"，两套不该合并（§10 单列） |

---

## 1. 一句话主张

> **地图上的点位，是「看这个点」的入口，不是「打开一份通道档案」的入口。**
>
> 凡是回答"这个点现在怎么样"的动作 —— 看一眼画面、看它走过哪 —— **就地在点上给**，不离开地图；
> 凡是"改它、管它"的动作 —— 才离开地图。而离开必须**有回来的路**。

这句话的推论是本设计最核心的一条取舍：
**地图不该被任何东西盖住**。用户点一个点，是为了"边看地图边判断"，
不是为了让一块 640px 的面板把刚看的东西盖掉。

## 2. 用户任务（JTBD）

| # | 任务 | 触发场景 | 用户期望 |
| --- | --- | --- | --- |
| T1 | **看一眼这一路现在是什么样** | 地图上发现一个点，想确认它是不是自己要找的那一路 | 点一下就能看到画面，**不用离开地图** |
| T2 | **知道这个点在哪、什么时候报的** | 判断点位是否可信（旧数据？别人的？） | 坐标 + 数据来源 + 多久以前 |
| T3 | **它最近走过哪** | 判断设备是否有位移、是否被盗、是否在巡逻 | 一条轨迹，能看出**动没动、动到哪** |
| T4 | **确认它是不是离线了** | 点位颜色/状态对不上预期 | 就地看到在线状态，而不是先打开档案 |
| T5 | **接着去管它**（改配置、云台、换安装位置） | 地图只是"找目标"的手段 | 一键切到管理面，且知道**怎么回到地图** |
| T6 | **找到刚才那个点** | 关了卡片后还想再看 | 点位有"刚才看过"的痕迹 |

⛔ **T1 是主任务，T5 是支线。** 现状把主支线做反了：点一下直接进 T5 的界面。

## 3. 现状诊断（用户视角，逐条给证据）

### P0-1 同一个对象，两套动作密度 —— 地图上只剩一个

**列表行**给了 6 个动作（`web/src/views/gb28181/device-mgmt/index.vue:2600-2645`，
`<a-table-column title="操作" :width="350" fixed="right">`）：
`播放` / `录像` / `停止` / `详情` / `编辑` / `删除`。

**地图点位**只有 1 个（`index.vue:998`）：

```js
element.addEventListener("click", () => openChannel(marker));
```

| 用户以为 | 实际发生 |
| --- | --- |
| 点一下 = "看看这一路" | 打开右侧 640px 抽屉，里面是**通道档案** |
| 抽屉里能播 | ⛔ 抽屉里 channel 详情的动作**只有**「编辑」和「复制编号」（`index.vue:3267`、`index.vue:3270`），**没有播放** |

⭐ 地图是"点位"最强的地方（用户在空间上指认了目标），动作密度却是最低的。
**动作密度应当与"用户此刻能指认得多准"同向，而不是反向。**

### P0-2 地图与列表共用同一个抽屉 ⇒ 地图被占掉

`openChannel`（`index.vue:1230`）同时服务两个语境：

- 列表行「详情」链接：`index.vue:2629`
- 地图标记点点击：`index.vue:998`

而抽屉是**固定 640px**（`index.vue:3186`：`<a-drawer v-model:visible="drawerVisible" :width="640" ...>`）。
底图区在抽屉右侧被压掉 640px；1024px 屏上几乎全盖。

| 用户以为 | 实际发生 |
| --- | --- |
| 点一个点，看一眼就关 | 地图被盖住，判断中断；要接着看别的点必须关掉抽屉 |

### P0-3 地图上根本没有"播放"这条路

`map-toolbar` 只有三件东西（`index.vue:3165-3174`）：缩放滑块（`mapZoom`）、
「定位点位」（`fitMapToData`）、「刷新地图」（`loadMapData`）。

全页播放入口只有两处，**都不在地图视图**：

- 列表行「播放」链接：`index.vue:2605-2607` → `playChannel(record)`（`index.vue:1662`）
- 卡片视图的「点播」按钮：`index.vue:3101-3102`
- 列表行的**双击播放**：`index.vue:1694`（`if (!isInteractiveDblclick(event)) playChannel(record)`）—— 地图点位**没有**双击行为

⇒ 从地图播放的完整路径 = **切回列表视图 → 找到那一行 → 点播放**。
用户心里的路径是"我指着它了，播它"。

### P0-4 「轨迹查询」在平台上没有出口：**数据在写，接口不存在**

这一条决定了这个需求能不能一次做完，必须先说清。

**数据是在的**：

- 写入方：`server/app/gb28181/subscribe/position.go:146`（`GbMobilePositionHistory{...}`），
  随 MobilePosition NOTIFY 一并落库
- 保留策略：`server/app/gb28181/subscribe/position_history.go`（按天清理），
  默认 **7 天**（`server/app/gb28181/controllers/service_config.go:20`：`defaultPositionHistoryRetentionDays = 7`）
- 220 开发库实测：**145 行 / 1 个通道（channel_id=3539）/ 2026-09-19 10:21 → 09-21 16:41**

**但查询接口一个都没有**。
`grep` 全仓只得服务配置那一对（`server/app/gb28181/routes/routes.go:705-706`）：

```
GET /api/gb28181/sip/service-config/position-history   ← 读「开关 + 保留天数」
PUT /api/gb28181/sip/service-config/position-history   ← 写「开关 + 保留天数」
```

那是**配置**，不是**查询**。⇒ 卡片上那个「轨迹」按钮，**今天点下去必然 404**。
后端要补什么见 §8（这是本设计里唯一"必须先做后端"的部分）。

### P0-5 实测数据把"行业标准轨迹查询"切掉了四项

把 220 库的 145 条真实采样拉出来算了一遍，结论直接约束设计：

| 事实 | 实测值 | 对设计的约束 |
| --- | --- | --- |
| 坐标确实在动 | 经度跨度 **55.94 m**、纬度跨度 **113.44 m**（≈126 m 对角线） | ✅ 轨迹线画得出来，不会退化成一点 |
| `speed` 字段 | **145/145 全为 0**（设备报了，恒 0） | ⛔ **不做速度着色**（数据是假的） |
| `direction` 字段 | 全为 0 | ⛔ **不做方向箭头** |
| `altitude` 字段 | 全为 0 | ⛔ 不做高度剖面 |
| 采样间隔 | 均值 1358 s，最小 **0 s**，最大 **65868 s（18.3 小时）** | ⛔ 不做等距时间轴；⛔ 不做"按真实时长"的回放动画 |

⭐ 行业标准轨迹查询的四件标配（**速度着色 / 方向箭头 / 里程统计 / 等距时间轴**）
在我们这套数据上**四件都做不到**。做了就是本仓最忌讳的东西 —— **伪数据**
（前例：OSD 的 `Length/Width` 滑杆，设备拒收改写却给了可编辑控件，见 `osd-overlay-design.md` §P0-2）。

**能诚实做的是**：采样点 + 真实时刻 + 平台自己按"位移 ÷ 间隔"估的均速（**标注"估算"**）
+ **把间隔断档画出来**。最后这条反而是我们比通用轨迹产品更有信息量的地方 ——
"这段时间数据不在"本身是运维要看见的事实。

### P1-1 点位没有"被选中"的表达

`createMarkerElement` 只给一个 class（`index.vue:990-996`）：`map-channel-marker` + 在线时 `online`。
没有 `selected`。⇒ 卡片关掉之后，用户无法知道刚才点的是哪个点（尤其点位密集时）。

### P1-2 点位上读不到"位置新鲜度"

`/map/markers` 已经返回 `positionStale` 与 `positionUpdatedAt`（`map.go` 的 `markerVO`），
但点位视觉上**完全没有体现**（只有气泡按在线率着色）。
⇒ "这个点的坐标是 3 天前的"这件事，只能打开抽屉才知道。

### P1-3 抽屉里的信息与"看点位"这件事的重合度很低

抽屉 channel 详情渲染的是 `kv-grid` 静态档案（`index.vue:3199-3220`）：
所属设备 / 厂商型号 / 摄像头类型 / 父级通道 / 坐标 / 当前流 …
再加挂载点与 48 格录像时间轴。这些是**"管通道"需要**的，
而"我刚才点的那个点是什么"只需要其中 3~4 行。

## 4. 设计语言（不新造，全部沿用母版）

母版 = `picture-settings-design.md` 的四条机制（`play-console-ux-architecture.md` §3 已把她们反推成 R1–R6）。
本模块的落法：

| 母版机制 | 本模块怎么落 |
| --- | --- |
| **M1 动作在画面、管理在面板** | 动作**在点位上**（浮卡）；管理**直达那件事该在的地方**（页内弹窗 / 播放控制台 / 「更多」），不再经过一个"装所有东西"的抽屉 —— 见 §6.8 |
| **M2 草稿与事实长得不一样** | 本模块**没有草稿**（点位卡片全是事实，没有"待下发"态）⇒ 这条**不适用**，别硬套。所有值都是事实层视觉（实线、无角标） |
| **M3 确认就近、有变更才出现** | 「播放」的结果**就近出现在地图上**（小窗），不是"丢到另一个弹窗里" |
| **M4 数值是二级表示；没有事实不给编辑；状态词不新造** | 坐标是二级表示（点开卡片才看全）；**轨迹没有接口 ⇒ 按钮禁用 + 说明**，不是点了报错；状态词直接用现有的「在线/离线」「上报/人工/目录」 |

⭐ **本模块唯一要新造的东西**：**轨迹面板**（因为它是新能力）。它沿用 `play-console-ux-architecture.md`
§3 的**三层词汇**：事实层（采样点、真实时刻）/ 估算层（⚠️ 平台估算均速，要带"估算"字样）/
不可用层（灰 + 原因，不给操作）。

## 6. 交互详设

### 6.1 卡片的出现与消失

**开**（三条路，都落到同一个"当前点位"）：

1. 点标记点（`index.vue:998` 的 click handler 改指向 `openPointCard(marker)`）
2. 点聚合气泡展开后的落单点（`expandCluster` 之后画出的标记点，同一条路）
3. （P1，后做）列表行右侧「在地图上定位」→ 切地图 + 打开卡片

**关**（四条路，**必须都收干净** —— 与 OSD 的 `exitXxxEditMode()` 同族纪律）：

| 路 | 说明 |
| --- | --- |
| 点地图空白 | `map.on("click")` 且事件目标不是标记点 |
| `Esc` | ⛔ 必须走 `stopPropagation()` 守卫：本页抽屉是 `a-drawer`、控制台是 `a-modal`，都在 `documentElement` 上挂 Esc（见 `play-console-ux.md` §「Esc 的归属」）。卡片作为最上层必须**吃掉**这一下 |
| 点另一个点 | **切换目标**，不是叠加（D7） |
| 卡片上的 `×` | 显式关闭 |

⛔ **卡片要被"收起来"而不是"关掉"**：拖地图 / 缩放导致点位出界时，
卡片转为**贴边的锚点小标签**（只剩一个圆点 + 通道名），点它重新展开。
理由：直接关掉会让用户以为"地图一动卡片就丢了"。

⛔ **卡片必须避让地图既有控件**：MapLibre 的 `NavigationControl`（右上）与 attribution（右下）
是**底图服务条款要求可见**的元素 —— 卡片锚在点位上方时，若点位本身靠右上/右下，卡片会压住它们。
**压住 attribution 是合规问题，不只是观感问题。** ⇒ 把控件所在的角当"禁区"，
与 §6.4 里小窗避让卡片是同一条纪律。（原型自测时正是卡片压住了左上角的注记，才补的这条。）

⛔⛔ **地图可视高度决定卡片能长多高 —— 实现前先量，别先画卡片。**
生产界面的地图区是 `flex: 1 1 auto; min-height: 460px`（`index.vue` 的 `.map-canvas`），
而"卡片锚在点位上方"要求卡片高度 + 点位上方留白 ≤ 容器高度。在 460px 的容器里，
**卡片上限约 300px**。原型实测：展开轨迹后卡片高 **455px** ⇒ 在 460px 容器里装不下，
必须二选一：

- **A（推荐）轨迹展开时卡片"局部收起"** —— 收掉事实行（坐标与来源在采样点列表里本来就有）、
  动作行压成一行图标；
- B 允许卡片盖住底图的一部分（但**绝不许盖住轨迹自己**）。

⭐ **不要**靠"把卡片做小一点"糊过去 —— 采样点列表与回放条都有可操作下限
（回放条 3 个按钮 + 滑轨 + 时刻 + 倍速 ≈ 240px 宽；列表一行要放下"时刻 + 坐标 + 间隔"三列）。

### 6.2 卡片的内容结构（三段）

```
┌────────────────────────────────────────────┐
│ ● 在线   前端球机              3402000000132…│ ← 对象行
│          通道 3539 · 设备 5147               │
├────────────────────────────────────────────┤
│ 位置   36.662311, 116.995036        [复制]  │ ← 事实行
│ 来源   移动位置上报 · 1 分钟前              │
├────────────────────────────────────────────┤
│  [▶ 播放]  [⟲ 轨迹]  [◎ 抓拍]               │ ← 就地动作（"看"，留在地图）
│  [⛶ 云台]  [✎ 编辑]  [⋯ 更多]               │ ← 离开去管（"管"，**直达目标，不再经抽屉**）
└────────────────────────────────────────────┘
```

⭐ **卡片上没有「详情」这个按钮了**（D2 退役，§6.8）。原来它承担的两件事被拆开：
「通道档案」留在**列表视图**（那边抽屉没退役）；「继续操作」变成直达按钮（云台 / 编辑 / 更多）。

**对象行**（数据来源 `/map/markers` 已有）：在线点 + 显示名（`displayName()`）+ 通道编号（可复制）
+ 设备编号。⛔ 不放"摄像头类型/厂商型号"——那是档案字段，不是"看点位"需要的。

**事实行**（数据来源同接口，**一行两列**）：

| 行 | 值 | 空/异常时 |
| --- | --- | --- |
| 位置 | `36.662311, 116.995036` → 点「复制」得 `116.995036,36.662311`（⛔ 复制顺序 = 经度在前，与地图粘贴习惯一致，但**显示 = 纬度在前**，与仓库现有 `kv-grid` 一致 —— 这条要显式写在卡片旁注里，否则复制出去没人知道顺序） | 不出现（没坐标的点本来就不在地图） |
| 来源 | `移动位置上报` / `人工录入` / `目录上报`（`positionSource`）+ 「1 分钟前更新」（`positionUpdatedAt`） | 来源空 → 显示「来源未记录」；时间为空 → 只显示来源 |
| 新鲜度 | **只在 stale 时出现**：琥珀行「位置数据已过期 · 最后上报 3 天前」 | 不 stale 就不占这一行（M3：有变更才出现） |

**动作行**：见 §6.3。

### 6.3 动作分组：判据是"这个动作的结果还需不需要看地图"

| 动作 | 权限码 | 结果要不要看地图 | 落点 |
| --- | --- | --- | --- |
| **播放** | `gb28181:play:start` | **要**（位置与画面要对上） | 地图上的**小窗**（§6.4） |
| **轨迹** | 复用 `gb28181:device:view`（⚠️ 见 §8-B2） | **要**（轨迹画在地图上） | 卡片**内联展开**（§6.5）+ 地图画线 |
| **抓拍** | `gb28181:device:snapshot` | 不要（但也不占屏幕） | 就地动作 + 卡片内的缩略位（回执落在这里） |
| **云台** | `gb28181:ptz:control` | 不要（要的是画面**结果**） | ⭐ **直达播放控制台的「云台控制」页**（`PlayConsoleLinked.vue:523`）—— **不再经抽屉** |
| **编辑** | `gb28181:channel:edit` | 不要 | 页内弹窗 `openEditChannelModal`（`index.vue:1814`，已有，直接复用） |
| **更多** | — | 不要 | 录像查询 `openRecordQuery` / 复制编号 / 删除（`gb28181:channel:delete`）/ 在列表中打开 |
| ~~详情~~ | — | — | ⛔ **已删除**（D2 退役）。通道档案留在**列表视图**，见 §6.8 |

⛔ **动作行的容量上限 = 3 + 3**。超出的收进「更多」。
理由：本仓已有反面教材 —— 列表行 6 个动作横排在 350px 里（`index.vue:2600`），
在卡片这个更窄的宽度里必须分两组。D2 退役后**恰好仍是 6 个**（详情 → 编辑），容量不变。

⭐ **门禁逐条照抄现有码，不新造**：`gb28181:play:start`（`index.vue:264`）、
`gb28181:device:snapshot`、`gb28181:ptz:control`（`index.vue:317`）、`gb28181:channel:edit`、`gb28181:device:view`。
没有权限的动作**不渲染**（本页既有口径），不是 `disabled`。

⭐ **云台为什么可以全屏、播放却不行**：两者都"要看画面"，但**空间是否仍是参照**不同 ——
播放时用户仍在对照"这个画面是地图上哪个点"，所以留小窗；云台一旦开始操作，用户的注意力
完全在画面**结果**上（转没转到位），地图此刻没有信息价值。判据同 §6.8：**用户此刻在做什么**。

### 6.4 「播放」：用小窗，不用全屏

**为什么不能直接用 `open()`**：

```ts
// web/src/store/modules/playback-console.ts:26-30
function open(nextChannel: PlaybackConsoleChannel) {
  channel.value = { ...nextChannel };
  displayMode.value = "expanded";   // ⛔ 显式置回全屏
  visible.value = true;
}
```

`open()` 会把 `displayMode` 重置为 `expanded`（全屏 modal），**地图立刻被盖住** —— 正是要避免的。

**做法**（机制已全在，是一条薄改动）：

```ts
playbackConsole.open(record);        // 先 open（拿通道上下文）
playbackConsole.minimize();          // 再收成小窗 ← 新增的这一行
```

- 小窗形态：`PlayConsoleLinked.vue:227` `miniPlayerModalStyle`（`position: fixed` + 可拖）
  + `.console-body.is-minimized`（`PlayConsoleLinked.vue:6953`）只留画面，隐藏侧栏/底栏/资源层
- 拖动手柄：`beginMiniPlayerDrag`（`PlayConsoleLinked.vue:5121`）
- 展开回来的按钮：`handleRestore`（`PlayConsoleLinked.vue:2352`）—— 已有，不用新增

**小窗首次出现的位置**：与卡片**避让**（卡片在中上部 ⇒ 小窗落右下角）。
⛔ 不能落在卡片上 —— 小窗一压卡片，用户就失去了"我刚在指哪个点"的锚。

### 6.5 「轨迹查询」：卡片就地展开为第二段

**时间范围**（三档，**上限由平台配置决定**，不是前端写死）：

| 档 | 值 | 备注 |
| --- | --- | --- |
| **24 小时** | 滚动 24h | ⭐ **默认**（Q2 定稿）—— "今天"从 0 点切，凌晨打开只有几十分钟数据，**看起来像"轨迹是空的"** |
| 今天 | 当日 00:00 → 现在 | 保留，供"就想看今天的"用；⛔ 不要设成默认 |
| 保留期内全部 | 读取 `positionHistoryRetentionDays`（`service_config.go:20`，默认 7 天）作为上限文案 | ⛔ 文案要写实际的保留天数；配置被改成 1 天后不能再写"最近 7 天" |

**展开后的卡片**：

```
┌────────────────────────────────────────────┐
│ ● 在线   前端球机              3402000000132…│
│ 位置   36.662311, 116.995036        [复制]  │
├────────────────────────────────────────────┤
│ ⟲ 轨迹    [今天] [24h] [保留期内(7天)]      │
│ 145 个采样点 · 跨度 126 m                   │
│ 平均间隔 22 分 · ⚠️ 均速约 0.3 km/h（估算）  │
├────────────────────────────────────────────┤
│  ◀ ▶  ─────●───────────────  16:41  ▮1× ▮4× │ ← 回放条（按序数步进）
├────────────────────────────────────────────┤
│ 16:41:08   36.662337, 116.995028   间隔 2 分│ ← 采样点列表（可滚动，当前点高亮）
│ 16:39:07   36.662351, 116.995127   间隔 1 分│
│ 16:38:24   36.662318, 116.995138   间隔 35 分│
│ ⋯                                          │
│ 16:29:01   36.662351, 116.995127   ⚠️间隔 6 时│ ← 断档行，琥珀
└────────────────────────────────────────────┘
```

⭐ **统计行的三条口径**（都在原型里体现）：

1. `跨度 126 m` = 采样点包围盒对角线，**不是里程**（里程需要按路径累加，且断档处会严重低估）
2. `均速估算` 必须带**「估算」**字样 —— 平台用 `位移 ÷ 间隔` 算的，设备上报的 `speed` 恒 0（P0-5）
3. `⚠️ 间隔 6 时` —— 超过阈值（建议 30 分钟）的相邻点**显式标出来**，因为"这段时间没有数据"
   是运维要看见的事实，而不是把它抹平

⛔ **不做的东西**（数据不支持，做了就是伪数据）：速度着色 / 方向箭头 / 高度剖面 / 里程统计 /
"停留点识别"（需要聚类算法，且我们的数据是静止的，识别出来的"停留"会覆盖全部采样点 —— 无信息量）。

### 6.6 轨迹在地图上的画法

**这是本页第一个真正的矢量图层**（在此之前全部是 DOM Marker，见 `device-map.md`）：

- `addSource(type: "geojson")` + `addLayer(type: "line")` 画折线；断档段**不连**（拆成多段 LineString）
- 采样点**默认不画**（145 个点会糊成一片），只在回放步进时高亮**当前点**（一个特殊 DOM Marker）
- 起 / 终点各一个标签；终点用点位的原标记点（它本来就是"现在在哪"）

⛔ **三条实现期硬约束**（都会静默失败）：

1. **`setStyle` 之后图层全丢** —— 本页 `darkMode` 变化会重建样式（控台侧同族问题见 `device-map.md`），
   轨迹图层必须挂 `map.on("styledata")` 重加，或改为"样式切换时清掉轨迹"（推荐后者，简单且不会错）
2. **卡片内容元素是 `createElement` 造的 ⇒ 样式必须 `:deep()`**
   （本页已踩过：`map-cluster-marker` 裸选择器一条不生效，用户看到白底黑字方块）
3. **点地图空白要关卡片** —— 而轨迹层的 `click` 也会冒泡上来
   ⇒ 轨迹/折线图层 `click` 要 `stopPropagation`，否则"点轨迹线也会关卡片"

### 6.7 与列表视图的关系（P1，可后做）

地图与列表共享同一个"当前点位"：列表里选中某行 → 点该行右侧「在地图上定位」→ 切地图 + 打开卡片。
⛔ **不合并两个视图**（列表语境是"批量管理"，需要表格列，与浮卡信息结构正相反）。

### 6.8 抽屉退役：边界、替代、代价（2026-09-21 老板拍板）

**⚠️ 先纠一个容易做错的理解**：本页只有一个 `a-drawer`（`:3186`，固定 640px），
它**同时承载两种对象** —— 靠 `drawerTarget.type` 切换：

| 抽屉 | 入口（`index.vue`） | 现状 | 本次处置 |
| --- | --- | --- | --- |
| **通道详情** | 地图标记点 `:994` | 点一下就盖住地图（P0-2） | ⛔ **切断** → 改走卡片 |
| **通道详情** | 列表行「详情」`:2629` | 同抽屉 | ✅ **保留** |
| **设备详情**（7 页签 `:3314-3553`） | 设备列表 `:2797` / `:2909` | 同抽屉 | ✅ **不动** |

⭐ **所以「抽屉退役」在实现上 = 切断 `index.vue:994` 这一行入口，不是删除抽屉组件。**

**为什么这样切才是对的**（判据一句话：**容器跟着语境走，不跟着组件走**）：

- 地图的语境是**看空间** —— 容器必须**让出**空间，所以用浮卡；
- 列表的语境是**看清单** —— 容器本来就该占位，抽屉正合适（且列表**没有地图锚点**，浮卡无处可锚）；
- 设备详情是**另一个对象**（地图点位是**通道**，不是设备），7 个页签装不进浮卡，也与我们讨论的场景无关。

⛔ **不做的三件事**（做了就是越界）：
1. 不删设备详情抽屉的 7 个页签 —— 它是设备列表的宿主；
2. 不删通道抽屉的模板与状态（`channelDetail` / `drawerTarget` 的 channel 分支）—— 列表还在用；
3. 不把「设备信息 / 设备控制 / 基本参数 / 录像存储 / 报警控制 / 设备状态 / 存储卡」搬进浮卡
   —— 它们与"看点位"的重合度低（P1-3），且 §13 那条硬约束不允许（卡片上限约 300px）。

**「管」的动作去新家**（逐条见 §6.3）：

| 原来怎么办 | 现在怎么办 | 机制是否已存在 |
| --- | --- | --- |
| 「详情」→ 开抽屉看档案 | 卡片上没有这个按钮；**档案留列表视图** | — |
| 「云台」→ 开抽屉并落到「设备控制」页 | **直达播放控制台**的「云台控制」页（`PlayConsoleLinked.vue:523`） | ✅ 已存在 |
| （无此按钮） | 「编辑」→ 页内弹窗 `openEditChannelModal`（`:1814`） | ✅ 已存在 |
| 列表行的其余动作 | 「更多」→ 录像查询 / 复制编号 / 删除 | ✅ 已存在 |

⭐ **代价（诚实写出来）**：地图上**不再能查通道档案**。
兜底 = 卡片「更多 → 在列表中打开」（切到列表视图并定位到该行）。
⛔ 不要试图"把档案塞进卡片"糊过去 —— §13 的硬约束（卡片上限约 300px，而展开轨迹已 455px）
决定了它装不下。

**实现注意**

- `openChannel(record)` **保留**（列表 `:2629` 还在调），只是地图那条不再调它；
- 新增 `openPointCard(marker: MarkerPoint)` 与它**并存**，⛔ 不要改造成"参数可选、走两条路"
  —— 两个容器的生命周期（抽屉有 `unmount-on-close`、卡片随地图事件开关）完全不同；
- 卡片同时**消费**一次 `getChannel`（`:1235`）拿最新的位置/来源/在线态：
  标记点数据可能已过期（地图是 15s 轮询、详情是点击时拉），**卡片要显示后者**。

## 10. 本模块之外（单列，**不并入**上述结论）

- **列表视图的动作密度**：6 个动作横排 350px（`index.vue:2600`）本身可讨论，但那是**列表**的语境，

- **`map-toolbar` 缺"按状态筛选"**（`index.vue:3165`）：只有缩放/定位/刷新，没有"只看在线"。
  这是地图工具条的独立问题。
- **`bucket.icon.opacityVertexArray` 断言**（maplibre `placement.ts:1240`）：来自底图样式自身符号图层，
  与本文无关（本页只用 DOM Marker）。⚠️ 但 §6.6 一旦给轨迹加了 `line` 图层，
  排查底部渲染问题时**不要**再把这条断言归给"底图"——届时要重新判（line 图层不产生 icon 顶点，
  理论上仍无关，但要在现场复验一次再下结论）。
- **`gb_device_target_track`（D-1 目标跟踪）**：名字里有 track，
  但那是**设备对画面内目标的跟踪**（会话级），与本文的**设备自身位置历史**是两件事。
  ⛔ 设计轨迹 UI 时别去复用它的表与接口。

| **Q4** | 卡片跟随点位 vs 固定在屏幕边 | ✅ **跟随点位**，出界收成锚点标签（§6.1） | "卡片属于这个点"。固定在屏幕边会让用户分不清它在说哪个点 —— 尤其地图上不止一个点的时候 |
| **Q5** | 「1 分钟前」相对时间 vs 绝对时刻 | ✅ **相对为主 + hover / 点按显示绝对** | 相对时间让人一眼判断新鲜度（"1 分钟前" vs "3 天前"）；绝对时刻留给要核对的运维场景 |
| **Q6** | 是否需要"位置历史开关"的门禁提示 | ✅ **需要** | 配置 `Enabled=false` 时，「轨迹」**既不隐藏也不置灰**，点了给明确说明：「平台未开启位置历史记录」（指向 `SIP 服务配置 → 位置历史`）。⛔ 隐藏/置灰会让用户以为**是本通道坏了** |

断档行立刻从 2 变成 3（下面第 1 条）。

### 自测中改掉的三处（都是"看代码看不出来"那类）

| # | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 断档行数 = **3**（应为 2），"37 秒"被标成断档 | 拿**显示文案** `parseInt("37 秒")` = 37 去比阈值 30 —— 秒和分的数字不可比 | 间隔改**结构化数值**（`gapMin`，单位分钟）+ 展示用 `gapText`。⭐ 通用形：**判据不许从显示文案反解** |
| 2 | 折线画偏，与点位对不上 | 轨迹 SVG 用了 `preserveAspectRatio="slice"` ⇒ 折线在 viewBox 坐标系、点位（CSS 像素）在另一套坐标系 | 把 `viewBox` 设成**容器实际像素尺寸**，1:1 对应。底图（抽象示意）用 slice 无所谓 |
| 3 | 卡片压住折线；起点 / 终点 / 点位三个标签叠在一起 | 布局没做几何校验 | 用 `getBoundingClientRect()` **脚本化断言两两不重叠**（见下），不靠眼睛；标签收敛成**只标起点**（终点由点位本身承担，时刻由回放条承担） |

几何断言（可直接抄）：

```js
var c = card.getBoundingClientRect(), p = pin.getBoundingClientRect(),
    t = document.querySelector('#traj line').getBoundingClientRect(), m = map.getBoundingClientRect();
function ov(a, b) { return !(a.right < b.left || a.left > b.right || a.bottom < b.top || a.top > b.bottom); }
// 判据三条：卡片不压点位 / 卡片不压折线 / 卡片完整落在容器内
```

### ⭐ 一条从原型长出来的真实约束

**地图可视高度决定卡片能长多高**（见 §6.1）。展开轨迹后卡片实测 **455px**，
而生产界面地图区 `min-height: 460px`（`index.vue` 的 `.map-canvas`）——
**装不下**。⇒ 实现期要么让卡片在轨迹展开时"局部收起"，要么先量容器高度再定卡片结构。

### ⭐ 另一条：轨迹的**真实形状**是竖长条

等比例画出来是"南北 113 m × 东西 56 m"的竖条 + 抖动，不是一条漂亮的巡逻动线。
原型如实画成竖条并配 **50 m 比例尺**。
横向拉伸可以让它"好看"，但会让人以为设备横向移动了上百米 —— 那是伪造（§P0-5 同族）。
