# 前端开发规范

## 组件使用原则

### 1. 优先使用 Arco 组件

禁止在业务页面中直接使用原生 HTML 控件替代已有的 Arco 组件。

例如：

- 弹窗优先使用 `a-modal`
- 抽屉优先使用 `a-drawer`
- 按钮优先使用 `a-button`
- 开关优先使用 `a-switch`
- 单选和分段选择优先使用 `a-radio-group`
- 进度展示优先使用 `a-progress`
- 状态展示优先使用 `a-badge`

使用组件库可以保持交互、键盘操作、禁用状态、主题色和暗色模式的一致性。

### 2. 优先复用已有封装组件

如果项目中已经存在满足需求的业务封装组件，应直接复用，不在页面中重新实现同类结构和交互。

使用前先检查：

1. `web/src/components/`
2. 当前业务模块的 `components/` 目录
3. 同一业务模块下已有的 Dialog、Drawer、Panel 和表单组件

复用组件时，应通过明确的 props、events 或 slots 适配业务差异，不复制组件源码后再局部修改。

### 3. 新组件先封装再使用

如果所选组件尚未进行统一封装，应先为它建立可复用的封装组件，再在业务页面中使用。

封装至少应统一：

- 主题类名和暗色模式
- 尺寸和响应式行为
- 标题、关闭和确认交互
- loading、disabled 和错误状态
- 对外 props、events 和 slots
- 必要的组件测试

例如，系统 Dialog 应统一使用 `a-modal` 并接入 `uvp-system-dialog`，不允许每个页面自行定义一套弹窗背景、边框、圆角和暗色样式。

## 组件选择顺序

实现一个新的交互时，按以下顺序决策：

1. 查找 Arco 是否已有对应组件。
2. 查找项目是否已有同类封装组件。
3. 如果没有同类封装，先创建通用封装，再接入业务页面。
4. 只有在 Arco 和项目封装都无法满足需求时，才考虑原生控件或自定义实现，并在代码评审中说明原因。

## 代码评审要求

以下情况应在评审中退回修改：

- 已有 Arco 组件却自行编写原生按钮、弹窗、开关或进度条。
- 已有业务封装组件却在页面中复制实现。
- 新增同类交互却没有提取可复用组件。
- 自定义组件没有接入项目主题变量或暗色模式。
- 自定义组件没有覆盖 loading、disabled、关闭和错误状态。
