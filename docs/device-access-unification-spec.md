# 目标

扫码配网和 GB/T 28181-2022 抓拍回传统一使用平台提供的设备接入入口。
标准部署通过 Nginx 进入后端；开发环境允许使用开发代理，不要求开发者先安装 Nginx。
取消用户维护两项业务地址的要求，同时保持扫码、控制台抓拍和 OpenAPI 抓拍可用。

# 用户故事

- 管理员部署平台后，可以直接生成接入二维码、下发抓拍，无须填写扫码和抓拍基址。
- 开发者启动前后端后，可以用同一局域网中的手机或设备测试扫码和真实抓拍回传。
- 开发者测试需要麦克风的 HTTPS 管理页面时，设备接入不会被迫使用设备不信任的证书。
- 现有用户升级后，不会因残留的旧地址配置继续连接旧主机或旧端口。
- OpenAPI 调用者可以创建抓拍会话，不因删除业务地址配置导致抓拍能力消失。

# 验收标准

1. 国标服务配置页面不再提供“扫码配网地址”和“2022 抓拍回传地址”输入项。
2. 两项旧地址配置退出生效链路；不把输入项转移到另一页面或要求用户手改配置文件。
3. 安装与启动流程不再要求填写或自动写入上述两项旧业务地址配置。
4. Linux、Windows 和容器标准部署的扫码、抓拍默认通过 Nginx 入口访问后端。
5. 开发环境以本机局域网 IP 打开管理页面后，可以生成二维码、兑换 SIP 信息、
   创建抓拍会话、接收图片和完成通知，并读取图像；不要求安装 Nginx 或配置两项业务地址。
6. 开发代理正确承接二维码落地页、兑换接口和抓拍上传接口，不返回 SPA 页面冒充业务响应。
7. 非标准端口不会在生成地址时丢失；公网部署按实际对外入口工作。
8. 使用 localhost 或回环地址访问时，不下发指向其他设备自身的无效地址；
   无法确定有效入口时明确提示使用设备可访问的局域网入口。
9. 管理页面启用自签 HTTPS 时，设备接入仍有可用的兼容入口；
   不要求设备关闭证书校验，不默认假设浏览器信任等于设备信任。
10. HTTP 上传不依赖设备跟随管理页面的 HTTPS 重定向；POST、PUT 上传内容和令牌保持完整。
11. OpenAPI 抓拍不会因旧配置消失而取消注册；上传和完成通知仍能关联原始会话。
12. 扫码的一次性令牌、有效期和兑换权限，以及抓拍的令牌和会话权限保持有效。
13. 不允许任意伪造的转发头改变设备接入入口。
14. 上述标准场景由自动化测试覆盖；真实设备扫码、上传、完成通知和图片读取另行记录实际结果。

# 非目标

- 不修改 SIP 注册地址、端口、域或媒体传输规则。
- 不增加新的用户可配置业务基址。
- 不自动建立网络路由、端口映射或信任任意自签证书。
- 不自动推断多网卡、分离网络和任意 NAT 映射中未被平台或入口暴露的可达地址。
- 不部署到远程服务器，不改动本次需求之外的工作区修改。

# 入口边界

- 仅访问 localhost 时，默认要求改用局域网 IP，不静默猜选某张网卡。
- 自签 HTTPS 管理页面对应独立的设备 HTTP 入口；标准部署和开发模式均自动提供该入口。
- 外部代理终止 TLS、使用非标准端口时，仅接受既有可信代理提供的对外入口信息。
- OpenAPI 通过请求上下文复用同一设备入口规则，不依赖旧配置。
- 现有配置文件中的旧字段不再读取或写入，不得以旧值覆盖新入口规则。

# 已确认技术方案

- Nginx 与 Vite 强制覆盖 X-UVP-Device-Base-URL，后端仅接受回环或既有可信代理网段提供的信息；普通转发头不能单独改变入口。
- Nginx 明文入口保留原始 Host/端口；自签 HTTPS 管理入口指向同机实际 HTTP 设备端口。既有可信上游 TLS 代理保留其对外协议与 Host/端口。
- Vite HTTP 默认共用 5177；开启开发 HTTPS 时自动增加实际开发端口加一的 HTTP 设备监听，端口冲突明确失败。
- 请求上下文共享同一次解析结果，二维码、控制台抓拍和 OpenAPI 使用它；二维码服务不再保存共享可变基址。
- SIP 级联抓拍没有浏览器请求，复用数据库里的 SIP 接入地址及启动器提供的实际 Nginx HTTP 端口；不引入可编辑业务 URL。未知 NAT 映射不猜测。
- 旧 YAML 地址段与前后端字段退出读取、写入和业务生效链路。

# 开发环境测试

- 默认开发服务监听 `0.0.0.0:5177`。使用 `http://<局域网-IP>:5177` 打开管理页面后，
  二维码、抓拍下发与设备上传都经 Vite 代理，地址自动使用该局域网入口；`localhost`
  和回环地址会被后端拒绝下发，不能用于真机或设备联调。
- 需要 HTTPS 管理页面时，设置 `VITE_DEV_HTTPS=true` 并准备开发证书。页面仍在
  `https://<局域网-IP>:5177`，Vite 会自动增加 `http://<局域网-IP>:5178` 作为设备入口；
  下发给设备的二维码和抓拍上传地址使用 5178，而不是开发 HTTPS 证书。
- 联调机器与设备之间应放行相应的 TCP 端口：HTTP 模式放行 5177；HTTPS 模式同时放行
  5177 和 5178。5178 被占用时开发服务会启动失败并明确提示，不存在额外业务地址配置。

# 任务与测试清单

1. 移除配置入口与 DTO → 页面不显示、不提交旧字段；后端不输出旧字段、旧输入不生效。
2. 统一入口解析 → 覆盖直连、可信/非可信代理、IPv6、非标准端口、无效基址、localhost 拒发。
3. 切换二维码与抓拍 → 不同请求入口相互隔离；一次性兑换保持；控制台与 OpenAPI 的 UploadURL 使用相同入口。
4. 切换部署及开发代理 → 新生成配置无旧段、脚本不再写旧字段；二维码 GET、兑换 POST、图像 PUT 保留路径和 body；HTTPS 对应真实 HTTP 监听。
5. 验证 → 相关 Go/Vitest 测试、部署生成器/语法、前端类型检查/构建、后端构建及 diff 检查。真实设备与生产部署另记，不以单测替代。
