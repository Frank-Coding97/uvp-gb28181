# 已确认的范围

- 面向 Linux（amd64/arm64）及 Windows 绿色独立包内置 Nginx。
- 页面提供 HTTPS 开关、HTTPS 端口及端口检测、证书与私钥上传。
- 关闭 HTTPS 后，通过现有 Nginx HTTP 端口访问管理页面；HTTPS 开关不关闭 ZLMediaKit 的 HTTPS/WSS。
- 上传证书提供“同时同步到 ZLMediaKit”选项。勾选后更新 ZLM 独立 PEM 并重启 ZLM；不勾选则保留其原证书。
- 同步提示：“同步证书需要重启 ZLMediaKit，正在进行的预览、回放、推流及对讲可能中断，需要重新连接。”
- 提交前确认本次影响范围；仅更新 Nginx 时重载 Nginx，不重启 ZLM。
- 页面展示配置、执行结果与实际生效状态；切换协议或端口后提供新访问地址。
- 不控制外置 Nginx、Nginx Proxy Manager、Compose 代理或远程 ZLM 节点；不包含自动申请及续签证书。

# 已确认实施约束

- 同步选项默认勾选；用户可取消。只有上传新证书才会触发同步及 ZLM 重启。
- 证书校验请求只在内存处理；multipart 临时材料及时清理，不长期暂存。应用时重新校验，正式文件使用包内固定路径，不接受客户端路径或命令。
- 后端使用 Go 标准库校验证书、私钥及匹配关系；首版接收 PEM 格式证书链与未加密 PEM 私钥。
- Nginx 和 ZLM 各自保留证书材料；首次安装可初始化为同一套，之后启动不能无条件覆盖 ZLM。
- Linux ensure_tls_material 仅在 ZLM 独立 PEM 缺失时初始化；已有文件在普通启动时保留。
- Windows 按当前 vendor/zlm 下独立 PEM 的实际启动路径处理，保留中文及空格路径支持。
- 服务控制限定为已识别安装目录内的固定操作，沿用运行身份；权限不足返回明确原因，不开放任意命令或提权接口。
- Nginx 配置校验通过后才应用；失败恢复旧配置与证书，并重新检查服务。
- Nginx 与 ZLM 的变更分别报告结果；恢复失败标为需要处理，不宣称已回滚成功。
- 当前工作区有大量既有改动；只修改本功能必需部分，不覆盖或提交无关内容。

### 顺带修掉的启动故障（默认关闭后必踩）

关闭态的渲染结果会把独立 HTTP 段合并进入口 server 并删掉 `UVP_HTTP_BEGIN..END`。
旧逻辑每次启动都把**当前 conf** 当 base 存下来 ⇒ 第二次启动时 base 里已经没有 HTTP 段，
`Render` 解析不到端口，`uvp-setup https-render` 失败 ⇒ `ctl.sh` 停在这一步「应用 HTTPS 配置失败」。
根因与表现完全对不上（既不是证书也不是端口占用）。已改为只在 conf **未渲染**（不含
`/__uvp_https_probe`）时才更新 base。
