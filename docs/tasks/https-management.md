# 已确认的范围

- 面向 Linux（amd64/arm64）及 Windows 绿色独立包内置 Nginx。
- 页面提供 HTTPS 开关、HTTPS 端口及端口检测、证书与私钥上传。
- 关闭 HTTPS 后，通过现有 Nginx HTTP 端口访问管理页面；HTTPS 开关不关闭 ZLMediaKit 的 HTTPS/WSS。
- 上传证书提供“同时同步到 ZLMediaKit”选项。勾选后更新 ZLM 独立 PEM 并重启 ZLM；不勾选则保留其原证书。
- 同步提示：“同步证书需要重启 ZLMediaKit，正在进行的预览、回放、推流及对讲可能中断，需要重新连接。”
- 提交前确认本次影响范围；仅更新 Nginx 时重载 Nginx，不重启 ZLM。
- 页面展示配置、执行结果与实际生效状态；切换协议或端口后提供新访问地址。
- 不控制外置 Nginx、Nginx Proxy Manager、Compose 代理或远程 ZLM 节点；不包含自动申请及续签证书。

# 已确认实施约束

- 同步选项默认勾选；用户可取消。只有上传新证书才会触发同步及 ZLM 重启。
- 证书校验请求只在内存处理；multipart 临时材料及时清理，不长期暂存。应用时重新校验，正式文件使用包内固定路径，不接受客户端路径或命令。
- 后端使用 Go 标准库校验证书、私钥及匹配关系；首版接收 PEM 格式证书链与未加密 PEM 私钥。
- Nginx 和 ZLM 各自保留证书材料；首次安装可初始化为同一套，之后启动不能无条件覆盖 ZLM。
- Linux ensure_tls_material 仅在 ZLM 独立 PEM 缺失时初始化；已有文件在普通启动时保留。
- Windows 按当前 vendor/zlm 下独立 PEM 的实际启动路径处理，保留中文及空格路径支持。
- 服务控制限定为已识别安装目录内的固定操作，沿用运行身份；权限不足返回明确原因，不开放任意命令或提权接口。
- Nginx 配置校验通过后才应用；失败恢复旧配置与证书，并重新检查服务。
- Nginx 与 ZLM 的变更分别报告结果；恢复失败标为需要处理，不宣称已回滚成功。
- 当前工作区有大量既有改动；只修改本功能必需部分，不覆盖或提交无关内容。

| 用例 | 输入或操作 | 期望输出 |

# H02 — 上传与证书校验

任务：成对接收证书链与私钥，校验后返回证书摘要信息供确认；应用请求重新上传并校验，不长期暂存私钥。

| 用例 | 输入或操作 | 期望输出 |
| --- | --- | --- |
| H02-1 | 匹配的 RSA / ECDSA PEM 证书链与私钥 | 校验通过；显示主体、有效期与指纹，不回传私钥。 |
| H02-2 | 缺少文件、坏 PEM、不匹配私钥、加密私钥、过期或尚未生效证书 | 返回具体原因；正式证书与运行状态不变。 |
| H02-3 | 超限文件、伪造路径或上传中断 | 拒绝或清理暂存文件，不写入客户端指定路径。 |

# H03 — Nginx HTTPS 开关、端口与应用

任务：两平台配置渲染支持 HTTPS 开关与端口，保留现有前端、API、上传及代理路由；应用前校验，成功后检查入口。

| 用例 | 输入或操作 | 期望输出 |
| --- | --- | --- |
| H03-1 | 关闭 HTTPS | HTTP 管理页可访问且不跳 HTTPS；Nginx 新连接不再提供 HTTPS；ZLM 状态不变。 |
| H03-2 | 开启 HTTPS、修改为可用端口 | 配置校验及 TLS 探测通过，返回新入口；证书指纹与配置一致。 |
| H03-3 | 非法端口、被其他进程占用、继续使用自身原端口 | 非法及冲突拒绝；自身原端口不误报；检测成功不保证后续应用不会发生竞争。 |
| H03-4 | 配置校验失败或应用期间端口被占用 | 返回真实错误并恢复旧入口；恢复失败单独报告。 |
| H03-5 | HTTPS 关闭后整包重启；API、上传及媒体代理请求 | 保持关闭状态，HTTP 路由正常；启动预检、健康检查及访问地址适配当前协议。 |

# H04 — ZLM 可选证书同步

任务：拆开首次证书初始化与后续更新，按提交选项应用独立 PEM；同步时只重启目标内置 ZLM，验证其 TLS。

| 用例 | 输入或操作 | 期望输出 |
| --- | --- | --- |
| H04-1 | 上传新证书并取消同步 | 仅 Nginx 指纹变化；ZLM PID、PEM 内容及对外指纹不变。 |
| H04-2 | H04-1 后整包停止再启动 | ZLM 仍加载原证书，不被 Nginx 新证书覆盖。 |
| H04-3 | 勾选同步并确认应用 | 提示重启影响；生成私钥加证书链 PEM；ZLM 重启，HTTPS/WSS 实际指纹与上传证书一致。 |
| H04-4 | 管理 HTTPS 关闭时同步证书 | Nginx 保持 HTTP 管理入口，ZLM HTTPS/WSS 继续开启并使用新证书。 |
| H04-5 | ZLM 重启失败或 TLS 校验失败 | 报告 ZLM 失败，尝试恢复旧 PEM 并验证；Nginx 结果单独显示，不伪装整体成功。 |
| H04-6 | 首次安装无独立 PEM；已有 PEM 的旧安装包 | 首次初始化可用证书；已有材料不被无条件替换。 |

## 实施结果

- H01：新增状态、端口检测、证书校验及异步应用接口；复用 protected 组与配置更新权限，提供四种数据库权限迁移。私钥上传在鉴权前即排除审计请求体采集。
- H02：PEM 配对、日期、大小校验及摘要返回；固定正式路径，临时文件清理，不回传私钥。
- H03：两套模板保留全部业务路由，启动读取持久配置；应用前校验、重载后检查入口模式与 TLS 指纹，失败恢复配置和证书。恢复材料保存到 data/https/recovery.json（0600），正常结束清理；恢复失败或进程中断后保留，并阻止后续操作覆盖。文件中的 data 为 base64 原材料，恢复前须由运维核对路径、内容及实际服务状态。
- H04：同步前检查 ZLM 原 PEM 可恢复性，证书独立保存；同步只调用 restart-zlm 并核对 HTTPS 和 signalingSslPort 两个入口。ZLM 失败不撤销已成功的 Nginx；原 PEM 恢复后再次探测，无法确认恢复则明确标记。过期的原证书仍可作为恢复材料。
- H05：系统配置新增 HTTPS 页签，默认勾选同步；提示及二次确认说明重启影响。确认内容使用同一份配置与文件快照；已确认应用成功后清空上传材料，避免后续保存意外重复重启。状态文案中文化，切换访问入口断连不直接判成功。
