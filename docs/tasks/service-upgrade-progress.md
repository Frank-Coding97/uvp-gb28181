## T1 上传进度数据

- [x] 为离线上传 API 增加可选进度回调，页面保存本次文件名、大小及上传状态。
- [x] 先补 API 与页面测试并看到失败，再实现回调与状态更新。

| 描述 | 输入 / 动作 | 期望输出 |
| --- | --- | --- |
| 回调透传 | 上传文件并传入进度回调，模拟 HTTP 上传事件 | 回调接收真实事件；原有 multipart、超时及异步响应契约保持不变。 |
| 初始和中途进度 | 选择 10 MiB 文件；已传 4 MiB | 立即出现文件名和上传状态；显示 4 / 10 MiB、40%，不提前显示成功。 |
| 传完但未受理 | 上传事件达到 100%，HTTP 响应尚未返回 | 显示等待服务端受理，不允许据此应用升级，不显示升级成功。 |
| 无可靠总大小 | 缺少可靠总大小，已收到上传字节数据 | 展示已传大小与处理中状态，不出现 NaN、无限值或虚构百分比。 |
| 上传失败和重新选包 | 上传拒绝后重新选择其他包 | 展示失败原因；新上传从新文件的初始状态开始，旧任务结果不覆盖它。 |

完成条件：本任务 API / 页面测试通过。

## T2 导入进度区

- [x] 在版本卡下展示上传、后台校验、升级包就绪三个步骤，替换原有导入文字提示。
- [x] 保留既有异步查询和刷新恢复机制，展示任务的真实状态。

| 描述 | 输入 / 动作 | 期望输出 |
| --- | --- | --- |
| 排队和后台校验 | 服务端先返回 queued，再返回 verifying | 当前步骤显示排队或校验中；不编造后台百分比；仍不能据此应用。 |
| 校验完成 | 同一任务返回 succeeded 及完整制品信息 | 显示升级包就绪与可信目标版本，保留主动创建任务与确认流程，不自动应用。 |
| 校验失败 | 返回 failed 和签名错误 | 显示校验失败与原因，不标记就绪，不使用旧包结果冒充本次成功。 |
| 刷新恢复 | 存储已有任务标识，重新挂载页面 | 查询原任务并恢复阶段；不伪造本次上传速度或已传字节。 |
| 查询断线并恢复 | 校验中查询失败，随后同一任务查询成功 | 保留最后状态并显示正在重连；恢复后继续该任务，失败查询不推断成功。 |

完成条件：上述页面行为测试及现有导入回归通过。

## T3 应用升级步骤

- [x] 顶部和任务详情复用进度展示组件；以 task_id 关联实际任务。
- [x] 展示准备与授权、备份、迁移、切换与验证、完成五组步骤，以及当前具体阶段。

| 描述 | 输入 / 动作 | 期望输出 |
| --- | --- | --- |
| 等待授权 | awaiting_confirmation | 明确显示等待确认，不误显示正在停服，不自动调用应用 API。 |
| 执行阶段 | 逐一返回 fetching、verifying、preparing、stopping、backing_up、migrating、activating、validating、committing | 对应步骤高亮并显示真实阶段；未结束时不显示升级成功；无整体虚构百分比。 |
| 成功终态 | 同一任务返回 succeeded | 明确显示完成，记录详情仍可查看结果。 |
| 失败及回退 | failed + failure_phase；rolled_back；recovery_required | 分别显示失败位置、已恢复旧版本、需要恢复；回退不显示目标版本升级成功。 |
| 未知阶段 | 未识别的 phase | 如实提示未知状态，不映射为已完成。 |
| 服务重启期间 | 活动任务状态请求失败，随后恢复 | 保留最近任务并显示重连；恢复后更新同一任务，旧成功记录不覆盖当前活动任务。 |
| 其他任务与历史详情 | 历史有成功任务，同时新任务执行中；打开旧任务详情 | 顶部显示当前活动任务，抽屉显示选中的历史任务，不混淆两个结果。 |

完成条件：上述组件 / 页面行为测试及现有授权与版本刷新回归通过。
