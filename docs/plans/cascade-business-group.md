# 当前证据

- `GbCascadeDeviceProjection`、`GbCascadeChannelProjection` 已通过 `PlatformID` 隔离共享授权与发布编号。
- `ProjectionRevision` 和事务条件更新已经保护共享替换，业务树沿用同一修订号，防止共享与业务目录相互覆盖。
- `PublishGroup` 目前仅保存开关；`catalog.Build` 没有生成 215/216 节点。
- 出站查询与主动推送均调用 `buildCascadeCatalogSnapshot`，其最后执行 `ChannelsOnly()`，会过滤所有容器并清空 ParentID。只修改前端或 Build 无法发布业务树。
- 出站响应 DTO 尚无 `BusinessGroupID`；Catalog 查询只接受本平台身份，尚不支持业务根或虚拟组织目标。
- 下级接入目录已有 215/216 模型，但属于来源目录，不能直接当作某上级的共享授权目录。

# 页面与操作

1. 国标级联表格增加“业务分组”操作，打开当前平台业务目录管理弹窗。
2. 左侧树展示一个业务根和嵌套虚拟组织；右侧维护选中节点以及当前平台已共享通道的挂载。
3. 首次进入明确显示“尚未配置业务分组”，显式创建根；不批量改写旧平台配置。
4. 根和虚拟组织编码给出类型规则及 20 位计数。可提供默认编号建议，保存前服务端校验冲突；编号保存后稳定，不按名称重新生成。
5. 挂载使用后端已共享通道快照；需要共享新通道时回到现有“共享”操作，不由目录编辑隐式授权。
6. 页内操作复用级联查看/共享权限；保存、刷新、推送分别显示结果和错误。过期修订号保留编辑内容并要求重新载入。
7. 五步连接向导保留现有职责；第四步提示发布开关与业务分组入口的关系。

# 数据与接口

- 新增平台专属业务节点模型：平台 ID、发布国标编号、节点类型（根/虚拟组织）、名称、父虚拟组织编号、排序等必要字段。
- 新增平台专属通道挂载模型：平台 ID、源通道 ID、目标虚拟组织编号；同平台源通道唯一。
- 使用独立模型，不直接修改下级上报目录。业务根数量、编号唯一性、节点类型、树无环和授权范围在保存事务中验证。
- 增加 `GET/PUT /api/gb28181/cascade/platforms/:id/business-group`；GET 返回节点、挂载、已共享资源以及 `revision`；PUT 全量保存该小型配置树，携带 `expectedProjectionRevision`。
- PUT 在事务中读取当前共享投影，再校验并保存节点和挂载，条件更新 `ProjectionRevision`。无效输入整体回滚。
- `ProjectionSnapshot` 纳入业务节点与挂载，目录树和播放授权来自同一平台快照。
- 取消共享时清理对应业务挂载；重新共享不恢复旧业务归属。删除/复建上级平台时清理旧树，避免继承历史分组。
- 新表纳入现有迁移与数据库初始化流程，覆盖 MySQL、PostgreSQL、SQLite、SQL Server；保留当前其他工作对数据库基线的修改。

# 国标目录与授权

- 依据：2016 附录 O、2022 附录 J；两版本的消息字段继续按对应 MANSCDP 定义核对。
- 215 根的 ParentID 指向制定目录的本平台系统 ID；首层 216 通过 BusinessGroupID 关联根，不把根编码误写为普通 ParentID。
- 嵌套 216 的 ParentID 指向父虚拟组织，同时携带根 BusinessGroupID。
- 资源保留物理父设备/系统关系，附加虚拟组织归属；复合 ParentID 使用标准分隔方式。
- 2016 的 BusinessGroupID 放在 Info 内，2022 放在 Item 层，分别使用独立期望 XML 测试，不只做同一实现的序列化往返。
- 启用业务发布时检查本平台系统身份的编码类型；不自动替换用户配置的 SIP 身份。非系统身份需要明确提示用户修正后再发布标准业务目录。
- 配置有效且开启 PublishGroup 时保留必要容器及业务关系，替换当前强制 ChannelsOnly 的输出选择；未配置/关闭时保留旧输出。
- 系统查询返回该平台完整已发布目录；业务根/虚拟组织查询按树筛选目标及后代，仍保持 SN、SumNum 和分批规则。
- 查询与手动推送复用相同快照和版本化序列化；未共享通道绝不加入目录或播放反查。

# 验证范围

- 存储与服务：两平台隔离、唯一根、编号重复/碰撞、错误类型、环/孤立节点、越权挂载、版本冲突、事务回滚、取消共享、删除复建。
- 协议：2016/2022 独立业务目录样本、首层/嵌套 216、资源复合 ParentID、按目标查询、分批、关闭发布回归、业务目录容器不被过滤。
- HTTP：权限、平台 ID 边界、请求校验、冲突状态、结果中不泄露认证字段。
- 前端：入口、平台切换、空态、节点操作、通道挂载/换组/移除、保存失败保留编辑、关闭再打开、权限禁用及原五步向导回归。
- 实现前在 tasks 文档逐项定义输入/期望结果，逐项执行 RED→GREEN；不另写测试文档。
- 静态检查和单测后执行 Vue 编译及登录态浏览器验收；真实上级接收/点播与本地测试分别报告。

# 工作边界与待审核选择

- 本次只新增平台专属业务目录能力，不顺手实现行政区划发布开关。
- 当前工作区已有级联模型、仓储、服务、数据库基线、SIP 和日志等未提交改动；实施前再检查差异，在其上做最小增量，不重置或覆盖。
- 方案采用一个业务根、通道单归属，节点删除需先移走内容；这是本期明确范围。
- 标准发布对本地系统身份的校验可能要求现有非 200 类型平台修正身份；不会静默改写旧连接。
