# 目标与范围

按已确认的操作体验规格，实现一个平台内的组织树、批量通道管理、草稿保护和发布操作闭环。2026-10-14 的统一工作区修订同时支持共享、取消共享、云台权限与目录归属的一次保存，并扩展既有服务端事务；发布设置继续使用单字段接口，避免整份回写连接配置。不新增数据库表，不改源通道，不扩展多根或多归属；具体实施范围以末尾统一工作区方案为准。

## 发现的版本差异与互操作风险

- 2016 A.2.1 的类型定义把 BusinessGroupID 放在 Info 内，而 O g) 的虚拟组织示例直接放在 Item 内。现有服务端选择 Info；2022 J g) 明确展示 Item 下字段。本轮保留现有版本化序列化，并记录 2016 标准内部不一致；不得宣称 Info 是原文唯一允许的位置，也不在 UI 中增加未经验证的兼容开关。
- 2016 9.5.3.1 对业务分组查询描述为返回分组及其虚拟组织；2022 J d) 明确包含设备目录项。现有 responder 的分组查询包含通道。此项是已有协议核对风险，UI 根节点的通道汇总不应被当作远端 Catalog 查询返回范围；后续协议整改需独立固定报文与对端互通证据，本轮不悄悄改变查询范围。
- 前端测试、现有 Go 测试均不能代替完整国标认证。任务阶段列出两版现有目录回归及上述已知限制，真实上级接收另行记录。

# 界面与交互

工作区使用独立详情页面，沿用 Arco 组件和项目明暗主题变量。桌面两栏，小屏纵向排列，修改摘要、放弃与保存集中在顶部操作区。页面到列表使用弹性高度布局，移除底栏后利用剩余空间；小屏列表保留滚动。最新技术范围以下方统一工作区修订为准。

- 顶部：直接展示共享方式标签及紧凑操作区，移除页面标题和上级状态卡；标签下显示修改摘要与流程提示，统计保留在资源范围和列表。
- 左侧：搜索、折叠的组织树，“未分组通道”为独立管理入口。根计数为全树已分组通道数；组织明确标出含下级数。搜索保留命中节点祖先路径。
- 根视图：目录概览和“新建虚拟组织”；不出现向根添加通道的操作。
- 组织视图：完整路径、直属通道表；新建下级、编辑、删除集中在树上方，并通过 Arco 节点右键菜单复用已有草稿操作。右键先选中目标节点，保留权限、非空节点限制和删除确认；菜单随共享方式、保存、选择器及搜索变化关闭。创建表单保留规范说明，已保存编号只读。
- 通道表：名称、发布国标编号、当前业务组织路径；仅使用现有数据可准确提供的字段，不为物理设备名称逐条请求。物理关联留在既有设备/共享视图。
- 添加通道：打开选择面板，标题固定“添加到〈当前完整路径〉”，默认未分组，支持名称/编号搜索、筛选和多选；切换组织后不沿用另一个组织的选择。
- 从其他组织加入时显示原路径和目标路径，确认“移动 N 个通道”，每个源通道最多保留一个绑定。
- 通道表支持批量移至其他组织、批量移出；移出后明确提示“仍保持共享”。同一操作禁止重复请求。
- 全选默认仅当前页，跨页选择保留且显示总数；搜索变更时清空选择并提示，避免不可见结果意外进入操作。单独的“选择全部筛选结果”显示明确数量。
- 非空节点删除显示原因及子组织、直属通道数量；引导先移动内容。发布开启时不允许删除最后一个业务根，提示先关闭发布。

首次进入给出“创建业务分组 → 建立虚拟组织 → 添加通道 → 保存 → 开启发布”的短引导。已有目录不重复走向导。

# 状态、模块与数据流

- `BusinessGroupManager.vue`：工作区与草稿会话；保存成功后保持当前节点、展开位置和筛选。批量选择面板可拆为同目录组件，避免单组件混入大量选择逻辑。
- `businessGroupState.ts`：沿用节点与绑定模型；增加路径、计数、未分组筛选、批量分配/移动和规范化差异比较的纯函数。编号建议继续基于现有生成器，但须避开本平台/上级 ID、已共享资源编号及已有节点；服务端最终校验。
- `cascade/index.vue`：传递当前平台与权限，处理共享入口及刷新平台数据。工作区发出“去共享”后先保存或放弃本次草稿，再打开现有共享窗口；共享完成或取消后重新读取分组快照，恢复仍存在的节点选择。
- 业务树继续使用 `GET/PUT /platforms/:id/business-group`；批量操作只修改内存中的 bindings，统一保存时提交全量 nodes/bindings 与 `expectedProjectionRevision`，避免逐通道写请求。
- 搜索和分页先在快照上完成，限制渲染行数。当前 API 返回全部共享通道，超大数据量仍有传输/内存边界，按真实规模验收后再决定是否需要服务端分页。

# 发布开关的最小服务端增量

现有 `updateCascadePlatform` 是整份配置更新，包含连接、认证和策略；服务端保存后还会执行运行时 Reload。仅为了改变一个发布开关，不应由工作区复制整个表单或构造默认配置回写。

建议增加 `PUT /platforms/:id/publish-group`，请求只有 `publishGroup` 与 `expectedRevision`（平台配置版本），返回最新平台视图。

- 使用现有级联管理权限和审计机制；按项目现有 API 权限注册/初始化方式登记端点，不能仅依赖前端按钮禁用。只补必要 API 授权元数据，不新增业务表或菜单。
- 服务端在条件更新中仅改 `publish_group` 和必要版本/时间字段，保留所有其他连接、密文和运行时配置。
- 开启前复用或抽取现有业务根、本平台 200 类型系统身份校验；最终事务内再次校验树，防止校验后被清空。与业务树写入使用同一平台一致性边界。
- 保存树使用 ProjectionRevision，发布设置使用 ConfigRevision；开启/关闭与清空树并发时，事务保证不能出现开关开启却没有合法根的状态。
- 如需要 Reload，复用当前运行时同步机制；数据库已提交但 Reload 失败时，报告“配置已保存，运行时更新失败”，重新读取真实状态后提供重试，不能提示成未保存或直接翻回旧值。
- 平台编辑器中的原开关保持为同一服务端字段，两个入口保存后都刷新最新版本；不创造两份发布设置。

工作区中“保存修改”仅保存目录；未保存时点击“开启发布”提供“先保存并开启”，顺序执行两个操作，分别反馈结果。第二步失败保留第一步成果；单独开启发布不自动启用级联平台。

手动“推送目录”复用既有端点与权限，名称标明是推送该平台目录，作用域不是仅当前组织。有草稿时先保存或放弃；发布关闭时明确业务分组不会包含在本次目录中。只展示后端已返回的条目/批次及结果，不虚构上级接收状态。

自动推送仅展示现有配置及已核实的触发语义；不承诺保存业务树必然立即触发，不新增自动订阅增量通知。

# 草稿与异常恢复

- 基线为最后成功加载/保存的快照，草稿为深复制 nodes/bindings，规范化比较判断 dirty；请求过程中锁住写操作，避免响应覆盖请求期间的新编辑。
- 切换节点保留草稿；关闭、Esc、遮罩、路由离开统一经过 dirty 检查，提供继续编辑、放弃、保存后离开。浏览器刷新/关闭页使用原生离开提醒，不宣称持久保存草稿。
- 保存错误保留内容并定位字段/节点；平台切换、迟到响应沿用序列号隔离，避免串平台。
- 冲突时保留草稿在当前会话供核对，停止重复提交旧版本；“重新载入”明确会放弃修改并需确认。首期不新增自动合并或双版本差异编辑器。
- 只读用户可浏览搜索、展开与统计。树编辑/推送沿用 share 权限；发布设置使用 manage；启用级联仍独立遵循 enable 权限。

# 2026-10-14 实施修订

按老板已确认的新流程，扩展既有 business-group PUT：新增可选 shareChannelIds（本地通道主键），由服务端按权限校验真实通道/设备，追加所需共享并替换目录与绑定，在同一事务/CAS 中提交。不从前端整份回写共享快照，不新增表或接口权限。

通道选择拆为独立 BusinessChannelPicker，使用现有权限过滤的通道分页查询；已共享范围支持按发布编号筛选。Manager 保留服务端共享快照，新增共享是单独草稿，保存时仅提交仍有绑定的新增 ID。组件关闭或请求迟到不能串平台。

自动化验收使用临时数据库与组件/API 测试；浏览器使用真实只读查询及隔离写请求验证，不操作真实上级的共享/发布/推送配置。保留原标签草稿，不部署。


# 2026-10-14 统一工作区实施方案

本节取代旧共享弹窗往返、仅保存有组织新增通道等描述。

- 平台页导航到隐藏详情路由 `/gb28181/cascade/:id/resources`，复用查看权限与 authenticated layout。详情页加载当前平台并嵌入工作区，路由离开委托同一草稿决策；平台编辑功能保持独立。
- Manager 使用全部共享、未分组和组织三种筛选共用通道表，组织表单按需展开。Picker 空目标仅添加共享，有组织目标同时加入绑定，既有共享不可重复新增。
- 基线保存 nodes、bindings、channels；新增共享、取消共享、云台配置和组织变化均在内存处理，dirty/摘要使用语义差异，失败保留草稿。
- 扩展既有 business-group PUT 的可选 `resourceChanges`，包含 `shareChannelIds`、`unshareChannelIds`、`channelPermissions`；与 nodes/bindings 共用一次事务及 ProjectionRevision CAS。空组织树下也可新增共享。
- 服务端验证数据范围与平台共享权限，保持既有发布编号；取消共享停用投影并清理绑定，云台只更新现有/本次新增共享，不接受任意通道授权扩大。事务失败整批回滚。
- 新资源事务提交后复用运行时 Reload，刷新目录与媒体会话授权；事务失败不触发 Reload。同步失败时仍返回已保存快照及 `runtimeSynced: false`，前端更新基线并明确提示，重试使用最新 ProjectionRevision 的资源保存，不借发布端点修改配置。
- 发布开关继续使用 ConfigRevision 和单字段端点；保存后的运行时同步失败明确报告持久化事实，不声称事务回滚。
- 使用临时数据库、组件与 API 测试验证提交合同和回滚；浏览器只读真实查询与草稿交互，写入场景使用隔离模拟。未授权部署、真实共享修改或 SIP 推送。

# 2026-10-14 双模式共享最终方案

本节取代之前独立发布两阶段流程。继续复用 publishGroup：false 为通道共享，true 为目录共享；不新增数据库字段或迁移。

- Manager 保留共享方式草稿及目录位置；channel 模式显示全部共享，directory 模式显示树和组织归属操作。退出、放弃、冲突和保存采用现有草稿会话。
- `PUT /platforms/:id/business-group` 顶层携带 `publishGroup`、`expectedConfigRevision`，与全量 nodes/bindings、resourceChanges 和 `expectedProjectionRevision` 一起保存。嵌套模式字段兼容，但新前端使用顶层字段。
- 仓储事务读取实际模式，仅模式变化时要求配置版本与 manage 权限；资源修订保护整份投影。事务内应用资源草稿，再校验目标模式，CAS 更新配置/投影版本；两种模式均允许保留未归类共享通道。
- 目录合法性校验同时覆盖独立发布接口和旧共享投影接口，保留合法根、有效归属及共享授权校验；不要求全部共享通道归入组织。所有错误整体回滚。
- GET/PUT 返回 publishGroup/configRevision；Manager 采用快照中的保存事实，刷新页面平台摘要。运行时 Reload 失败仍返回提交状态与同步失败提示。
- Arco Select 使用条件渲染隐藏目录操作，不能对具有多根节点的组件依赖 v-show。平台编辑器移除第二处可编辑方式开关。
- 不改变协议 XML 的版本序列化；临时 SQLite 事务测试与本地浏览器读取不等于真实跨数据库、SIP 对端或部署验收。
