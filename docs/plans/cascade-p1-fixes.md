## 总体选择

沿用现有每上级独立 actor、SIP 事务客户端、级联会话和共享资源保存接口。修复 D01–D05，不增加业务表、迁移或新页面；不修改现有开发台账。所有源码修改基于当前完整工作区，保留既有暂存与未暂存内容。

协议依据为 GB/T 28181-2022 第 8、9 章及附录 G；注册绑定有效期处理按其引用的 SIP 规则（RFC 3261 第 10.2.4 节）执行。2016/2022 共用的 SIP 修复同时回归两个现有 profile；本轮不引入 D16 的版本参数校验或 D10 的版本协商。

## D01：明确 SDP 属性所属层级

修改 `server/app/gb28181/sdp/cascade_video.go` 中属性分派。先判断尚未进入媒体段，再判断是否为选中的 video，避免两个 nil 指针相等被误当成选中视频。

- 方向与格式走已有会话级存储、媒体级覆盖规则。
- rtpmap/setup 等分支访问媒体对象前必须确认对象存在；不因本次修复扩展未经支持的属性语义。
- 非视频段、后续视频段不得污染已选中的视频对象。
- 保持现有错误返回路径，由级联入口返回相应 SIP 错误；不增加 recover 掩盖解析缺陷。

## D02：保留到期意图，保证串行执行

修改 `server/app/gb28181/cascade/runtime/runtime.go`。每个 actor 保持至多一个进行中的维护事务，用有限的待办标记合并注册/续期及心跳意图，不建立无界队列。

- 事务忙碌时记录待办；收到结果后按停止/注销、注册/续期、心跳的顺序处理。
- 注册完成后优先处理已经到期的心跳；不把重复事件逐条补发。
- 每类维护定时器替换前停止旧实例；对已进入消息队列的旧定时事件用代际标识丢弃，防止旧回调覆盖新日程。
- 失败沿用现有重试策略，避免待办导致立即无限重试；本轮不扩展 D09 心跳故障重注册策略。
- 停止时清除维护待办及定时器，等待现有事务收尾后按实际注册状态注销；强制停止保留现有超时退出语义。
- 调度仍使用现有 Scheduler/Clock 注入，不使用真实等待模拟到期。

## D03：将授予期限从 SIP 结果传到运行时

在 `cascade/sipclient` 中解析成功 REGISTER 响应的有效期，向 actor 提供明确的“已授予期限/未提供期限/响应非法”结果。解析必须保留本次请求的 Contact，不能简单取响应的第一个 Contact。

- 匹配本次注册的 Contact 绑定；其 expires 参数优先于响应级 Expires。无关绑定不参与本次期限计算。
- 仅在对端未提供可用于本次绑定的期限信息时，兼容回退到请求期限；显式非法值、多义匹配、数值溢出按注册结果异常处理，不能静默当作长期在线。
- 显式零期限按绑定未生效处理，停止该注册的心跳/续期并走现有重试节奏。
- actor 持久化的 expiresAt 与续期时机使用同一授予期限；80% 仍是工程提前量，保持短期限下续期严格早于到期，计算避免 time.Duration 溢出。
- Logout 仍以请求零期限执行，不与正常注册成功混淆。测试 fake 未携带 SIP 响应时保留明确的兼容路径，并单独覆盖真实客户端到 actor 的期限传递。

主要文件：`cascade/sipclient/transaction.go`、相关请求工厂或期限辅助文件、`cascade/runtime/runtime.go` 及对应测试。

## D04：收紧现有来源信任边界

### 本轮选择与兼容影响

采用配置端点约束：INVITE 和 RecordInfo 均要求实际网络来源地址、端口、传输协议及上级编码匹配唯一启用平台，取消 identity-only 回退。现有严格匹配可复用，IP 比较使用规范化地址，不能以 Via、Contact、SDP 或 From 中声明的地址代替实际来源。

该选择会拒绝“配置为局域网地址，INVITE 却从另一 VPN 地址到达”的现有宽松路径。当前测试明确允许这种行为，需替换成“不可信跨地址拒绝”的回归，不能仅删除失败测试。本轮不自动学习上级报文中的新地址，也不增加任意地址白名单。

配置端点约束修复的是现有任意来源回退；它不等于密码学身份认证，不能抵御能伪造同一 UDP 源地址的攻击者。完整双向摘要、TLS 或可信多地址接入属于后续安全能力设计，不能把本轮结果报告为已完成国标信令安全认证。若必须保留现有跨网卡自动放行，需要调整本方案，明确额外可信凭据或受控地址来源后再实现，不能继续依赖 From 唯一命中。

### 入站及会话链路

- INVITE 完成可信上级识别后再解析 SDP 和查询共享资源；未知或停用上级在资源调用前拒绝。
- RecordInfo 使用相同的严格匹配规则，再执行录像共享授权及投影解析。
- ACK/BYE/INFO 在现有 Call-ID、tag、CSeq 验证之外，必须匹配会话建立时的实际来源；错误 ACK 不确认会话，错误 BYE/INFO 不释放或控制会话。
- CANCEL 由内嵌 sipgo 事务层提前消费，不能只改业务 Handle。需在事务层进入既有事务前增加可选来源校验，应用仅为级联视频事务启用：校验失败不能触发 200/487 或终止原 INVITE；相同来源的合法 CANCEL 与重传继续工作。相应非 2xx ACK/重传也需覆盖，避免事务层绕过应用校验。
- 事务校验须在事务创建时确定，避免等待业务 handler 安装校验期间留下窗口。默认行为保持原状，仅约束明确识别为级联视频的事务；不修改全局事务键规则。
- 复用现有日志机制记录拒绝原因与实际 peer，不记录凭据。

主要文件：`cascade_invite_handler.go`、`cascade_recording.go`、SIP 装配代码、`server/third_party/sipgo` 的最小可选事务校验接口及测试。该内嵌模块需单独运行测试，主模块测试不能替代。

## D05：新增共享权限由后端默认规则决定

根因是 `BusinessGroupManager.vue` 把选择器草稿中的 false 当成显式权限提交，覆盖后端 `addBusinessGroupShares` 已有的平台默认值。优先修复提交语义，不在后端无条件覆盖明确的权限更新。

- 新增共享仅提交 shareChannelIds，不再把没有权限编辑入口的草稿默认值送入 channelPermissions。
- 保留现有 API 的显式权限更新能力；已有共享通道编辑组织、保存或取消共享时，不产生隐式权限修改。
- 后端继续以保存时平台 PTZEnabled 为新增共享默认值，避免前端快照过时；重新激活共享沿用现有后端默认规则。
- 草稿中的 ptzAllowed 只作本地数据兼容，不代表新增共享的明确授权。保存后以服务端读取结果为准；不为本轮新增无用 props 或权限 UI。
- 控制执行仍同时检查平台总开关及通道权限，不批量修订既有 false 记录。

主要文件：`web/src/views/gb28181/cascade/BusinessGroupManager.vue` 及其交互测试，后端 repository/controller/control 的边界回归测试。选择器仅在实际需要时做最小修改。

## 数据流、依赖与验证边界

- 注册：请求 Contact → 成功响应对应绑定期限 → actor 状态、expiresAt 与维护定时器。
- 入站请求：实际来源 → 唯一上级 → 共享与功能授权 → 源设备/录像/媒体；会话后续请求受原始 peer 与事务/对话标识共同约束。
- 新共享：前端新增通道 ID → 保存事务读取平台当前默认值 → 投影权限 → 控制服务二次授权。
- D02 与 D03 修改同一运行时，串行落地；D04 的事务校验先验证底层行为，再验证级联入口；D05 不与后端授权规则冲突。
- 无新增第三方依赖、业务迁移、环境变量或线上配置变更。
- 下一阶段定义逐项输入、期望输出和 RED/GREEN 命令；本阶段不编写业务实现或执行真实台账联调。
