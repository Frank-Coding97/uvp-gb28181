## 信令端点
- 从收到心跳的真实传输源获取端口，核对 SIP From 与 XML DeviceID 一致；不采用 Contact/Via 中的自报地址。
- 仅允许已有成功注册、注册仍有效、来源 IP 与传输方式符合注册关系的设备刷新端口；跨 IP 或传输变化需要重新认证注册。UDP 心跳本身不是密码学身份认证，不能宣称能防同公网出口下的所有冒用。
- 在设备状态事务中同时更新心跳事实、来源端口和必要的恢复事件；保留 online_on_heartbeat 配置语义。用接收时刻及条件更新阻止并发旧快照覆盖新注册/新心跳。
- 保持现有所有新事务从设备表取路由，不重新实现点播、查询、控制。既有 SIP 对话路由单独检查与测试，不能盲改对话目标或宣称只改设备表就解决存量 BYE。

## 在线状态
- 以真实 SQLite 执行验证现有带时区与小数秒存储格式，统一到可比较时刻，保持其他数据库分支。复用现有离线扫描与状态事件。

## 注册鉴权
- 只读分析脱敏现场认证事务，在服务器内存中按现有配置验证摘要，只输出分类与匹配布尔值。
- 确认平台缺陷后才修改并添加失败测试；错误凭据、未响应挑战等设备行为如实记录，不关闭认证、放宽 nonce 或重放约束。

## 风险与验证
- 同公网 IP 下的无认证 MESSAGE 仍依赖既有信任边界；超期注册不能借心跳延长认证有效期。
- 首先使用隔离内存 SQLite 和本机 SIP 回归，不写客户数据或开发共享库。
- 本地相关单元测试、竞态检查、构建与现场恢复分别报告；生产升级与回退遵循现有原位升级机制，发布前排除其他未完成任务。
