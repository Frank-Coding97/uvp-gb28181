# 方案结论

沿用系统配置的 YAML 持久化、既有配置权限和任务调度框架。新增一个按日志类型分派的清理执行器，以六个内置任务承载各类日志清理。

每类任务独立执行、启停、手动触发、记录结果；不新建调度系统，不让一个长任务串行阻断全部日志类型。

# 配置与页面

- 在系统配置页面新增“日志清理”页签，六个保留天数输入使用现有 SNumberField 和统一表单样式。
- 前后端均校验 1–365 的整数，输入在失焦或提交时展示错误，不自动钳制数值。
- 复用 `/api/config/get` 与 `/api/config/update`，扩展 `logCleanup` 段；旧请求没有该段时保持日志配置不变。
- 仅在“日志清理”页签保存时提交该段，避免保存其他系统设置时无意启用新增日志清理。
- 更新接口沿用 `system:config:update` 权限，同时验证日志配置；所有验证在任何配置写入前完成。
- 保存失败恢复本次修改的内存配置，返回失败；成功保存不触发删除。
- 每次任务开始读取一份完整配置快照，执行过程中固定使用该快照，下一次执行再采用新值。

| 前端字段 | 持久化键 | 默认值 |
| --- | --- | --- |
| sipRetentionDays | gb28181.trace.retention_days | 沿用已有有效值，缺省 7 |
| operationRetentionDays | log_cleanup.operation_retention_days | 180 |
| loginRetentionDays | log_cleanup.login_retention_days | 180 |
| jobRetentionDays | log_cleanup.job_retention_days | 30 |
| playbackRetentionDays | log_cleanup.playback_retention_days | 7 |
| schedulerRetentionDays | log_cleanup.scheduler_retention_days | 7 |

SIP 保留天数继续使用原配置键，不能双份存储。国标服务配置页面将其改为只读说明并指向系统配置；SIP 采集开关留在原处。原聚合 API 的 SIP 保留期字段继续兼容，相关保存路径共用保留期校验和运行时应用逻辑。

调整 SIP 保留期时，需要刷新现有报文可用期及诊断运行时配置。通过运行时回调连接配置服务与 GB28181 装配，避免系统控制器直接依赖国标控制器；应用失败需明确区分“已保存”和“运行时未应用”，不能显示完全成功。

# 任务注册和升级

- 清理任务统一为重复执行、`0 0 3 * * *`、禁止同一类型并行、单次最长 10 分钟。
- 使用固定任务参数标识日志类型，保留天数不放任务参数，避免任务配置与系统配置各存一份。
- 复用 `system-login-log-cleanup` ID，保留数据库中已有启停状态和执行历史。
- SIP、调度、播放分别新增固定 ID；操作和任务结果日志分别新增固定 ID，幂等注册到 `sys_jobs`。
- 新增操作和任务结果清理任务可以预注册，但在 `log_cleanup.configured` 缺省或为 false 时直接跳过并记录“等待首次保存日志清理配置”。
- 首次成功保存日志清理配置设置上述标记；后续才执行新增类型的实际删除。任务的用户启停状态始终独立保留，不在配置保存或重启时强制启用。
- SIP、调度、登录、播放沿用已有自动清理行为，统一迁移至调度器；原独立清理循环停止。
- 保留旧登录日志执行器名称作为兼容入口，内部读取同一登录保留配置，避免已有自定义任务因执行器消失而失效。
- 清理入口按日志类型互斥，防止内置任务与用户复制的同类型任务同时删除；不改变调度器对其他任务的并行规则。

# 数据清理规则

每次任务固定执行时刻，计算 `cutoff = now - days × 24h`，只处理严格早于 cutoff 的数据。内部批次大小固定为 500，无需新增用户配置。

| 日志 | 数据及时间依据 | 实现方向 |
| --- | --- | --- |
| 操作日志 | sys_operation_logs.created_at | 按 ID 分批硬删除，包含已软删除记录 |
| 登录日志 | sys_login_logs.created_at | 复用 CleanupBefore，改为读取配置天数 |
| 定时任务日志 | sys_job_results.end_time | 只清理已结束执行结果，不修改 sys_jobs |
| SIP 日志 | gb_sip_trace_message.occurred_at、诊断 observed_at | 复用现有仓储分批清理，排除进行中的诊断相关数据 |
| 调度日志 | scheduler_log.happened_at | 将现有整段删除改为按 ID 分批删除 |
| 播放日志 | 已终态记录的 finished_at，兼顾最新事件时间 | 先选择过期且无近期事件的已结束生命周期，批次内清理关联事件和记录 |

- 分批查询主键，再按主键和到期条件删除，避免依赖不同数据库不一致的 DELETE LIMIT 语法。
- 每个批次单独事务；已完成批次保留成果，失败或取消立即退出，下一次执行继续清理剩余数据。
- 删除前复核到期条件和终态；截止时刻、近期数据、活动播放和进行中的诊断均保留。
- 播放事件与关联记录按生命周期处理，避免仅删除旧事件导致仍保留的生命周期详情残缺；无关联记录的历史孤立事件按事件时间分批回收。
- SIP 子类型的任一路径失败不掩盖另一路径结果；汇总已删除数量并返回失败。
- 不删除运行日志文件、会话、设备操作意图、录像、位置历史或统计表。

# 旧后台逻辑迁移

- SIP Trace Module 保留采集、写入、重试与关闭流程，移除自动清理 ticker；清理直接依赖数据库仓储，因此关闭 SIP 采集后仍能清理历史数据。
- GB28181 bootstrap 保留调度日志写入服务，移除 pruneSchedulerLogDaily 后台循环。
- DashboardRetention 保留 SIP 统计数据的 30 天清理与既有生命周期状态维护，仅移出播放日志的过期删除职责。
- 生命周期状态维护与日志删除是不同职责：禁用清理任务不停止状态维护，状态维护也不能绕过任务禁用执行删除。
- 更新相关关闭等待逻辑及回归测试，避免移除 goroutine 后遗留未关闭的 done channel 或关闭等待超时。

# 执行结果

当前 sys_job_results 只有状态和错误，成功记录不能保存删除数量。新增一个可空的 `summary` 文本字段用于执行摘要；不把成功摘要伪装成错误。

- 调度器保持 Execute(ctx, job) error 接口，通过每次执行独立的上下文报告器收集可选摘要，避免并发任务共享可变结果。
- JobResult 增加可选摘要，结果消费者持久化到 sys_job_results.summary；其他执行器不使用时行为不变。
- 摘要包含日志类型、保留天数、截止时刻、实际删除数量及跳过原因；失败时保留已完成删除数，错误仍走原字段。
- 既有定时任务日志页面增加“执行摘要”，普通任务无摘要时显示空占位。
- 提供 MySQL、PostgreSQL、SQL Server、SQLite 的字段迁移及回退，并更新必要的初始化 DDL；迁移不删除日志数据。

# 依赖及主要改动范围

- 后端：系统配置请求与控制器、日志配置/清理服务、任务执行器及注册、结果持久化、GB28181 Trace/调度/播放旧清理装配。
- 前端：sysconfig API、配置 store、系统配置页、国标服务配置中保留天数展示、任务日志 API 与页面。
- 数据库：任务结果 summary 字段及已有查询/删除时间索引核对，按现有迁移机制交付。
- 不引入外部依赖，不修改其他任务策略或日志采集业务。

# 风险与权衡

1. 播放记录默认保留由 30 天缩短为 7 天，是已确认规格的行为变化；仪表盘若直接查询共享播放记录，其历史明细也会受该保留期限制，独立统计表仍按原策略保留。
2. 六个任务同一时刻执行可能产生数据库压力，以小批事务和同类互斥控制；不让多类日志争用一笔大事务。
3. 配置文件与任务数据库没有跨介质事务；使用配置保存标记作为新增类型清理门槛，避免首次保存同时更新两处启用状态。
4. 配置并发修改及 SIP 热重载必须覆盖共享写入路径，防止两处设置竞争；旧聚合 API 继续兼容同一配置值。
5. 定时任务完成、浏览器展示、数据库记录清理是不同验证层次；实际执行验收使用隔离测试数据，不以构建成功替代运行验证。

技术方案已确认，并按关联任务清单完成实现。浏览器页面和真实数据库运行验收单独记录，不以静态测试替代。
