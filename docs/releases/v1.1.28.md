# 1.1.28

发布日期：2026-11-26

这一版把 Windows 单机版的启动和停止都做成了「看得见」的过程，另外补上了一处播放授权漏洞、修好了几个现场容易误解的状态提示。用 Windows 版的用户建议升级，对接 OpenAPI 播放的第三方系统请先看文末的升级提示。

## 新增

- **Windows 双击启动就能看到过程了**：以前双击 `UVP-GB28181.exe` 之后屏幕上什么也不出现，服务其实已经在后台启动，用户往往以为没点成功，又反复双击。现在会立刻弹出一个启动窗口，实时显示「环境检查 → 初始化数据与配置 → 启动服务」三个阶段和每个组件的结果，大约一分钟。
- **启动完成后自动打开管理页面**：服务一就绪，就用系统默认浏览器把平台地址打开，不用再手动复制地址到浏览器。这个动作只在启动那一次发生；托盘里的「重启服务」不会反复弹标签页。
- **停止和退出也有窗口了**：右键托盘选「停止服务」或「退出」，会弹出一个停止窗口，逐个显示管理页面、后端、流媒体、Redis 是否已经停下；哪个进程没停干净会明确标出来。停完之后窗口会停住，看完按键关掉即可，关窗口不会影响托盘和服务。

## 修复

- **Linux 单机版启动时报参数错误、整个服务起不来**：1.1.27 的 Linux 包在启动时会停在「ZLM 端口同步失败」并退出，实际原因是启动脚本调用安装助手时用错了一个参数名（写成了 `--ffmpeg-bin`，程序只认 `--zlm-ffmpeg`），安装助手直接拒绝执行。这个问题每次启动都会出现，跟机器环境无关；Windows 版不受影响。如果你在 1.1.27 上遇到过「解压后执行启动脚本直接报错」，换这一版即可正常启动。
- **OpenAPI 直播播放的授权检查有缺口**：通过 OpenAPI 拉流时，以前只有 HTTP-FLV 这几种方式会校验播放授权，HLS、WebRTC、RTMP、RTSP 直播则可能绕过检查直接取流。现在所有直播协议都走同一套授权，并且会校验播流会话与申请时的会话是同一个，避免有人拿别人的授权把流引到别处。
- **Windows 版第二次启动起不来**：管理员身份启动过一次之后，用普通账户再双击启动，程序会停在「进程授权状态不可用」并退出。原因是第一次留下的状态文件只有管理员能读写，普通账户打不开。现在创建时就同时授权给当前用户、系统和管理员组，谁启动过都不影响下次启动。
- **「固定地址回放」「自动点播」和单端口收流同时开启会静默失效**：节点用单端口模式收流时，这两项设置实际上不起作用，但界面上还是显示已开启，排查时很难看出问题。现在会自动对账：只要存在单端口收流的节点，就把这两项关掉并在界面上说明原因，不会再出现「设了却没生效」。
- **停止服务时 Redis 被误报「未在运行」**：停止流程先让 Redis 自己优雅退出，稍后才检查进程，那时它已经退出了，于是每次都打印「Redis 未在运行」。现场上一秒刚看到它启动、端口也在监听，很容易以为停止没生效。现在会记住停止前它是否在运行，正常退出就显示「已停止」。
- **改过登录口令后，登录页仍然提示 admin / 123456**：这个提示读的是配置文件里的出厂初始口令，而首次登录改密并不会回写配置文件，于是改过密码的现场每次启动都看到旧口令，以为密码被重置了。现在措辞改成「出厂初始口令，首次登录会强制改密」，并补了一句忘记口令时如何重置。
- **点「前往升级」进去还要再点一次检查**：侧边栏的「前往升级」跳过去之后，检查结果会被页面重建冲掉，用户得手动再点一次「检查在线更新」。现在落地即自动检查，结果直接显示。

## 变更

- **Windows 启动方式**：推荐继续双击包根目录的 `UVP-GB28181.exe`（带托盘图标）。原来的 `start.cmd` 仍然可用，但它没有托盘图标，也不会自动打开管理页面。

## 升级提示

- 升级前请备份 `data/` 与 `config/` 目录。
- **Linux 用户请直接升到这一版**：1.1.27 的 Linux 包启动时会报参数错误、服务起不来，本次已修好；之前没装成功的机器，用这个包重新解压启动即可。
- **对接了 OpenAPI 播放的第三方系统请注意**：本次补齐了 HLS、WebRTC、RTMP、RTSP 的播放授权校验。如果此前是绕过授权直接拼流地址播放的，升级后会被拒绝，需要改走正式的播放申请接口取流。
- Windows 单机版升级时，如果托盘图标还在运行，请先右键「退出」再覆盖安装包，避免老进程占着文件。
- 这一版没有数据库结构变更，升级后直接启动即可。
