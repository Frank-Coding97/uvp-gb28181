# 1.1.19

发布日期：2026-11-09

这次升级主要解决「设备多了就看不见摄像头」这一类规模问题：万级设备同时注册时，
MySQL 上目录入库和通道写入不再把数据库连接池打满，配置下发与能力刷新也不会再
因为一次写回失败卡死整条流水线。另外修掉了新装机改端口不生效的老问题，
点播新增 TCP 主动收流模式。

## 新增

- 点播支持 TCP 主动收流。通道选 TCP 主动模式时，平台在收到设备应答后主动回连设备取流，
  适合设备在 NAT 后面、只能自己往外连的场景。设备同时也要求主动时会明确提示冲突，
  不会表现为「一直转圈然后超时」。单端口复用模式的节点不具备外连能力，会直接给出提示。
- 国标配置页新增「设备校时」开关，默认关闭。打开后平台在设备对时请求的应答里补上日期头，
  设备据此校准自己的时钟；关闭时与老版本行为完全一致，报文不改动。
- SIP 的 UDP 接收缓冲由系统默认值提高到 4MB，上千台设备同时注册时不再因为缓冲区过小被内核丢包。

## 修复

- 全新安装的包改端口不生效：以前首次装机也会被按默认端口段拉起，配置里写的端口被忽略；
  现在首次装机直接按配置生效，老包升级仍沿用原有端口，不会莫名漂移。
- 端口预检现在能报出被系统临时连接占用的端口。之前只检查有没有服务在监听，
  实际上设备的出站连接也会占住本地端口，导致启动时才失败。端口段落在系统临时端口范围内时
  会给出警告和两条处置建议（预留端口或换段）。
- Linux 启动脚本在端口被占用时，报错信息会被打成「端口: No such file or directory」，
  真正的失败原因被冲掉，现在能正常显示。
- MySQL 上大批设备同时注册时，页面「设备在线但看不到摄像头」。原因是通道挂载用的
  先查后插写法在高并发下互相死锁，现在数据库隔离级别默认改为读已提交，
  写通道、写设备订阅也改成一条语句交给唯一键判重，压测中通道覆盖率从 8.4% 恢复为全量。
- 万级压测时目录入库把数据库连接占满，导致全平台查询卡住。目录入库现在限制并发，
  并给每次入库加了超时，连接占用有上限，单批再大也不会拖垮整个平台。
- 设备配置下发与能力刷新会永久卡住：单条结果写回失败后整条流水线停摆，后续配置一直排队。
  现在单条失败不影响同批其它设备落库，连续失败会记错误日志并自动收敛；
  停机时仍然保证结果必须写回。
- SQLite 下千路压测吞吐被压死，补上了 WAL 模式下缺失的同步级别设置。
- 侧边栏出现两条滚动条（一条自绘、一条系统原生），已收成一条。
- 侧边栏菜单在条目较多时被裁切，已修。

## 变更

- Linux 与 Windows 单机版对「首次安装」的判定口径统一，两个平台改端口的行为一致。
- 对外开放接口的接入套件（Java/Python/Go 客户端、Postman 与 Apifox 调试集合、签名规范）
  已独立成仓，不再随平台安装包交付。README 的「对外开放接口」一节同时给出 GitHub 与
  Gitee 两个仓库地址，国内访问更稳定。

## 升级提示

- 升级前请备份 `data/` 与 `config/` 目录。
- 从 1.1.18 升级时，数据库隔离级别会自动切到读已提交。如果现场有特殊要求，
  可在 MySQL 配置项里显式指定 `transactionisolation`；不填即为读已提交。
- 已经在用 MySQL 且设备量较大的环境，建议升级后观察一次「设备通道」页的通道数量，
  确认与设备实际上报一致。
- 端口配置在首次装机时才允许直接生效；老环境要改端口，请先停服务、改 `config/config.env`
  后再启动，脚本会按新端口重新拉起。
