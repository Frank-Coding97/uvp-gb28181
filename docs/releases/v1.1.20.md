# 1.1.20

发布日期：2026-11-10

这次升级主要是把平台对外开放给第三方系统的接口（OpenAPI）整体重做了一遍：设备、通道、点播、云台、报警、订阅、配置、位置和云录像等能力统一成 106 个动作接口，请求参数和返回字段更完整，随包也补上了完整的接口契约和调用示例。另外「检查在线更新」变及时了，容器版装机的端口预检也修掉了两个会让安装卡住的问题。

## 新增

- OpenAPI 按「动作 + 参数绑定」重新组织，共 106 个接口，覆盖设备与通道查询、直播点播、录像与存储卡、云台控制、报警与事件订阅、设备配置与视频参数、位置轨迹、云端录像目录等场景。
- 设备与通道的返回信息更完整：一次可以拿到基本信息、在线状态、通道能力集、控制状态、存储卡等，不用再为每类信息单独调用。
- 云台补齐预置位、巡航、轨迹、精确位置、扩展控制等成套接口；报警与事件补齐列表、订阅创建、查询、续期与取消。
- 设备配置与视频参数支持查询、下发、刷新，并能查询下发结果；新增通道能力刷新、目录刷新、维护操作等接口。
- 接口契约文档与 Java 签名示例同步更新，第三方系统可以按文档直接对接。

## 修复

- 手动点「检查在线更新」的结果以前不写入升级提示缓存，侧边栏可能迟迟不显示已经发现的新版本。现在检查结果会立即记录。
- 后台自动检查由每 6 小时一次改为每 15 分钟一次，页面取回结果的轮询由 30 分钟改为 2 分钟，新版本提示更及时。
- 容器版（docker compose）装机的端口预检原先只检查有没有服务在监听，会漏掉被系统出站连接占住的端口，往往安装到启动阶段才报「端口已被占用」并让容器反复重启。现在把「监听占用」和「连接占用」分开判断，分别给出换端口段、等待重试或整段预留的处置建议。
- 容器版样例配置里的版本号写死成旧值，照样例建配置会去拉取不存在的旧镜像。现在打包时按当前版本自动写入。
- 增量升级包的文件名对齐官网下载清单的命名约定，下载与校验不再对不上号。

## 变更

- ⚠️ OpenAPI 接口地址全部调整：原来按设备层级展开的路径（例如 `/openapi/v1/devices/{设备ID}/channels/{通道ID}/live`）改为按动作命名的扁平路径（例如 `/openapi/v1/live/start`、`/openapi/v1/channel/list`），请求参数与返回结构也一并调整。已对接的第三方系统需要按随包的新契约文档更新调用。
- 签名方式与请求头保持不变（HMAC-SHA256 与五个 `X-UVP-*` 请求头），访问密钥不需要重新申请。

## 升级提示

- 升级前请备份 `data/` 与 `config/` 目录。
- **使用 OpenAPI 对接的系统，请先在测试环境按新版契约改好接口地址和字段解析，再升级平台**，否则升级后调用会报「接口不存在」或取不到数据。
- Linux 与 Windows 单机版可在「服务升级」页在线升级，也可以使用本版的增量升级包，只下载变化的文件。
- 容器版请使用本版重新生成的离线安装包；从旧版沿用 `.env` 时，把里面的版本号改成 1.1.20。
