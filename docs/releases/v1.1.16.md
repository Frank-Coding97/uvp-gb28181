# 1.1.16

发布日期：2026-11-03

本次升级的重点是把「通道配置」重做成一个能一屏看完的工作台，并补上两个运维最常问的事实：
**这台设备到底按哪个字符集上报**、**这次点播请求的是主码流还是子码流**。
另有对讲稳定性、云台指令回写和一批界面细节的修复。

## 新增

- 通道可以指定实时点播的主/子码流：按设备兼容方式分成四组（stream、streamnumber、大华、水星/TP-LINK），
  默认「设备默认」即不改动设备原有行为。保存不会打断正在看的画面，界面会明确说明
  「当前这场直播是否已经用上所选配置」——新配置从下一次新建直播开始生效。
- 通道配置改成分区工作台（录像 / 报警 / 抓拍 / 状态与维护），不用再在几个页签之间来回猜。
  改到一半关窗、翻到上一条/下一条通道、离开页面或刷新浏览器，都会先问一句再走，避免白配一遍。
- 设备详情新增「字符集」一栏：同时显示设备自己声明的字符集和平台实际按哪个解。
  两者不一致时会直接标明「声明不可信」——遇到设备名、通道名乱码时，第一眼就能定位原因。
- 设备列表的目录树把在线设备排在最上面，离线和故障的往下沉。
- 侧边栏发现新版本时会提示；「服务升级」页提供定时检查开关，可以自己决定多久查一次。
- 一个离线升级包同时覆盖绿色包与 systemd 两种部署方式，现场不用再分辨该拿哪一个。
- 容器部署支持在页面内完成离线升级。

## 修复

- 设备名、通道名乱码：部分设备在报文里声明的编码与实际字节不符，平台以前信声明，现在按内容优先判定，
  这类设备的中文名可以正常显示。
- 对讲/广播不再因为切标签页或窗口失焦而中断；麦克风被占用或采集途中掉线时会给出可操作的提示。
- 云台与设备配置指令在跨机房链路上偶发「指令发出去了、状态却卡住不动」。现在把「准备」与「发送」拆成两段，
  结果回写有独立的处理时间，链路抖动不会被误判成失败。
- 升级到新版本后进地图报「无权限」：补上了地图视图接口的权限迁移。
- 容器部署升级时升级助手起不来的几处目录与默认值错位。
- 视频小窗右侧被裁掉一截。
- 多屏播放页定时刷新会让展开的设备树先折叠再展开。
- SIP 消息时序图里同一毫秒内的请求与应答顺序颠倒。
- 设备卡片视图默认每页改为 12，四列屏不再出现单独一个卡片的空行。
- 发布清单不再把 Linux 绿色包误标成容器部署。

## 变更

- 「自动升级策略」已移除，改为可在服务升级页开关的定时检查——不再由平台单方面决定什么时候升级。
- 设备目录树的「在线优先」排序改由接口侧完成，翻页与排序在全量范围内一致。
- SIP 追踪的会话列表改为滚动分页，不再一次返回全部；查询取消条数上限，改为按时间窗取全量。
- 全局滚动条颜色改用主题变量，暗色模式下不再是一条亮色横杠。

## 升级提示

- 升级前请备份 `data/` 与 `config/` 目录。
- 本版新增两组数据库迁移（通道播放码流配置、设备上报字符集），启动时自动执行，无需人工干预。
- 通道的「播放码流」默认是「设备默认」，升级后点播行为与升级前完全一致，需要时再逐个通道调整。
- Linux 与 Windows 单机版均可在「服务升级」页在线升级；Windows 版首次升级前请确认当前版本不低于 1.1.15。
