# 1.1.23

发布日期：2026-11-16

这一版给设备加了「类型」，NVR 和下级平台终于能和普通摄像机分开看；设备多了可以按类型筛。另外修了播放器切协议失败、HLS 带不上鉴权、首帧状态不准这几处问题，首页三条趋势线也换成了真实历史数据。

## 新增

- 设备支持手动标注类型（IPC / NVR / 下级国标平台）：新建设备、编辑设备时各有一个类型下拉，默认 IPC。设备卡片图标会跟着变（摄像机 / 硬盘 / 网络），列表也新增「类型」列，一眼能分出哪台是 NVR、哪台接的是下级平台。注册报文里没有可靠的形态判据，所以平台不做自动猜测，类型完全由人工维护。
- 设备列表支持按类型筛选：工具栏「状态」旁边多了一个类型下拉，可选 IPC / NVR / 下级平台。只在设备资产视角出现（通道没有类型、地图视角只认点位，这两处不显示）。筛选后列表和在线率环形图同步刷新，筛选条上会留一枚标签方便一键清除。
- 通道位置可以直接改：通道列表的「位置」单元格和通道卡片上各加了一支铅笔，点开就是现有的选点弹窗（可直接填经纬度，也可在地图上点），不用再打开整张通道编辑表单。没有通道编辑权限的账号看不到这个入口。
- 播放器会提前说明「这个协议在你这台电脑上放不了」：切到某个协议时会比对设备实际编码（H.264 / H.265 / 音频编码）和当前浏览器的解码能力，放不了就给出原因，而不是让你对着黑屏猜。

## 修复

- 播放器切换协议失败：从一种协议切到另一种时，旧播放器还没把播放容器交还，新播放器就被创建，结果报容器被占用、画面出不来。现在切换会等旧实例彻底销毁再建新的。
- 切换协议后画面状态被旧实例覆盖：旧播放器的报错、超时回调在新播放器起来之后仍会触发，把状态写成「报错」或「拉流超时」，看起来像新协议也坏了。现在旧实例的回调一律忽略。
- HLS 播放拿不到鉴权：HLS 请求没有带上播放凭证，签了鉴权的流会直接拉不到。已修正。
- 「正在连接视频流，等待首帧」的提示和实际状态不同步：有时首帧已经出来了提示还在，有时该提示的时候不提示。现在严格跟着首帧状态走。
- 首页三条迷你趋势线画的是「假数据」：SIP 卡片的大字是今日累计，曲线却是最近几分钟的每分钟增量（永远不会往上走）；点播成功率和今日流量是前端每几秒自己攒的当前值，刷新就归零，画出来是一条平线。现在三条线都改成后端给的真实历史序列（SIP 按累计、成功率按小时、流量按每小时增量），末点与卡片大字一致。顺带修好了汇总与趋势查询共用同一个查询对象导致的 SQL 歧义报错。
- 「设置位置」弹窗的暗色配色与圆角跟全站不一致：暗色模式下标题、提示文字、输入框糊在背景上，弹窗是直角。现在统一走全站弹窗样式，地图区底色也改成中性面，亮色下不再整块纯白。
- 码率类型看不懂：下拉和详情里原来只写 CBR / VBR，现改为「恒定码率（CBR）」「可变码率（VBR）」，校验提示同步改成中文说明；未识别的码值仍按字典原样显示。

## 变更

- 直播通道卡片去掉了「已请求所选配置但未确认」这行提示：它描述的其实是「一切正常，只是平台没去核实设备侧码流」，既不能点也不能改，却占着每张直播卡片一行。真正需要知情的两条（当前直播未使用所选配置 / 码流配置无法确认）保留。
- 设备管理与录像回放两个页面的样式统一，通道编辑表单做了精简，字段不再重复堆叠。
- 播放控制台调整：云台侧栏、标题栏、详情卡片间距与配色对齐，码率类型文案统一。

## 升级提示

- 升级前请备份 data/ 与 config/ 目录。
- 从 1.1.22 升级可使用在线升级、增量升级包或全量包；更早的版本建议直接用全量包。
- **存量设备升级后类型都是「IPC」**。如果你接了 NVR 或下级国标平台，请到设备列表点编辑，把类型改成对应值，之后卡片图标和类型筛选项才会正确。
- 设备类型是新增字段，升级时数据库会自动补列，无需手工执行 SQL。
- Linux 与容器版按常规方式升级即可，本次无额外操作要求。
