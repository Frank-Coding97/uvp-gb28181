# 1.1.27

发布日期：2026-11-25

这一版主要解决 Windows 单机版的一个现场问题：1.1.26 的 Windows 包在部分机器上启动时卡在「流媒体服务（ZLM）启动失败」，原因已经查清并修好，用 Windows 版的用户建议尽快升级。另外把产品名称在全线统一成「UVP-GB28181统一视频接入平台」，并修了几处表格错位与列表刷屏的细节。

## 新增

- **Windows 启动程序带图标了**：包根目录的 `UVP-GB28181.exe` 以前在资源管理器、桌面快捷方式和任务栏里都是一个白纸图标，现在换成了平台自己的图标，和其他程序放在一起更好认。

## 修复

- **Windows 版流媒体服务启动失败**：1.1.26 的 Windows 包在部分机器上启动时会停在「流媒体服务（ZLM）启动失败」。实际原因是启动时传给流媒体程序的配置文件路径少了一层目录，文件明明就在包里却读不到，程序于是悄悄退回到出厂端口（80/443）并继续运行。现在改为按实际安装位置自动推算路径，并且在启动前先确认那份配置文件确实能打开，打不开就直接说明「配置文件打不开」而不是让现场去猜。Linux 版不受影响。
- **云端录像、录像缓存的表头错位**：这两个列表滚动时表头和内容会错开一截，操作列也偏窄，现在列宽和表体对齐了。
- **流媒体会话列表的类型显示不全**：部分会话类型（例如 ICE 会话）在列表里显示的是英文原始值，现在统一显示中文。
- **SIP 报文诊断里的会话列表被占满**：设备的心跳保活包以前会塞满整个会话列表，把真正有价值的信令挤出去；现在默认不再收录这类空包。
- **SIP 报文的「起始方法」列折行**：这一列以前会把 `REGISTER` 断成两行，现在一行显示完整。
- **打开设备录像时设备树没定位**：从别处进入设备录像，左侧设备树以前停在折叠的设备节点上，现在会自动展开并选中当前通道。
- **服务升级的更新说明露出乱码符号**：升级弹窗里的更新说明以前直接显示 `-`、`**` 这类标记符号，现在按条目正常排版。
- **后端访问日志刷屏**：常规的接口访问日志不再逐条写进日志文件，排查问题时更容易找到有用信息。

## 变更

- **产品名称统一**：新装环境的系统名称、浏览器标签页都叫「UVP-GB28181统一视频接入平台」。已经装好的环境不会被改动，如需一致可在后台「系统设置 → 系统配置 → 系统名称」里改一次。
- **设备目录树底部不再显示在线/离线数量**：这一行和每台设备后面已有的「在线/总数」重复，去掉后目录更清爽，设备总数仍在设备列表里能看到。

## 升级提示

- 升级前请备份 `data/` 与 `config/` 目录。
- 从 1.1.26 升级可用在线升级、增量包或全量包，本次没有额外的操作要求。
- **Windows 单机版用户请优先升级**：本次修好了 1.1.26 里流媒体服务可能起不来的问题，升级后不需要再手工改任何配置文件。
- 这一版没有数据库结构变更，升级后直接启动即可。
