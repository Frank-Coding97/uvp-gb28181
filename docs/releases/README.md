# 升版说明存放约定

发版时，脚本会**按版本号到这个目录读取升版说明**，原样填进 GitHub Release、Gitee Release
和官网升级日志。三方共用同一份内容，不会出现"某处忘了同步"。

## 文件命名

固定为 `v<版本号>.md`，与 Git tag 完全一致（带前缀 `v`）：

```
docs/releases/v1.1.4.md
docs/releases/v1.2.0.md
```

版本号以仓库根目录 `VERSION` 文件为准。

## 内容格式

第一段是给用户的总体说明，之后按「新增 / 修复 / 变更」分节。分节标题用 `##`，
脚本不做解析，整篇内容都会作为 Release 正文发出去，所以**写成能直接给用户看的成品**，
不要留 TODO、内部代号或调试备注。

```markdown
# 1.1.4

发布日期：2026-10-18

一句话说明这次升级给用户带来什么。

## 新增

- 新增了什么能力，用户在哪里能找到

## 修复

- 修了什么问题，之前的表现是什么

## 变更

- 行为、默认值或界面上的调整，升级时需要注意什么

## 升级提示

- 需要先做什么（备份、停服、配置调整等）
```

## 发版前检查

- 文件名与 `VERSION` / 目标 tag 一致，否则脚本报"找不到升版说明"并中止。
- 内容里不要写内部分支名、服务器地址、账号等不便公开的信息。
- 本次如果没有对外可见的变化，也要写文件，明确说明"内部维护版本，无对外可见变化"。
