# 1.1.22

发布日期：2026-11-12

这一版新增「心跳记录」，让设备掉线能直接看出断在哪一段；另外集中修了一批「设备明明在线却一直显示离线」「页面 403」「Windows 服务升级页不能用」这类问题，并重做了通道配置弹窗的排版。

## 新增

- 运行监控新增「心跳记录」：列出平台实际收到的每一条心跳（收到时间、平台判定、应答耗时、心跳间隔、来源地址、传输方式、客户端），并按时间画成一条连续性条带 —— 哪段有线、哪段断了，看一眼就知道，不用再逐条翻表。表头给出已加载条数、异常条数、平均间隔和最近一次心跳。
- 心跳记录会主动说明「为什么这里没有数据」：如果当前时间范围内一条心跳都没有，会自动往前 7 天找最后一次心跳，并提示「最后一条心跳在什么时间、距今已经多久没有心跳」，避免把「设备昨天就掉了」误读成「记录被清了」。
- 部署时自动填写对讲的候选地址：对讲走 WebRTC，浏览器拿到的候选地址取自 ZLM 的 rtc.externIP，出厂为空时浏览器与平台不在同一网段就会「点了没反应」。现在启动前自动探测并写入（云主机取弹性公网 IP，局域网取默认出口网卡地址），也可以用 config.env 里的 UVP_ZLM_EXTERN_IP 固定；探测不到就保持原样，不乱猜。
- 广播跨网段时会提示音频大概率到不了设备：广播用什么传输方式由设备决定，其中 udp 与 tcp_active 两种跨网段都过不去，只有 tcp_passive 能穿 NAT。现在设备选了前两种、且媒体地址与信令来源不在同一网段时，播放器在「正在广播」期间常驻提示。只提示，不阻断。

## 修复

- 设备 NAT 重绑定后会永久卡在离线：设备不再续注册、只保留心跳，而平台对它的每条心跳都回 200，设备因此认为注册一直有效、永远不重新注册，双方互相等待。现在「注册已过期」的心跳改回 403（Registration Expired），设备会重新注册；来源不可信的心跳仍然静默丢弃并回 200，不给探测者反馈。
- 设备列表页报 403 打不开：存量数据库缺少接口权限登记，已补齐。
- 报警列表里堆着一批空白记录：设备对报警的应答（Result OK）被当成新报警存了下来，级别、方式、类型全空。现在只把真正的报警通知入库；另外按标准不携带报警类型的方式（1/3/4/7）显示「—」而不是「未知」，不再看起来像平台丢了字段。
- Windows 单机版「服务升级」页一直提示不可用（503）：解压目录太深时，升级助手与后台通信用的套接字文件路径超过系统上限，两端都连不上。现在路径超限会自动换到固定的短路径，并在助手启动与后台连接两侧提前校验。
- Windows 单机版装好之后第二次启动服务起不来：启动脚本收紧目录权限时，把授权锁文件的权限也一并清空了，后台因此拒绝启动。现在单独恢复锁文件的继承授权，锁文件本身不删。
- 从设备进入地图再返回，视角莫名变成全网设备列表；从设备列表看一眼地图再回来又变成通道视角。现在都按进入地图前的视角还原。
- 设备/通道列表的加载反馈不对：首次进入和翻页没有任何提示（一片空白），而 10 秒自动刷新时又整块盖住遮罩。现在只在该有的时候盖遮罩，自动刷新只转一下刷新按钮；点进设备通道时左侧目录树莫名闪一下的问题也一并修好。
- 云台控制与设备配置的下发改为「先确认设备应答、再继续处理」，避免同一件事被重复处理；云台操作的过期判定改为按主键精确处理，不会再误伤别的操作。

## 变更

- 通道配置弹窗排版重做：基本参数页的滑杆不再横贯整行，加减按钮恢复成正常小方块，数值框能完整显示数字（不再被清除按钮压住）；设备名称等输入框与滑杆的右边界对齐；报警上报页的标签不再被截断（以前正好截掉括号里的标准元素名）；整页字号与行高放大一档，更易读。
- 首页：把卡片拉高时，曲线图会长高吃掉多余空白，不再把一大片空白堆在下方；图表仍保底 90 像素，不会把坐标轴和基线挤掉。

## 升级提示

- 升级前请备份 data/ 与 config/ 目录。
- 从 1.1.20 升级请使用在线升级、增量升级包或全量包；低于 1.1.20 的版本请直接用全量包。
- Windows 用户如果此前因「服务升级页一直不可用」没能完成升级，建议这次用全量包覆盖安装；装好后请再确认一次「服务升级」页能正常打开。
- 对讲跨网段的现场升级后会自动填好候选地址，无需手工配置；已手工设置过 rtc.externIP 的以现场配置为准。
- Linux 与容器版按常规方式升级即可，本次无额外操作要求。
