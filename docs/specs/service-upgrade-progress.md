# 服务升级进度可视化

状态：老板已确认需求、方案与任务清单；源码实现与本地验收完成。

## 目标

管理员在导入升级包及应用升级期间，能看清当前正在做什么、是否仍在处理，以及最终是否成功。页面沿用系统现有风格。

## 用户故事

- 选择离线包后，可以看到文件名、已上传大小、总大小及真实上传百分比。
- 上传完成后，可以区分等待处理、后台校验、校验通过；校验通过后仍须主动创建并确认升级任务。
- 应用升级后，可以查看准备、停止服务、备份、迁移、切换版本、启动验证及最终结果。
- 服务重启或网络断开时，可以识别正在重连；恢复连接后继续查看同一任务。
- 失败时，可以看到失败阶段与原因，并区分升级失败、已回退及需要人工恢复。

## 验收标准

1. 选包后立即出现上传状态，展示文件名、已传/总大小；总大小已知时展示真实百分比，不以计时器推进进度。
2. 上传到 100% 仅表示文件传输完成，不能显示“升级成功”或提前允许应用；后台校验通过后显示“升级包已就绪”。
3. 无精确百分比的后台阶段展示步骤与处理中状态，明确当前阶段，不编造校验、备份或迁移百分比。
4. 应用升级时展示服务端实际任务阶段。等待授权单独显示为等待状态；不能误显示正在停服。
5. 连接中断时保留最近状态并标明正在重连，不能将中断推断为成功或回退。只有收到明确成功结果后才展示升级成功。
6. 完整上传已受理后刷新页面，可恢复后台导入或升级任务；传输尚未完成时刷新，不承诺继续上传。
7. 失败、已回退、需要恢复与未知阶段有明确文字，失败位置和原因可查看。
8. 复用系统现有视觉风格，桌面和窄屏、明暗主题均可阅读；默认展示紧凑进度，诊断详情按需展开。
9. 保留权限、签名校验、二次确认及无人值守行为；不因新增进度展示自动应用升级。

## 非目标

- 不改变本次 1.1.5 包，不中断正在进行的手动验收。
- 不新增断点续传、后台阶段耗时预测或虚构的整体百分比。
- 不重构升级执行机制或扩展发布站点功能。
