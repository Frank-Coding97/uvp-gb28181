## 目标

修复静态审查报告 D01–D05 五项 P1 问题，保证合法上级请求可正常处理、注册维护不中断、注册状态符合实际授予的有效期，并防止不可信来源调用级联能力以及新增共享通道误失云台权限。

依据：`docs/audits/gb28181-cascade-static-review-2026-10-15.md`。本规格已对照当前工作区重新核查，问题路径仍存在；尚未修改业务实现。

## 用户故事

- 作为运维人员，我希望合法 SDP 不会导致服务异常，续期和心跳发生重叠时级联仍能持续工作。
- 作为下级平台管理员，我希望平台遵守上级实际授予的注册期限，并只接受可信上级对共享资源发起的请求。
- 作为共享资源管理员，我希望平台允许云台控制时，新共享通道按现有默认规则获得权限；已有限制不会被无故放开。

## 范围与验收标准

| 编号 | 修复后行为 | 验收标准 |
|---|---|---|
| D01 | SDP 会话级属性与媒体级属性正确区分，异常输入按解析结果处理 | 首个 `m=` 前的方向、格式及其他相关属性不再引发 panic；合法 Play/Playback 仍能解析；非视频媒体属性不污染视频结果；非法报文返回可处理的错误。 |
| D02 | 事务重叠不会丢失必要的注册维护工作 | 心跳占用事务期间到期的续期最终执行；续期期间到期的心跳后续恢复；重复到期事件不造成并发事务或无限补发；停止后不恢复维护任务，并正确收尾。 |
| D03 | 注册状态和续期时机依据上级实际授予的期限 | Contact expires 与 Expires 分别覆盖；两者冲突按适用 SIP 规则取值；上级缩短期限时在到期前续期；未提供期限时保持合理兼容；零值、非法值不造成错误的长期在线状态或忙循环。 |
| D04 | 入站请求具有可信的上级来源约束 | 伪造 From、端口和传输协议但来源不可信的 INVITE、RecordInfo 不得触发取流、发流或录像查询；有效来源的实时点播、回放和录像查询保持可用；ACK/BYE/CANCEL 等会话操作不能借同类弱匹配越权；多上级隔离仍有效。 |
| D05 | 新共享通道遵循平台现有 PTZ 默认授权规则 | 平台允许/禁止 PTZ 时新增共享均按相应默认值保存；前端草稿默认值不再误覆盖后端继承；已有通道的显式权限保持不变；平台总开关仍约束最终控制权限；取消共享后重新共享的权限行为与既有授权规则一致。 |

## 验证边界

- 每项先补可执行的缺陷复现测试，确认修复前失败，再修改实现并运行针对性回归。
- 核心并发调度修复需执行相应竞态检查；权限修复需覆盖前端提交与后端持久化、请求入口到资源调用的边界。
- 本轮使用本地代码、模拟依赖和隔离测试数据验证，不操作浏览器，不修改现有开发环境级联台账。
- 测试结果只能证明已覆盖的代码行为，不代表真实上级、设备动作或媒体互通已验收。

## 非目标

不处理 D06–D16 和 M01–M13，不批量修改存量通道权限，不增加无关功能；不部署、推送或提交其他工作区改动。

## 技术方案阶段需明确的边界

- D04 当前宽松匹配用于换网卡、VPN/NAT 场景。修复不能继续把身份字段当作可信来源证明；技术方案需明确合法多地址接入的支持边界，以及不再允许的未验证来源行为。
- D03 需分别核对适用版本的注册规则及现有 SIP 事务返回信息，避免混用 2016/2022 标准约束。
- D05 不将“本轮修复”解释为给全部存量共享通道开启云台权限。
