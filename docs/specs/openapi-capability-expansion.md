# 目标

通过 OpenAPI 向第三方提供平台支持的完整设备侧业务能力，包含 GB/T 28181-2022 定义的设备查询、控制、媒体、事件通知等能力，也包含平台已有的设备扩展业务。对标准或设备版本有依赖的能力须明确标注，不支持时返回可识别的结果。

“全部能力”指操作设备及其音视频资源的产品能力，不指把平台内部所有 `/api/**` 管理接口直接开放给第三方。能力目录必须显式登记，不从内部路由自动生成。

# 已核实的现状

当前工作区源码及 `api/openapi-v1.yaml` 显示，对外目录有 12 项操作：设备/通道查询 6 项、实时点播 1 项、云台预置位和操作查询 5 项。对外尚未覆盖设备录像查询、回放控制、下载、抓拍、语音、设备配置、升级和 2022 扩展控制等能力。

平台内部已有录像检索、回放与下载会话、抓拍、设备配置、实时/历史媒体、预置位、巡航/扫描、看守位、精准云台、目标跟踪、存储卡、重启、固件升级、语音对讲等实现入口。覆盖度、运行条件以及设备实测结果仍需逐项盘点；内部有入口不等于已完成对外契约或端到端可用。

GB/T 28181-2022 的能力依据包含第 7 章控制要求、第 9 章流程与协议接口、附录 A MANSCDP 命令集、附录 B MANSRTSP、附录 N 域间订阅通知及附录 O 采集部位代码。标准的“应、宜、可”强度需保留；不能把协议标准等同于每台设备都支持所有功能。

本规格依据源码、OpenAPI 文档和 GB/T 28181-2022 工程参考整理，未验证部署版本、签名请求、真实设备或媒体链路。规范报文及字段实施前须对照正式标准原文核实。

# 用户故事

- 第三方可以按授权查询设备、通道、目录、状态、配置、存储、告警及设备能力。
- 第三方可以执行获授权的设备控制、录像与媒体操作、图像抓拍、语音及设备维护，并读取异步任务结果。
- 第三方可以订阅设备告警、目录、位置及状态等事件，并可靠地处理通知重试和重复投递。
- 管理员可以按能力分组查看并逐项授权，控制、配置、下载、破坏性维护等权限互相独立。
- 第三方能知道操作是平台已受理、设备已应答、设备已执行，还是设备不支持/执行结果未知。

# 完整能力盘点范围

下表定义必须逐项盘点的设备侧能力族，不代表每项都已实现。盘点需给出“已对外、平台已实现待开放、需补实现、设备/协议不支持、排除”的明确状态。

| 能力族 | 必须盘点的操作 |
| --- | --- |
| 目录与设备查询 | 设备/通道目录、设备信息、设备与通道状态、设备能力、目录刷新及查询结果 |
| 参数与配置 | 配置读取/刷新、视频参数读取与设置、设备配置读取与下发、配置操作结果 |
| 告警与状态 | 告警查询、告警布防/撤防/复位、设备状态事件、报警/状态通知订阅 |
| 实时与历史媒体 | 实时点播及会话释放/状态；录像检索；历史回放、暂停/继续/定位/倍速/停止；录像下载、状态、取消及受控取文件 |
| 录像业务 | 设备录像开始/停止；平台云录像查询、回放、下载及任务结果（作为平台扩展能力单列） |
| 云台与镜头 | 方向/变倍/聚焦/光圈、预置位、巡航轨迹与启停、扫描、看守位、雨刷/辅助控制、精准云台状态与操作结果 |
| GB/T 28181-2022 扩展控制 | 目标跟踪、存储卡状态及格式化、软件升级及结果、远程启动/重启、抓拍控制及结果；逐项核对协议版本、应答类型和设备能力 |
| 图像采集 | 抓拍会话创建、结果查询、图像库查询与取图；区分设备抓拍与平台已有图片资源 |
| 语音 | 语音对讲、语音广播的创建、状态、结束和媒体资源；作为标准能力或平台扩展分别标识 |
| 位置与移动设备 | 实时/历史位置查询、位置订阅通知，以及采集部位等 2022 目录扩展字段（以平台实际实现为准） |
| 订阅与通知 | 目录、报警、位置、状态等订阅生命周期、续订、取消、事件交付与查询补偿 |

2022 标准命令需区分有应答与无应答。对于无应答命令（例如目标跟踪），接口只能报告平台已下发或本地记录的指令意图，不得伪称设备已执行。回放控制须核对标准规定的 MANSRTSP/INFO 流程；注册版本协商和设备能力决定可用命令，不向较低版本设备发送其不能识别的消息。

# 能力与授权规则

1. 每个可授权操作有独立稳定 scope，并关联业务分组、公开路由、请求/响应契约、执行适配器、风险级别、数据范围和协议/设备支持条件。
2. 能力目录只显示代码中已注册且可执行的操作；数据库发布或管理员授权本身不能创造任意路由或绕过代码执行门禁。
3. 设备与通道按客户端数据范围校验；会话、任务、操作、下载票据、抓拍图片及订阅对象都必须重新绑定并校验所属资源。
4. 控制、配置、媒体、下载和维护操作分别授权。重启、固件升级、存储卡格式化等高风险操作必须有独立 scope、审计和明确确认语义；格式化等破坏性操作不得混入普通设备控制权限。
5. 2016/2022 协议版本、设备上报能力和平台注册能力须能共同决定可调用性。标准版本支持不代表具体型号支持；未知能力不得假定为支持。
6. 异步操作返回 operation/task/session 标识，并区分已受理、等待设备、成功、失败、超时和结果未知。媒体及文件链接遵守有效期、撤销和资源释放策略。
7. 对接事件通过明确配置的回调或可恢复的查询接口交付；必须定义签名、重试、顺序、去重、续订和断线补偿语义。

# 验收标准

1. 形成设备操作源能力清单，逐项对应现有产品入口、GB/T 28181 版本/条款或平台扩展、OpenAPI 路由/scope、授权风险、设备支持条件及实现/验收状态；没有未分类的设备操作能力。
2. 已确认纳入范围的能力全部进入分组能力目录；未授权请求拒绝，管理端授权、目录、文档和实际路由一致。
3. 第三方不能通过替换 deviceId/channelId/sessionId/taskId/operationId/download token 越权访问其他部门资源。
4. 覆盖 2016 与 2022 版本协商和命令差异测试；不支持能力、无应答能力和设备结果未知均按真实语义响应。
5. 控制命令、回放/下载/抓拍/对讲会话和订阅具备明确的启动、状态、结束/取消、超时与清理行为。
6. 高风险命令有独立授权和审计；破坏性操作的确认、幂等和重复提交行为有测试锁定。
7. 每个操作有契约、鉴权、数据范围和错误映射测试；协议交互通过 SIP/MANSCDP/MANSRTSP 报文验证；媒体类能力通过媒体链路验证；设备相关能力通过设备型号或模拟器接受验证。三类证据分别报告。
8. 不声称所有厂商设备都支持全量命令；公开文档列明标准/平台扩展边界及不支持响应。

# 非目标

- 不把用户、角色、客户端密钥管理、权限系统、SIP 服务、媒体节点、固件仓库 CRUD、日志和平台配置等管理能力作为第三方设备操作开放。
- 不将内部 `/api/**` 路由、原始 SIP 报文或任意 MANSCDP XML 透传给第三方；对外使用版本化、类型明确的业务契约。
- 不允许客户端以自定义原始协议命令绕开能力目录、参数校验、授权和审计。

# 阶段决策

老板已确认方向是“对外提供设备操作全部能力，包含 GB/T 28181-2022 能力”。本稿将“全部”界定为上述设备侧能力族，以及盘点后纳入的产品实现能力；不能把平台全部内部管理 API 或设备厂商未实现的能力视为可用。需求规格确认后再产出技术方案和带测试用例的任务清单。
