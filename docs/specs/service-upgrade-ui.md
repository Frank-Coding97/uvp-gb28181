# 服务升级页面整理

状态：待老板确认需求与交互预览。预览使用示例数据，不代表部署完成。

## 目标

用户进入“系统管理 → 服务升级”后，能立即判断当前版本、是否可升级，以及如何手动导入升级包；阅读记录时不被配置项、构建标识和长日志干扰。

## 用户故事

- 管理员先查看当前版本，再检查在线更新或导入离线升级包。
- 管理员在升级前可阅读新增功能、改进、问题修复和升级须知；升级后仍可从历史记录回看该版本说明。
- 管理员查看最近升级结果，需要排障时再展开任务详情和诊断日志。
- 管理员主动进入自动升级设置，配置维护窗口并明确保存，区分已保存状态与未保存编辑。
- 只读用户可查看状态和记录，只能在具备管理权限时执行操作。

## 验收标准

1. 默认页突出当前版本与手动升级入口，不展示整张无人值守配置表；“升级记录”和“自动升级设置”可切换。
2. 未配置发布站点时，检查更新按钮说明不可用原因，离线导入根据实际能力及权限独立展示。
3. 数据库迁移阻断、状态失联、恢复未完成等影响升级的情况，在操作区域附近明确提示；不得用界面整理掩盖真实问题。
4. 记录列表展示版本、结果、方式、操作者、本地可读时间和详情入口。Build ID、任务 ID、失败阶段和完整诊断按需查看，长日志不撑高列表。
5. 成功、失败、已回退、待恢复、进行中分别表述；只有服务端已验证回退才能写“已恢复旧版本”。
6. 自动升级设置使用清晰分组和稳定的表单对齐；统一启用状态、保存按钮与未保存提示，轮询不覆盖用户编辑。
7. 部署信息使用可理解的中文，构建身份等技术信息默认收起；未知状态如实显示，不能伪造正常。
8. 桌面与窄屏下按钮、表单、列表均不互相挤压，详情日志可滚动，适配既有明暗主题。
9. 保留现有权限、签名校验、二次确认与升级状态恢复行为。
10. 后续先做页面行为回归与构建，再在 220 的 52000 隔离实例登录验证菜单点击、实际页面及升级操作入口；本地预览不等于上线。

11. 版本更新说明与执行诊断分别提供入口；当前版本及历史记录可查看说明，在线发现新版或离线包校验通过后可在应用前阅读。说明来自签名发布元数据并可随历史记录保存；缺失时提示“该版本未提供更新说明”，不得根据日志推测或编造更新内容。多版本跨度只显示实际提供的说明，不暗示完整覆盖中间版本。

## 非目标

仅按需补齐版本说明的透传与历史留存，不改变升级执行协议、迁移规则、签名策略、发布站配置及无人值守执行机制；截图中未知迁移记录是独立运行问题，需单独核对，不能仅通过中文提示宣称已修复。
