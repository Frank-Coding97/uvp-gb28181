# 目标

管理员通过平台配置日志保留天数，平台复用现有定时任务自动清理过期数据库日志，避免日志数据持续积累。

# 用户故事

- 管理员在统一入口查看、修改各类数据库日志的保留天数。
- 管理员保存后，后续清理使用最新配置，重启后仍保留配置。
- 管理员在现有定时任务及任务日志中查看清理任务的启停和执行结果。

# 已核实的现状

- 登录日志通过平台定时任务每日清理，保留期固定为 180 天。
- SIP 日志已有 1–365 天保留配置，默认 7 天，使用独立后台循环清理。
- 媒体调度日志固定保留 7 天，使用独立后台循环清理。
- 播放生命周期事件固定保留 7 天；播放记录另有 30 天保留逻辑，当前与仪表盘历史数据清理关联。
- 操作日志、定时任务执行日志已入库，尚未发现按可配置保留期自动清理的逻辑。
- 日志中心的运行日志来自实时日志流和内存缓冲，不属于数据库日志。

# 范围与建议默认值

各类日志分别配置保留天数；以下默认值和清理边界已确认。SIP 已有自定义值必须保留。

| 日志类型 | 建议保留天数 | 清理范围 |
| --- | --- | --- |
| SIP 日志 | 沿用现有值，缺省 7 天 | 过期报文及相关已结束诊断数据 |
| 操作日志 | 180 天 | 过期操作日志，包含已软删除的历史日志 |
| 登录日志 | 180 天 | 过期登录日志 |
| 定时任务日志 | 30 天 | 过期任务执行记录，不删除任务定义 |
| 播放日志 | 7 天 | 已结束播放的过期事件及关联记录，保留活动播放数据 |
| 调度日志 | 7 天 | 过期媒体节点选择日志 |

# 验收标准

1. 提供统一配置入口，建议位于“系统配置 → 日志清理”；每类日志独立配置保留天数。
2. 保留天数必须是 1–365 的整数；空值、零、负数、小数和超范围值明确报错，不自动改成边界值。
3. “保留 N 天”表示只删除早于执行时刻减去 N×24 小时的数据；恰好等于截止时刻的数据保留。
4. 保存配置不立即删除日志；下一次任务执行使用最新配置，重启后仍生效。
5. 建议每日服务器本地时间 03:00 清理，使用现有定时任务的启停、手动触发和执行结果能力。
6. 同类日志不能同时由旧后台循环和新定时任务重复清理；禁用清理任务后，该类自动清理停止。
7. 清理实际移除过期数据库记录，分批执行；任务超时或失败可见，后续执行可继续处理剩余数据。
8. 单类日志清理失败不影响其他类型；整体执行结果反映失败，并能定位失败类型及各类删除数量。
9. 清理相关日志时保持关联数据一致性；不删除活动播放、进行中的诊断、登录会话和任务定义。
10. 只有具备相应配置权限的用户可以修改保留期；后端验证权限及输入。
11. 升级保留已有 SIP 保留期及任务启停状态；操作日志、定时任务日志新增自动清理需管理员首次保存配置后启用。

# 非目标

- 本次不处理运行日志文件轮转、磁盘文件删除、录像、位置历史、仪表盘统计数据的保留策略。
- 不增加立即清空全部日志入口，不修改日志采集开关或日志查询业务。
- 不扩大到其他业务数据库表，不执行生产数据删除或部署。

# 已确认决策

- 各类日志分别配置保留天数，避免覆盖当前不同日志的保留策略。
- 统一入口使用“系统配置 → 日志清理”，每日 03:00 执行。
- 播放记录与事件统一采用 7 天默认保留期。

需求规格已确认，进入技术方案、任务清单及实施阶段。
