# 目标

让管理员在当前上级平台的业务分组界面内，清楚完成建目录、批量分配通道、保存以及查看发布状态。
日常维护以组织和通道为中心，减少重复选择、跨弹窗往返和误操作。
老板已确认操作体验方向，并于 2026-10-14 授权直接实施。最新范围以下方“共享与目录统一工作区”修订为准。

# 当前问题与证据

以下来自当前工作区源码及已有规格核对，未作为真实浏览器视觉验收结论。

- 平台行的业务分组、共享、编辑、推送为分散入口；发布业务分组开关位于平台编辑向导第四步。
- 组织内添加通道需要选择单个通道，再次选择目标组织，再点击“挂载 / 移动”；已选组织没有直接成为操作目标。
- 已挂载通道仅显示名称和移除按钮，缺少编号辨识、搜索、批量操作和未分组资源视图。
- 新增组织默认建立在当前节点下面，按钮“添加组织”没有说明创建位置；父节点选择只显示名称，重名组织不易区分。
- 已有内容的节点删除按钮仅被禁用，没有给出需要处理的内容和下一步入口。
- 每次进入默认选择数组第一节点；根节点的通道计数仅计算直接挂载，容易在存在下级通道时仍显示零。
- 关闭后清空编辑，没有未保存确认；版本冲突文案要求关闭重开后合并，与关闭清空编辑的行为矛盾。
- 保存提示、发布开关、主动推送结果分散，用户难以判断当前配置何时用于上级目录。

证据文件：BusinessGroupManager.vue、cascade/index.vue、cascade-business-group.md。

# 用户故事

- 首次配置时，我知道先建立哪一层、通道从哪里来，以及完成后还需做什么才能用于上级目录。
- 日常维护时，我能在一个组织内一次加入、移出或移动多个已共享通道。
- 通道很多或同名时，我能通过名称、发布编号和当前组织路径找到正确资源。
- 编辑过程中，我知道哪些修改尚未保存，误点关闭、跳转共享或保存失败不会直接丢失编辑。
- 保存后，我能区分配置已保存、业务目录发布开关已开启、推送请求结果及上级展示效果。

# 推荐操作体验

## 入口与整体布局

- 保留上级平台行入口，进入该平台的宽幅管理工作区；页面不另设标题区和上级状态卡。
- 页面直接从共享方式标签开始；统计通过当前资源范围及列表数量展示。
- 左侧为可搜索、折叠的组织树，另提供“未分组通道”视图。未分组仅是管理视图，不创建国标节点。
- 右侧展示当前组织完整路径、通道列表及主要操作。节点名称、编号等信息简洁展示，修改时进入“编辑组织”。
- 根节点展示目录概览与下一步引导，不用一个“不能挂载”的空列表占据主要区域。
- 标签旁集中返回、推送、放弃与保存；标签下用紧凑文字展示修改摘要和操作提示，不设底栏，通道区域利用剩余高度。

## 首次建立目录

- 未建目录时显示简短路径：创建业务分组 → 新建组织 → 添加通道 → 保存并设置发布。
- “创建业务分组”优先填写业务名称，提供建议编号并说明规则；用户可在创建时检查编号。
- 建立根后，明确引导“新建下级组织”；新建时清晰显示所属路径，不先插入一个不明位置的默认节点。
- 没有已共享通道时显示“尚无可分配通道”与“去共享通道”。跳转前处理未保存修改，完成共享后返回当前平台分组位置。
- 已有目录时直接进入管理工作区，不强制重复走首次引导。

## 批量管理通道

- 选中组织后点击“添加通道”，目标固定为该组织，不要求重复选择。
- 选择界面支持名称或发布编号搜索、多选；默认展示未分组通道，允许查看其他组织的通道。
- 通道显示名称、发布编号、当前组织路径；同名资源可明确区分。
- 从其他组织加入通道时明确显示原组织和目标组织，并提示这是移动而非复制。
- 组织内支持“批量移至其他组织”“移出组织”。移出后进入未分组视图，提示仍保持共享。
- 未分组视图支持批量选择目标组织进行归类；不把“未分组”显示成错误或未发布。
- 批量选择数量、筛选结果及全选范围清楚可见，避免用户误认为只操作当前可见行。

## 组织维护

- 主要动作使用“新建下级组织”“编辑组织”“移动组织”；移动目标显示完整路径。
- 目录树明确区分业务分组和虚拟组织，通道使用摄像机语义，禁止将资源表现成可编辑目录。
- 根展示全树通道总量；组织明确区分直属数量与含下级数量，右侧默认只显示直属通道。
- 非空组织不可直接删除，提示剩余子组织和直属通道数量，并提供对应处理路径。
- 删除空组织需要明确确认；不自动级联删除其内容。

## 保存、发布与恢复

- 所有目录编辑在保存前属于本次未保存修改；切换组织保留编辑，关闭或离开时提供继续编辑、放弃修改、保存后离开。
- 保存失败保留编辑和当前选择，错误尽量定位到相关组织、通道或字段。
- 版本冲突时保留草稿供核对；明确重新载入会放弃本地修改，并需用户主动确认，不承诺自动合并。
- 工作区内可查看并设置业务目录发布状态，具备相关权限时才能修改；无有效根时说明原因并引导完成配置。
- 保存目录与开启发布分别报告结果。若目录保存成功但开启发布失败，保留已保存结果并允许单独重试。
- 手动推送独立于保存，推送使用已保存配置；存在草稿时先明确处理，不悄悄推送旧配置。
- 提示开启发布后，已保存业务目录可用于后续目录查询或推送；仅保存、开启开关或请求被接受均不得称为“上级已展示”。
- 若配置自动推送，提示保存可能触发自动推送；具体结果与现有能力保持一致，不虚构接收状态。

# 验收标准

1. 初次进入即可辨识当前上级、目录是否建立、发布开关及可分配资源来源。
2. 选择一个组织后，可一次搜索并加入多个通道，无需重复选择目标组织。
3. 通道移动前可识别原组织与目标；同一上级下仍最多归属一个组织。
4. 移出组织不取消共享，未分组共享通道保持原有发布规则。
5. 创建和移动组织时位置明确；不可用操作解释原因，重名组织可通过路径区分。
6. 关闭、离开、保存失败和版本冲突均不会无提示丢失修改。
7. 保存与发布各自反馈成功失败，平台停用或缺少权限时明确说明操作限制。
8. 小屏可完成组织选择、批量操作及保存；键盘可到达主要操作，明暗主题信息可辨识。
9. 真实页面验收覆盖首次配置、已有目录维护、同名通道、多层组织、保存失败和冲突恢复。

# 范围与规范约束

- 延续一个上级一个业务根、嵌套组织、已共享通道单归属规则。
- 不增加全局分组菜单、多归属、拖拽编排、自动分组或批量导入。
- 不改源设备、下级上报目录及共享授权语义，不将分组操作隐式变成共享操作。
- 一个上级一棵业务树、每个通道仅归属一个虚拟组织，是当前产品约束；不能表述为国标普遍限制。
- 工作区的树形视图表达业务归属；通道的物理所属设备不因分组操作改变。
- 编号遵循统一编码规则：业务根类型码 215、虚拟组织类型码 216、20 位数字；创建时提供建议编号和合法性校验，保存后稳定，不因改名或移动重新生成。
- 已核对 2016 附录 O 与 2022 附录 J 的业务树规则：业务分组为根、虚拟组织为分支、设备为叶；2022 明确不包含子业务分组。
- 两版分别核对协议字段，前端不拼装国标 XML。2016 附录 A 与 O 对 BusinessGroupID 位置的内部不一致及目录查询版本差异在技术方案中明确记录，不能把现有实现直接当作标准结论。
- 未归属虚拟组织的已共享通道继续遵循既有发布行为；“未分组”是管理筛选状态，不等于未共享或未发布。
- 业务目录保存、发布开关更新、手动推送是不同操作和结果。界面可以串成一步步引导，但不能把其中一个结果冒充另一个。
- 业务树编辑使用级联共享权限，发布设置使用级联管理权限，手动推送使用现有推送权限和启用条件；优化入口不扩大账号权限。

# 2026-10-14 已确认修订：直接选通道并共享到组织

老板在内置浏览器走查后确认按新方案修改。本节取代上文“只可选择已共享通道、不改变共享授权”的交互范围；共享授权仍需明确表达并遵循原权限。

- 现场：上级 wvp-220 的共享快照为空，设备通道查询返回 10 路；原分组选择器只查共享快照，导致无数据。
- 选中组织即可查询账号有权限的本地通道，不要求先退出配置共享。未共享通道加入草稿，统一保存时明确共享给当前上级并归入该组织。
- 已共享通道保留发布编号、PTZ 等配置；其他组织通道经明确移动确认改归属。移出已共享通道仍保留共享，移出待共享草稿则取消这次新增共享。
- 保存前呈现新增共享、加入、移动、移出的数量与目标上级；共享与目录绑定要么一起完成，要么均不变。
- 左侧树上方集中新建目录、下级组织、编辑和删除操作；树节点支持右键及 Shift+F10 菜单，操作作用于目标节点。右侧顶部只保留通道操作，组织字段按需展开。选择通道在同一面板替换内容，不叠第二层弹窗。
- 标签旁提供返回、放弃和保存，推送仍是独立动作；保留草稿离开保护，修改摘要位于标签下方。
- 215/216 编码和物理父级语义不变；仅保存不等于上级已展示。当前有效版本为 2016，保留已有双版本报文逻辑。


# 2026-10-14 已确认修订：共享与目录统一工作区

本节取代上述分散共享入口、强制先建树和弹窗往返的描述；老板已明确授权直接落地。

- 平台列表只保留“共享与目录”资源管理入口；共享数量点击进入同一独立页面。
- 左侧固定“全部共享”“未分组”，下方业务目录；右侧共用可搜索、分页、多选的通道表。没有业务根也可添加共享，通道保持未分组。
- 在虚拟组织添加未共享通道，明确将其共享给当前上级，并在一次保存中建立组织归属。根仅汇总，不接收通道绑定。
- 添加、取消共享、组织归属和通道云台权限共同形成一份草稿；保存前展示变更摘要，并一次原子提交。
- “移出组织”仍保持共享；“取消共享”同时移除业务绑定；关闭业务目录发布不取消共享。
- 组织名称、编号、父级编辑按需展开；批量勾选仅表示选择范围，不直接改变共享状态。
- 保存配置、发布设置和手动推送各自反馈；离开独立页面须处理未保存修改。不会将本地保存或推送响应称为上级已展示。
- 复用既有权限与目录接口，不新增全局业务分组菜单；协议序列化、物理归属、产品单根/单归属约束保持原逻辑。

# 2026-10-14 已确认修订：按照目录共享 / 按照通道共享

本节为最新规则，取代上文独立发布开关和两次保存的描述。老板已确认标签决定实际共享方式、保存后生效；目录模式允许保留未归类但仍共享的通道，并授权直接继续实施。

- 通过两个标签选择共享方式，当前生效方式与草稿目标明确分开；切换标签不立即写入或推送。
- 通道模式直接维护共享通道，不要求业务根；目录树与归属数据保留，隐藏目录管理动作。
- 目录模式显示资源范围与目录树，流程为业务根 → 虚拟组织 → 添加/归类通道 → 保存。新增通道必须选中虚拟组织，业务根不能作为通道目标。
- 目录模式保存要求唯一有效业务根；移出组织只解除目录归属，不取消共享，未归类通道仍可保存并保持共享。
- 共享方式、目录、归属、共享增减和通道权限形成同一草稿并一起提交；失败不产生部分修改。切回通道模式保留目录及通道归属。
- 平台编辑器只显示共享方式摘要，修改入口统一到共享与目录。资源写权限仍为 share，方式实际变化另外要求 manage。
- 保存成功但运行时同步失败时显示已保存的真实方式和修订号，允许重试同步；不能宣称上级已展示。
- 组织归属是目录管理信息，不把“所有共享通道必须归类”描述为 GB/T 28181 强制条款。
