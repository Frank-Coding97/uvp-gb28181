## 目标

修复静态审查报告 D06–D16 共 11 项 P2，使管理操作准确表达持久化与运行时结果、级联注册可恢复并完成版本协商、已发布目录可查询，以及媒体会话与既有回放控制可正确维护。

依据：`docs/audits/gb28181-cascade-static-review-2026-10-15.md`。规格编写时已复核问题路径；实施结果和未完成边界见任务清单，本规格中的验收目标不等于实机验收结论。

标准以 GB/T 28181-2022 为本轮基准，同时保持既有 2016 和 auto 配置的兼容边界。标准中的应、宜、可与工程策略分别说明，不将产品选择写成国标强制要求。

## 用户故事

- 作为管理员，我希望保存、启停和删除后的提示反映真实结果，不把配置已保存误报为上级注册或注销已经成功。
- 作为下级平台运维人员，我希望上级重启、心跳失败或媒体中断后系统可以恢复或收尾，不遗留虚假在线状态和媒体资源。
- 作为上级平台使用者，我希望通过已发布的设备和业务目录节点查询共享资源，使用合法域名配置接入，并能够重新请求同一媒体源和控制历史回放。

## 范围与验收标准

| 编号 | 预期行为 | 必须验证的边界 |
|---|---|---|
| D06 | 保存、启停、删除提示区分配置结果与运行时同步结果 | HTTP 200 且 `runtimeSynced:false` 时显示准确的降级提示并刷新实际状态；不显示已经注册、已经注销或未经证实的删除成功；正常同步也不把异步注册请求当作注册完成；请求失败保持真实错误反馈。 |
| D07 | 删除 API 准确表达平台是否已删除 | 启用平台停用持久化后第一次同步失败时，不返回删除成功；软删除后同步失败时，明确已删除但运行时尚未同步；完整成功、持久化失败、存在活动媒体会话均有匹配结果，且页面与 API 一致。 |
| D08 | 实时流在源流或发送器消失后回收会话与租约 | 覆盖 UDP 开启/关闭 RTCP、TCP 主动/被动发送；确认媒体终止后收尾上级会话并释放所持资源；暂时查询错误不能直接等同媒体终止；停止发送失败不得提前释放仍被占用的源流；不影响同源其他消费者或其他上级。 |
| D09 | 心跳故障进入可恢复的注册生命周期 | 按约定的连续超时次数判离线（2022 默认 3 次），随后恢复注册，不必等待原续期；明确拒绝与瞬时失败分别处理；恢复成功、注册失败重试、维护事务重叠及停用均有确定行为；错误状态与持久化一致；不存在忙循环、并发注册或旧定时任务造成的重复维护。 |
| D10 | auto 根据注册响应发现版本并应用有效版本 | 覆盖 `X-GB-Ver` 的受支持版本、缺失、无效及未知值，以及摘要挑战后的最终响应；有效版本影响后续实际报文和持久化状态，重启后保持一致；固定 2016/2022 不被 auto 逻辑意外覆盖；能力声明与实际使用版本不矛盾。 |
| D11 | 已发布物理设备节点可查询其共享通道 | 查询当前上级可见设备时返回属于该设备的已共享子通道，保持请求 SN、总数和分批一致；未发布设备、其他设备和其他上级的资源不可泄露；无子通道和业务目录并存均有明确结果。 |
| D12 | 已发布业务组/虚拟组织可通过实际 Catalog 入口查询 | 兼容 To 为本平台且 XML 指定节点，以及 To 直接指向当前上级已发布业务节点的请求；未发布、未知、跨上级节点拒绝；To、Request-URI 与 XML 目标发生冲突时不得扩大查询权限；不将全部直寻址方式表述为强制标准要求。 |
| D13 | 上级域名配置前后端一致并保持可信来源边界 | 有效域名可配置并匹配其合法解析地址；IP、IPv6、多个解析结果、解析失败及地址变化有确定行为；From 身份、端口、传输协议及共享范围仍必须满足校验；不恢复仅凭身份字段放行的回退；覆盖目录、信息、PTZ、INVITE 和录像入口及已建会话来源绑定。 |
| D14 | 按媒体源标识处理同源重新请求 | 使用发送者 ID 与发送方媒体流序列号区分媒体源；符合替换条件的新 INVITE 先安全释放旧链路再建立新链路；同一 SIP 事务重传不触发重复替换；不同上级、不同媒体源和其他消费者互不误停；旧链路停止失败、同时重建和容量限制不造成错误释放或资源泄漏。 |
| D15 | 已有回放链路支持完整的指定范围控制与可信响应 | 覆盖 npt、smpte、指定终点 Range、暂停/继续及既有正向倍速；合法请求贯通到下接设备并产生相应控制结果，指定终点具有实际约束；PLAY 响应提供与上行媒体对应的 RTP-Info，其中 seq/rtptime 保持标准“宜携带”的强度，携带时必须是真实值；非法时间、越界、设备失败及会话权限变化不被误报成功；保持现有回放隔离。 |
| D16 | 注册有效期符合实际选用版本 | 固定 2016 或 2022 的配置与实际 REGISTER 都不使用小于 3600 秒的正注册期限，注销的 0 秒另行处理；覆盖 3599/3600 秒边界、auto 首次注册与协商后切换、存量短周期配置及前后端一致性；本地请求期限与上级实际授予期限分别处理。 |

## 验证方式

- 在任务阶段为每项定义输入、预期结果与可执行测试，再先复现失败、实现修复并验证通过。测试结果直接回填任务清单，不另外创建测试或验收文档。
- D06/D07 覆盖页面操作调用与管理 API 的真实响应契约；前端测试通过不替代后端持久化结果验证。
- D09/D10/D16 覆盖注册响应、运行时调度、后续报文与持久化边界；维护时序使用可控时钟和受控事务，关键并发路径执行竞态检查。
- D11/D12/D13 覆盖实际 SIP 入口与共享投影，既验证合法请求可达，也验证非可信来源和越权请求不能调用资源。
- D08/D14/D15 覆盖会话、源流、发送器及下接控制，不能只用解析测试或单个辅助函数测试代替完整调用链证据。
- 本轮使用本地代码、模拟上级/设备和隔离测试数据；不操作浏览器，不修改当前开发环境已有级联台账，不部署。
- 自动化测试只证明已覆盖的代码行为；真实上级互操作、设备动作及 RTP/PS 媒体包验收另行列明，不提前宣称通过。

## 非目标

不将 M01–M13 纳入本轮；不新增录像来源、订阅、报警、语音或升级业务；不批量修改存量共享权限；不自动修改宿主机时钟。倒放属于另行确认的推荐能力，不借 D15 扩大范围。

不覆盖、清理、提交、推送或部署工作区其他任务的改动。P1 相关代码若位于本轮调用链中，需保持相应安全与调度约束，但不把前轮完成声明当作本轮验证证据。

## 技术方案阶段必须明确的问题

- D07：定义未删除、已停用、已删除及运行时未同步的结果契约，再决定操作顺序，避免页面与 API 各自猜测。
- D09：核对正式标准的心跳失败判定与重试约束，明确恢复条件和等待时长；工程退避与定时任务管理单独说明。
- D10/D16：明确 auto 对外声明的能力、无版本响应的兼容策略、版本持久化及运行时切换顺序，以及存量短周期配置的处理。
- D13：明确域名解析与地址更新的信任边界和失败策略，禁止为兼容域名降低到 identity-only 匹配。
- D14：回看正式 PDF 附录 K/L，保留附录 K 在目录与正文中属性标注冲突的解释边界；明确替换范围及多消费者隔离。
- D15：回看正式 PDF 附录 B，明确 smpte 时间基准、终点控制与 RTP-Info 的实际数据来源；当前回放接口仅暴露起点和倍速，不能在只有字段解析的情况下标记完成。

## 标准原文核对依据

2026-10-16 对照本地正式 PDF `国标文档/GBT+28181-2022.pdf` 渲染页核对，以下为印刷页与 PDF 阅读页对应关系；原始文本提取有乱码，因此不以提取文本代替页面判断。

| 关联项 | 原文位置 | 核对结果 |
|---|---|---|
| D09/D16 | 9.1.1，印刷页 16 / PDF 页 23 | 注册失败一般重试间隔不应短于 60 秒；注册默认 86400 秒，过期时间不应短于 3600 秒；注销 0 秒见 9.1.2.2，印刷页 17 / PDF 页 24。 |
| D16 兼容边界 | GB/T 28181-2016 9.1.1 续页，印刷页 16 / PDF 页 21 | 2016 版同样要求注册过期时间不应短于 3600 秒、缺省 86400 秒；2016 与 2022 在此最低值上没有兼容豁免。 |
| D09 | 9.6.1 d/e，印刷页 30 / PDF 页 37 | 双方需统一心跳间隔和连续超时次数，默认分别为 60 秒、3 次；发送方连续检测不到响应达到配置次数后认为接收方离线。明确 SIP 拒绝后的恢复策略需另外说明，不能把它和超时规则混为一谈。 |
| D10 | 附录 I，印刷页 138 / PDF 页 145 | 注册及成功或失败响应携带 X-GB-Ver；2.0 为 2016，3.0 为 2022；后续交互时高版本方应避免发送对方不能识别的消息。 |
| D08/D14 | 附录 K，印刷页 143 / PDF 页 150；9.2.1 d，印刷页 18 / PDF 页 25 | 原文包含媒体丢失监测、BYE 收尾及同媒体源释放旧链路后重建；正文实时点播基本要求也引用附录 K。目录 PDF 页 4 标资料性而附录正文标规范性，保留该冲突。 |
| D14 | 附录 L，印刷页 144 / PDF 页 151 | 媒体源标识包含发送者 ID 与发送方媒体流序列号；发送方序列号为不超过 20 位的字符串，实时首位为 0、历史首位为 1；同源请求与域内多接收端分发需分别处理。 |
| D15 | B.2.1，印刷页 106–107 / PDF 页 113–114 | 应支持 npt/smpte 相对时间范围，PLAY 响应给出 RTP-Info；seq/rtptime 是“宜携带”。示例解释它们对应定位后第一个 RTP 包；不能使用模拟值，也不能未经验证把下接设备的值冒充重新发流后的上行值。 |
