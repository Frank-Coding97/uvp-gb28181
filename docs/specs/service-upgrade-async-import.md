# 目标

离线升级包的上传和签名校验必须脱离浏览器请求生命周期。上传请求完成后，浏览器可以关闭、刷新或断网，升级助手仍继续处理已完整写入的文件；页面重新打开时可以通过同一个标识查询真实结果。

# HTTP 契约

保留现有入口 `POST /api/system/upgrade/import`，避免已发布前端和权限记录失效。请求仍为 `multipart/form-data`，字段名为 `file`，一次只允许一个升级包。接口只负责把完整文件安全写入助手收件目录并受理后台校验，不在请求内等待解包、签名和 SHA-256 校验完成。

成功受理返回 `202`，响应数据至少包含：

```json
{
  "job_id": "<opaque id>",
  "upload_id": "<opaque id>",
  "phase": "queued"
}
```

`job_id` 是页面轮询的稳定标识；`upload_id` 作为兼容字段保留，不能暴露收件目录、暂存目录或任意本机路径。若实现只生成一个标识，两个字段返回相同值即可。受理成功只表示文件已经完整落盘并交给助手，不能返回已校验的版本、摘要或可应用状态。

使用 `GET /api/system/upgrade/import/:id` 查询导入任务。`:id` 只能是服务端生成的 opaque 标识，服务端不得把它拼接成客户端可控路径。响应状态至少覆盖：

| status | 含义 | 可创建升级任务 |
| --- | --- | --- |
| `queued` | 已落盘，等待助手处理 | 否 |
| `verifying` | 助手正在解包、验签或计算摘要 | 否 |
| `succeeded` | 校验通过并已写入助手暂存区 | 是 |
| `failed` | 上传、校验或暂存失败 | 否 |

`succeeded` 状态才可以携带版本、build_id、release_id、size、sha256、deployment、os、arch 和更新说明；其他状态不得伪造这些字段。HTTP 可以额外提供 `status` 兼容字段，但必须与 `phase` 表达同一状态。成功结果可放在 `staged`、`artifact` 或 `result` 之一，浏览器只在 `succeeded` 后接受。禁止向浏览器返回内部 `path`、`inbox_token`、密钥、完整路径或 multipart 正文。`failed` 必须包含可展示的脱敏原因。

# 助手 RPC 约束

业务进程到助手的 RPC 只能传递受校验的 `inbox_token` 和异步任务标识，不能传递本机路径、shell 命令、systemd unit、Compose YAML 或上传正文。任务和导入状态由助手持久化；业务 HTTP 请求断开不会取消后台校验。

重复查询同一个标识必须返回同一条持久记录。助手重启后，`queued`/`verifying` 任务应恢复或明确转为 `failed`，不能丢失，也不能把未完成文件标记为 `succeeded`。已完整落盘的文件在校验失败时必须清理收件临时文件；失败不能创建可应用暂存制品，也不能影响当前运行版本。

半包、读取中断、超过上传上限和重复 `file` 字段都必须返回错误并清理临时文件；半包不得进入后台校验。上传失败后首版允许重新上传，不承诺断点续传。

# 契约验收用例

| 输入/动作 | 期望 |
| --- | --- |
| 完整上传后立即关闭页面，随后按返回的 ID 查询 | 后台继续校验；重复查询返回同一任务，从 `queued`/`verifying` 到 `succeeded` 或 `failed`。 |
| 助手在 `queued` 或 `verifying` 时重启 | 启动恢复继续校验，或明确记录 `failed`；不能遗失任务或返回成功。 |
| 上传流中断、超限或包含两个 `file` 字段 | 请求失败，不产生可查询的已受理任务，收件目录无半包。 |
| 完整文件签名无效或摘要不匹配 | 任务为 `failed`，有脱敏原因；收件临时文件已清理，没有可应用暂存结果。 |
| 查询未知、格式错误或路径样式 ID | 返回明确 4xx/404，不访问 ID 指定的本机文件，不泄露其他任务。 |
| 客户端收到 HTTP 202 | 只展示排队/处理中；只有成功终态才能展示版本并允许创建升级任务。 |
| 旧同步客户端读取 202 | 不得将响应误认作含 `StagedArtifact` 的 HTTP 200 成功；失败兼容行为明确且不创建升级任务。 |

# 兼容与安全边界

现有同步导入调用方不能把 `202` 当作“升级包已校验”。前端必须根据导入任务状态轮询，只有 `succeeded` 才展示目标版本并允许创建升级任务。`POST /api/system/upgrade/tasks` 仍以助手返回的可信摘要为准，不能信任浏览器提交的版本、路径或状态。

导入任务状态查询是短请求，普通 API 的全局超时保持不变；只有文件上传路径使用专用大小和读取限制。Nginx、后端和助手的限制必须一致，避免通过放大全局请求超时掩盖未完成上传。
