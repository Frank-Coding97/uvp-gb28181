## 目标与用户故事

作为上级平台，我需要通过 DeviceStatus 查询本级平台及当前向我实际发布的通道，收到保留请求 SN 和发布编码的业务应答。

## 验收标准

- 仅启用的可信上级可查询；To、Request-URI 仅允许本平台容器或本次 XML 目标，禁止查询其他上级或未共享资源。
- 本平台 ONLINE/OK 仅表示本进程可接收和处理本次查询，不代表媒体节点或全部下接设备健康；设备状态来自本次下接 DeviceStatus 查询结果，不由 Catalog、注册状态或旧缓存推断。
- SIP 200 仅确认收到请求，设备失败或事实缺失返回明确业务失败；缺失的可选事实不伪造。
- 响应使用上级的 2016/2022 协议配置、原 SN 和发布编码，不泄露源设备、报警及网络标识。
- 等待设备期间发生停用或配置/投影版本变化时停止结果发送。

## 非目标与未决问题

本任务遵循当前 Catalog 发布模型：物理设备投影隐藏，仅查询本平台及实际发布通道；行政区划和业务节点不作为状态查询目标。本任务不新增报警共享模型、订阅、下载、控制扩展或数据库迁移。报警列表没有可靠发布映射时省略，不将本任务视为报警级联完成。真实上级和设备验收单列。

## 执行授权

老板已要求“开始做尚未贯通的级联功能”，并授权“无人值守”“继续推进”；按此授权持续执行规格、方案、测试与实现，不重复请求阶段确认。只操作本地代码和隔离测试，不操作浏览器、开发级联台账、设备或部署环境。
