# 服务升级 SQLite 备份路径缺失修复

状态：老板已明确授权“直接修”；源码、本地回归及 220:51001 助手更新完成，完整业务升级由老板继续验收。

## 目标

使用 SQLite 的安装实例能够正常完成升级前备份；缺少备份条件时在中断业务之前明确拒绝升级。用户无需额外填写默认安装已知的数据库路径。

## 用户故事

- 管理员使用现有配置安装、启动并升级时，助手备份实际业务使用的数据库。
- 管理员调整 SQLite 数据文件位置后，升级仍使用配置指向的数据库，不误备份默认路径或新建空数据库。
- 数据库备份条件不满足时，管理员能看到原因，当前业务继续运行。
- 已失败并验证回退的升级保持原有历史记录，不伪造成功，也不自动重新应用。

## 验收标准

1. 默认相对路径和自定义绝对路径均对应实际业务数据库；不依赖执行升级命令时的工作目录。
2. 绿色包和使用相同配置注册流程的 systemd 安装均无需手工补填默认数据库路径；Docker 显式宿主路径的现有行为不被覆盖。
3. SQLite 路径缺失、文件不存在或目标不是普通文件时，在停止服务及执行迁移前失败。
4. 配置使用外置数据库时保持现有备份和凭据规则，不误用 SQLite 备份。
5. 对存在 WAL 的数据库继续使用一致性快照；保留备份校验及回退验证，不通过跳过数据库备份放行。
6. 220:51001 当前实例的路径登记及助手状态验证分别记录；不影响 52000 实例，不代老板应用升级。
7. 回归分别覆盖路径解析、实际注册文件内容、停服前拒绝和已有快照/回退行为。本地测试、远端配置验证和完整升级验收分开报告。

## 非目标

- 不更改业务数据库内容，不关闭备份保护，不修改失败任务历史。
- 不自动再次执行真实升级，不将当前旧版本标记为升级成功。
- 不调整此次无关的国标级联、权限、页面布局或发布站点功能。
