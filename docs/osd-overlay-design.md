# 图像叠加 OSD 操作方式重设计

## 0. 本文件的位置与边界

用户口径：**「播放控制台的图像叠加操作方式，对普通用户不太友好，整体重新设计一下」**。

本文件只回答这一个问题：**用户想「在画面上加几个字」时，平台上应该怎么操作**。

- **不改协议**：不新增 `ConfigType`、不动 `blocks` 键名、不动 `deviceConfigPayload.ts` 的翻译口径。
- **不改后端**：`manscdp/device_config_osd.go` 的收发/校验/对账全部保持。
- **不重议遮挡与镜像**：`picture` 组的交互已在 `picture-settings-design.md` 定稿并落地，本文件把它当**母版**复用（§1），不改它的任何结论。
- 顺带发现的**跨模块**问题（页签结构、状态词表、底栏定高）单列在 §9，**不并入**本文结论。

---

## 1. 一句话主张

> **图像叠加是「在画面上摆几行字」，不是「填一张坐标表」。**

现状把它做成了后者：一个 9 项的配置表单 + 手算像素坐标。而**同一屏、同一个坐标系**的遮挡，已经做到了「点新建 → 在画面上拖一下」。同族配置两种操作方式，是这次要抹平的落差。

---

## 2. 用户任务

| 任务 | 触发场景 | 用户期望 |
| --- | --- | --- |
| **让画面带上时间** | 取证 / 追责：录像回放时对得上时间 | 打开就有，格式看得懂，位置别挡主线 |
| **让画面带上点位名** | 多路画面分不清 / 上级平台看这路流 | 写上「北门」「3 号车间」，放在空白处 |
| **调位置** | 字挡住了重要区域 / 想换个角 | 拖一下就到位 |

三件事的共同点：**都在描述「画面上的什么地方出现什么字」**。所以操作应当发生在画面上（与母版 §1 同构）。

---

## 3. 现状诊断（用户视角，逐条给证据）

### P0-1 位置只能盲输，画面上一个标记都没有

- 时间戳位置 = `timeX` / `timeY` 两个滑杆（`web/src/views/gb28181/device-mgmt/deviceConfigGroups.ts:278-279`，范围 0~3840 / 0~2160）
- 每条文字各自一对 X / Y **手输框**（`device-mgmt/DeviceConfigTextItems.vue:82-105`）
- 画布上的叠加层**只画遮挡**（`components/PlayConsoleLinked.vue:3930` 的 `maskOverlayBoxes` 数据源是 `pictureRegions`，:4790 的 `mask-overlay-layer` 同理），**OSD 一条都不画**

后果：用户要把「我想放右上角」在心算成 `(1740, 60)`，还得先去别处查坐标基准是多少。**这是普通用户第一眼就会卡住的地方。**

> ⛔ 对照：遮挡同样用绝对像素坐标，但已经画布化（`PlayConsoleLinked.vue:3997` `startMaskDraw` → `:4052` `finishMaskDraw`）。**OSD 是本页签唯一还在盲输坐标的东西。**

### P0-2 「窗口长度 / 窗口宽度」是**伪可编辑字段**——点了没用

| | 现实 |
| --- | --- |
| 界面 | 两个滑杆，可编辑，默认 `1920` / `1080`（`deviceConfigGroups.ts:261-277`、`:438-439`） |
| 设备 | **拒收平台改写**——写 `2560×1440` 或 `720×576` 都回 200 OK，但回读仍是 `704×576`（`device-mgmt/DeviceConfigDrawer.vue:1065` 注释里的真机实测） |

而且这两个字段**根本不是 OSD 自己的属性**——它们是「设备那把图像尺」，也就是**遮挡坐标的基准**（`DeviceConfigDrawer.vue:1070` 的 `pictureCanvasSize` 就是从 OSD 组的 `length/width` 读出来的）。

三层后果：

1. 用户改了 → 下发 200 → 回读没变 → **归因成本极高**（本仓最贵的一类故障）。
2. 字面「窗口长度」会被理解成「文字框多宽」或「字号」→ 改成 `200×50` 下发 → 设备仍按 `704` 的尺解读 → 结果不可预测。
3. 一个功能共享的事实，被做成了**另一个功能的表单初值**——遮挡拿它当基准，OSD 拿它当可编辑项。

### P0-3 「不指定（不下发该元素）」把协议语义当成了选项文案

`deviceConfigGroups.ts:186`：

```ts
{ value: "", label: "不指定（不下发该元素）" }
```

- 普通用户的任务是「时间要什么格式」，不是「要不要下发这个元素」。
- ⚠️ 但**不能删**：这个态有独立语义 —— `TimeType` 是 `OSDConfigBlock` 里唯一保留指针的取值字段，`nil` = 设备不指定格式，与「给一个 0」是两件事（`server/app/gb28181/manscdp/device_config_osd.go:53-56`）。
- ⇒ 只能**换说法**，不能去能力。

### P1-1 时间格式是模式串，看不见结果

`deviceConfigGroups.ts:187-188` 的两个 label 是 `YYYY-MM-DD HH:MM:SS` / `YYYY年MM月DD日HH:MM:SS` —— 用户要自己想象渲染出来长什么样。而且只有 2 个选项（协议只定义 0/1），用户会去找「能不能去掉秒」「能不能 24 小时制」，那些不在标准里。

### P1-2 一个「时间戳」被拆到四处

`deviceConfigGroups.ts:252-279` 的字段顺序：

```
① 时间显示（开关）
② 时间格式（下拉）
③ 窗口长度（滑杆）   ← 与时间戳无关，但夹在中间
④ 窗口宽度（滑杆）   ← 同上
⑤ 时间 X（滑杆）
⑥ 时间 Y（滑杆）
⑦ 文字显示（开关）
⑧ 叠加文字（列表）
```

用户心智里的对象是「时间戳」，界面上是 4 个**互不相邻**的字段（①②⑤⑥），中间隔着两个与它无关的画布尺寸。

### P1-3 8 条文字 = 维护一个数组

`DeviceConfigTextItems.vue` 是「文字 / X / Y / 删除」的三列 grid。用户的任务是「加一行字」，界面要求的是「维护一个 ≤8 条的列表，并给每行配一对坐标」（上限见 `deviceConfigGroups.ts:226-229`）。

### P1-4 改了在画面上看不出来

遮挡有草稿态标记（`PlayConsoleLinked.vue:4795-4805` 的 `is-draft` + 角标「#2 待下发」）；**OSD 改了只在侧栏 footer 显示「N 项未下发」**（`DeviceConfigDrawer.vue:2088-2100`）。

这违反母版的主力机制 M2 —— **草稿与事实长得不一样，且差别要出现在动作发生的地方**。而 OSD 的动作（定位）恰恰发生在画布上。

### P2-1 坐标系文案与实际基准不一致

`DeviceConfigTextItems.vue:128` 写：

> 坐标为像素，原点在播放窗口左上角

- 标准原文确实是「相对播放窗口左上角」（`device_config_osd.go:21`）；
- 但真机实测的基准是**设备声明的图像尺寸**（`704×576`），而「播放窗口」在显示尺寸 ≠ 声明尺寸时不是一回事（`DeviceConfigDrawer.vue:1055-1068`）。
- 遮挡侧已经统一到「设备声明的坐标画布 · 704×576」这个说法（`PlayConsoleLinked.vue:3912` `pictureCoordinateText`），**OSD 侧还是旧文案** ⇒ 同屏两套说法。

## 4. 设计语言（不新造，全部沿用母版）

| 母版机制（`play-console-ux-architecture.md` §1 / §3） | OSD 上怎么落 |
| --- | --- |
| **M1 / R1** 动作在画面、管理在面板 | 拖动定位、加一行字、删除 → **画布**；开关、格式、列表、精确数值、读取 / 下发 → **面板** |
| **M2 / R2** 草稿与事实长得不一样，差别出现在动作发生的地方 | 已生效 = 实线锚点；未下发 = **虚线 + 琥珀 + 角标「待下发」**；未定位 = 琥珀虚线 + 「未定位」 |
| **M3 / R3** 确认就近、有变更才出现、不静默消失 | 复用画布底部那条浮条（`PlayConsoleLinked.vue:4830` `picture-draft-bar`），文案扩到 OSD |
| **M4 / R4** 数值是二级表示；没有事实不给编辑；状态词不新造 | 像素坐标折叠进「精确数值 ▾」；沿用 `groupFactsMissing` 闸门（`DeviceConfigDrawer.vue:1036`）；沿用事实 / 草稿 / 结果三层词表 |

## 5. 关键决策：预览层长什么样

这是本设计唯一需要先拍形态、再谈细节的地方。三条路：

| 形态 | 做法 | 评价 |
| --- | --- | --- |
| **A 仿文字预览** | 在画布上画出看起来像 OSD 的文字 | ⛔ **伪造了不存在的能力。** 标准 `OSDCfgType`（A.2.1.12）9 个字段里**没有字体、字号、颜色、对齐** —— 用户看到像真的字，立刻会问「字号能不能调」。<br>⛔ 更麻烦：设备**已经烧进码流**的时间戳在播放器画面里本来就看得见，再叠一个假字 = 画面上**两个时间戳**，是最难解释的一类假象。 |
| **B 锚点 + 内容标签**（推荐） | 画布上一个锚点，标签直接写内容：「时间戳」「① 北门」。拖动 = 改坐标 | ✅ 不伪造任何东西，天然把「这里只管位置和内容」传达出去。<br>✅ 不和真实 OSD 打架（锚点用引线偏到坐标点右上 8px，不压住第一个字）。<br>✅ 与遮挡框选层**同一套坐标换算**，基础设施零新增。<br>⭐ **意外的好收益**：设备已烧的时间戳就在画面上，用户可以直接**对着那个真字拖锚点对齐** —— 免费的精确校准，A 方案做不到（假字会盖住真字）。 |
| **C 取景框** | 画一个与 `TimeX/TimeY` 对齐的空框 | 介于两者之间，但框有大小 ⇒ 仍然暗示了一个设备并不保证的尺寸。 |

**取 B。** 依据是本仓自己反复验证过的一条立场（`deviceConfigGroups.ts:5-7`）：

> 照搬只会做出一堆点不动的假界面。

形态 B 就是「不做假界面」在预览层的对应做法。

### 5.1 必须写进文案的诚实边界

> **平台无法预览 OSD 的真实样子。**

标量只定义「位置 + 内容 + 开关」，字体字号由设备自己决定 ⇒ 锚点标签只能说「字大致出现在这里 / 标记点就是下发的坐标」，**不能**说「这就是效果」。这条要出现在锚点的 `title` 与首次引导文案里。

## 6. 交互详设

### 6.1 落点：OSD **留在侧栏**，但两侧职责重新划分

| 区域 | 职责 |
| --- | --- |
| **侧栏（属性栏）** | 管理面：两个对象块（时间戳 / 叠加文字）+ 只读坐标基准 + 读取 / 还原 / 下发 |
| **画布** | 操作面：新增锚点层 `osd-overlay-layer`；锚点**默认只读**，点右上角「调整位置」进编辑模式后才可拖（§6.5） |
| 底栏 | **本次不动**（遮挡卡 + 镜像卡保持原样） |

**为什么不搬到底栏当第三张卡**：底栏是定高 148px 的卡片容器，塞不下「8 条文字的列表 + 每行坐标摘要」；且 `picture-settings-design.md` §9-5 已定「OSD 留侧栏」。本设计**不与那个决定冲突**。

**并且本形态对将来两种走向都成立**：若 `play-console-ux-architecture.md` §7-Q2 决定把画面组归位属性栏，则 OSD 与 picture 会成为属性栏的 `osd` / `picture` 两个组，下面这套「对象块」结构可以直接当那两组的渲染形态。

### 6.2 对象块一：时间戳

```
┌ 时间戳 ───────────────────────────────── [开关] ┐
│ 格式   [ 2026年09月20日11:49:18            ▾ ]  │  ← 下拉框，样例 = 当前时刻的实例
│ 位置   [调整位置]  1740, 60          精确数值 ▾ │  ← 编辑模式开关就在这一行
└────────────────────────────────────────────────┘
```

⭐ 版式统一成**标签列 + 控件列**两栏（标签列 26px 定宽），三块面板共用同一套骨架，
扫一眼能顺着标签列找到东西（对应 §3 P1-2「一个时间戳被拆到四处」）。

- **格式样例化**：三个选项渲染成**当前时刻的实例**，不是模式串。
  - ⛔ 每秒刷新只更新这几个 option 的文本节点，**不要**用同一个定时器驱动整个面板重渲染。
  - ⭐ **三选一的枚举用下拉框，不是三条竖排单选**（2026-09-20 第二版）：单选摊开占掉
    半块面板的高度，而这里要腾地方给后面合并进来的视频编码（见 §12.4）。
- ⭐ **「调整位置 / 完成调整」按钮在这一行的坐标读数旁边**（2026-09-20 第二版）：
  它改的就是这一行的坐标 —— 按钮、读数、结果三者同一条视线（完整演进见 §6.5）。
- **「不指定」改文案为「跟设备走（不发格式）」**，解释放 `title`：「不发送格式字段，由设备用它自己的默认格式」。—— 语义一字未改，只是说成人话（对应 §3 P0-3）。
- **开关关掉时**：格式与位置行**灰显但仍可读**，并在块标题右侧标「已关闭，画面不显示」。
  - ⛔ 不要隐藏：标准里 `TimeEnable=0` 时 `TimeX/TimeY/TimeType` **照样在报文里**（`deviceConfigPayload.ts:344-355` 一律带全），配置是"还在、只是不显示"。隐藏会让用户以为配置丢了。

### 6.3 对象块二：叠加文字

```
┌ 叠加文字 ─────────────────── 2/8      [开关] ┐
│ ① [北门              ] 2/32   定位   ✕     │
│ ② [3 号车间          ] 5/32   定位   ✕     │
│ + 加一行字                                   │
└──────────────────────────────────────────────┘
```

- 每行 = 编号圆点（**与画布锚点编号同源**）+ 就地可编辑的文字 + 字符计数 + 定位入口 + 删除。
- ⭐ 定位入口的文案压到两个字「定位」（2026-09-20 第二版）：侧栏本来就窄，
  「在画面上定位」六个字把输入框挤到看不见内容；动作本身有 `title` 说全。
- **「在画面上加一行字」**：点一下 → 列表新增一行 + 画布上出现一个锚点 + 焦点落在文字输入框。
  - ⛔ **坐标不预填**（沿用 `DeviceConfigTextItems.vue:9-10` 的既有决定：预填会让人以为"平台帮我对齐了"）。
  - 新增行进入**「未定位」态**（琥珀虚线锚点 + 标签「未定位」），拖一下就落地 —— 这样 0,0 不会被误认为"平台帮我放在左上角了"。
  - ⛔ 未定位的行**不允许下发**（`buildOSD` 里 X/Y 为 0 是合法值，平台没法从值上判"用户没摆" ⇒ 判据必须是**草稿里的定位状态**，不是坐标值）。这一条要在实现时显式记一个字段，别用坐标反推。
- 字符计数 `12/32` 就地显示（上限见 `deviceConfigGroups.ts:229`：**32 个字符**，中文按 1 个算）。
  - 现状只有 `buildOSD` 拒发时给一句「第 N 条叠加文字超过 32 个字符」（`deviceConfigPayload.ts:334-335`）——用户得回去找是哪条。改成输入时就地提示。

### 6.4 坐标基准块（只读事实）

```
画布    704 × 576   [只读]
```

⭐ 2026-09-20 第二版从"带边框的事实块"改成**同一套标签列骨架下的一行**（上边一条细分割线）：
它是一行事实，不是一块面板 —— 省下的高度留给后面要合并进来的视频编码（§12.4）。

- 数据源：回读的 `OSDConfig.Length/Width`，即已有的 `pictureCanvasSize`（`DeviceConfigDrawer.vue:1070`，已过 `groupFactsMissing('osd')` 闸门）。
- **没读到就不出现**（不显示 `1920×1080` 模板值 —— 那是平台初值、不是设备值）。
- 退回到解码尺寸时按 `.is-unverified` 琥珀态标注（复用 `maskCanvasNote` 的既有处理，`PlayConsoleLinked.vue:3873` `maskCanvasFromDevice`）。
- ⛔ **删掉那两个可编辑滑杆**（对应 §3 P0-2）。

**删掉可编辑控件会不会导致发不出去？** 分三条路核对过：

| 情况 | 结果 |
| --- | --- |
| 有回读事实 | 用回读值下发，正常 |
| 无回读事实（`never_read` / `type_absent`） | 整组本来就禁编辑（`familyFieldsDisabled`，`DeviceConfigDrawer.vue:904`），字段显示「—」，走不到下发 |
| **设备回了 `OSDConfig` 但没带 `Length/Width`**（违约报文） | `pictureCanvasSize` 返回 `null` ⇒ 下发时 `requiredInt` 拒发（`deviceConfigPayload.ts:309`） |

⚠️ **第三行是本次改造必须一并处理的**：拒发文案现在是「OSD 窗口长度必须是 1~3840 的整数」（`deviceConfigPayload.ts:310`），而改造后界面上**已经不存在这个控件** —— 用户会看到一条**指向不存在控件的错误**。文案要改成「设备未声明坐标画布（`Length/Width`），无法下发本组配置；请点「读取」重新查询设备」。

### 6.5 画布层：`osd-overlay-layer`

与 `mask-overlay-layer`（`PlayConsoleLinked.vue:4790`）**并列**的一层，复用同一套坐标换算：

```
left  = X / Length * 100%
top   = Y / Width  * 100%
```

（基准统一取 `maskCanvasSize`，`PlayConsoleLinked.vue:3871` —— OSD 与遮挡本来就用同一把尺，不新造第二个基准。）

**⛔⛔ 只读态：这一层整个不存在（2026-09-20 第二版，最终形态）**

本文档第一版写的是"锚点常驻、只读态降噪"，第二版改成"锚点常驻但按钮搬出画面"——
两版都被老板否掉了：

> "这个为啥还是默认显示呢，不是说的点击调整位置之后才出现这个『时间戳』标签吗，并且现在这个 OSD 过于混乱"

**锚点层的定位是「正在摆位置」这件事的操作面**，不是"位置信息的载体"——
位置信息由侧栏的 `X 1740 · Y 60` 承担，画面上再摊四五个带引线的标签就是纯噪声，
而屏幕上的每一寸都在放视频。⇒ 只读态 `v-if="osdEditMode"` 不渲染，一个标记都不画。

**编辑模式内的三种状态**（此时品牌蓝是**对的**信号：可拖、是操作目标）：

| 状态 | 视觉 |
| --- | --- |
| 已生效（设备事实） | 品牌蓝实心锚点 + 蓝底标签 |
| **待下发**（本次改过） | **虚线 + 琥珀 + 角标「待下发」** |
| **未定位**（新增未摆） | 琥珀虚线 + 标签「未定位」 |
| 所属开关已关闭 | **淡显**（非隐藏）+ 标签后缀「已关闭」 |

⛔ 「开关关闭 → 隐藏锚点」是**错的**：与遮挡侧「设备已停用但保留区域」同构（`device-config-center.md`「展示语义」段）—— 隐藏会让用户以为配置丢了，而它下次启用会一起活过来。

⛔ 上一版那组 `.osd-overlay-layer:not(.is-editing)`（"只读态用中性玻璃"）**已删**：
锚点已经不在了，留下一组永远匹配不到的选择器只会让下一个人以为还存在第二种锚点外观。

**交互细节**：

- 锚点层 `pointer-events: none`；**锚点本体只在编辑模式下存在，所以它可以一直是 `auto`**（见下一条）。
- ⭐ **拖动是显式动作：先点「调整位置」进编辑模式**（2026-09-20 拍板，本文档最初写的是"随时可拖"）。
  - ⛔ 锚点层盖着的就是播放器：随时可拖的话，用户"想点一下画面"（暂停 / 双击全屏 / 起手拉框变焦）就会顺手把某行字挪走。
    而平台上**看不到真字**（真实效果由设备渲染），这类误操作在画面上完全看不出来，只会等到下发后设备上真的换了位置才被发现。
  - 退出：再点「完成调整」/ `Esc` / 换页签 / 换通道，四者都收干净（含拖到一半的临时坐标）。
  - ⛔⛔ **按钮的最终落点是侧栏「时间戳」面板的「位置」行**（2026-09-20 三次调整）：
    ① 画面右上角 → 老板："会遮挡画面"；② 画面下方工具条（`.switcher-osd`）→ 仍在画面附近、视线要在画面和侧栏之间来回跳；
    ③ **归位到它控制的那一行坐标旁边**。判据很硬：这个按钮**改的就是这一行的坐标**，
    按钮、读数、结果三者同一条视线 —— 而它是常驻按钮，任何画面内的位置都等于永久占掉一块视频。
    - 实现：`DeviceConfigOsdBlocks.vue` 的 `.osd-adjust`；状态由**画面侧持有**
      （`PlayConsoleLinked` 的 `osdEditMode`），抽屉只读它（`:osd-editing`）并发"我要切一下"的意图
      （`@toggle-osd-edit`）—— 画布自己的退出路径（Esc / 换页签 / 换通道）也要能收干净，
      状态存两份必然搞岔。
    - ⛔ **没有画布的宿主不渲染这个按钮**（`:osd-canvas-linked` 默认 `false`，如设备详情里那种
      用法）：那种场景下它点下去什么都不会发生。此时**精确数值默认展开**，
      否则用户连改坐标的入口都没有。
    - ⛔ 与遮挡框选**双向互斥**：框选期间点它 → 取消本次框选并进编辑模式；
      `startMaskDraw()` 里也 `exitOsdEditMode()`。两个覆盖层都吃 `pointerdown`，同时开着说不清拖的是什么。
  - ⭐ 侧栏每行的「定位」**本身就是显式意图**，点它直接进编辑模式 + 那枚锚点闪一下 —— 否则会出现"点了按钮、标闪了一下、却拖不动"。
- 拖动：`pointerdown` → 本地临时值实时渲染（显示 `X 1740 · Y 60`）→ `pointerup` 才写草稿。
  - ⛔ 别在 `pointermove` 里写草稿：脏值统计会在拖动过程中反复抖动。
- ⛔ **与遮挡框选互斥，双向都要管**：`maskDrawMode` 为真时 OSD 锚点不可拖；进 OSD 编辑模式时也要把框选关掉
  （两个覆盖层会抢 `pointerdown`，同时开着的结果是同一个按下动作"既可能画框、也可能挪字"，用户没法预期）。
- 锚点用引线把标签偏到坐标点**右上 8px**，避免压住设备真实 OSD 的第一个字（§5 形态 B 的那条收益要靠这个成立）。
- 与 §8 落地序的关系：原本第 4 步「先只读展示」+ 第 5 步「锚点可拖」是**两个发布阶段**，
  现在合成**同一版里的两个模式**（默认不画，点按钮才画且可拖）—— 两个阶段的需求都在，不必分两次交付。

## 7. 状态与错误（沿用词表，不新造）

| 界面状态 | 后端 `reconcile` | 表现 |
| --- | --- | --- |
| 尚未读取设备值 | `never_read` | 灰点；无控件只显示「—」；明说「点『读取』向设备查询」 |
| 正在读取 | `pending` | 灰点 + 进度；字段禁用 |
| 已同步 · 回读于 HH:MM | `read_ok` | 绿点；可编辑；锚点实线 |
| 设备未返回此配置 | `type_absent` | 灰点 +「该设备未返回图像叠加配置」+「2016 版无此类型」 |
| 已接受但值未生效 | `mismatch` | 黄点 + 设备错误码 |
| 读取或下发失败 | `failed` | 红点；透出**后端业务消息** |

⛔ 三条硬约束（都是本仓既有结论，别在 OSD 上放松）：

1. **`Result=OK` 不是终态** —— A.2.6.8 的应答体只有 `CmdType/SN/DeviceID/Result`，不回显任何配置；权威值只来自回读对账（`device_config_osd.go` 头部注释 + `device-config-center.md` 的 OSD 标准原文段）。
2. **一律不出现传输层文案**（`Request failed with status code 400`）。
3. **坐标只承诺「落到设备能做到的那一行」** —— 纵向（`timeY` / `items[].y`）会被设备**向下取整到行高 16 的整数倍**，横向是逐像素的（2026-09-20 真机控制变量扫描：下发 8/12/17/20/25/33/100/158/255 → 回读 0/0/16/16/16/32/96/144/240；TimeX 18/289/317 与文本行 X 25/33 全部原样回读）。所以差不足一行的回读值**不算**「值未生效」，不该弹黄点 —— 判据落在 `ptz/device_config.go` 的 `foldOSDPositionsToRowGrid`（只折**下发侧**：设备回一个不在网格上的值仍会报）。
   ⛔ 但**不改协议面**：平台照旧如实下发操作员拖到的坐标，折算留在对账里做；操作员在侧栏看到的最终值以回读落库的真值为准。

### 12.1 实现期新增的一条产品决定：编辑模式（§6.5）

**问题**：锚点层常驻在画面上，且盖着播放器。锚点随时可拖 ⇒ 用户"想点一下画面"就会顺手把某行字挪走；
而平台上**看不见真字**，这类误操作在画面上完全看不出来。判据：这不是猜测 —— 锚点 `pointerdown` 里
原本没有任何"用户意图"的门槛，`beginOsdDrag` 只挡了遮挡框选和设备事实。

**决定**：锚点**默认只读**，加一个「调整位置 / 完成调整」开关；进编辑模式后才可拖。
（按钮位置同日二次修订：从画面右上角搬到**画面之外**，见 §12.3。）

**代价（如实记录）**：多一次点击、多一个模式状态。缓解：
- 侧栏「在画面上拖动」直接进编辑模式（那本身就是显式意图）；
- `Esc` / 换页签 / 换通道都能退出，四者共用同一个 `exitOsdEditMode()`；
- 常驻说明与按钮标题**跟着模式改文案**，不许在拖不动的状态下写"直接拖动"。

### 12.3 二次修订：按钮搬出画面 + 只读态降噪（2026-09-20）

> ⚠️ 本节的两条**都已被 §12.4 取代**（按钮的最终落点在侧栏、只读态改成整层不画）。
> 保留在这里是因为"为什么会走到那一步"的推理链本身有价值 —— 尤其是"常驻按钮不许进画面"
> 这条判据，§12.4 没有推翻它，反而是它的延续。

老板上机看原型后提了两条，都成立，当天改完：

| 反馈 | 根因 | 修法 |
| --- | --- | --- |
| 「调整位置的按钮不应该放到视频播放画面上，这样会遮挡画面」 | 按钮是**常驻**的，钉在画面上等于永久占掉一块视频 | 搬到画面下方工具条（`.switcher-osd`），与「播放协议」同一行 |
| 「调整位置不进入编辑状态的时候时间戳不应该显示激活」 | 只读态沿用了编辑态的品牌蓝实心标签 ⇒ 那片画面看起来"全被选中" | 只读态改中性玻璃（半透明深底 + 浅灰字 + 空心圆点），品牌蓝只在编辑模式出现 |

**连带改动（都是这两条的必然结果，不是顺手做的）**：

- 只读态画面里**只放锚点**：原来那句挂在锚点层左下角的常驻说明删掉，只在编辑模式渲染；
  只读态的解释搬到按钮旁边那句（贴着可点的东西放）。
- 引导的闪烁对象从"锚点层那句说明"改成"**按钮本体**"（`osd-edit-guide` → `osd-edit-guide-v2`）——
  引导必须指着真正可点的东西，否则它指向的位置已经不存在了。
- 框选遮挡期间按钮从"不渲染"改成"**禁用**"：它现在在画面外、不会被框选层盖住，
  位置稳定比"按钮突然消失"好解释（原因写在 `title` 上）。
- 编辑模式的操作说明从**左下角搬到左上角**：左下角会被下发浮条（底部居中、最长铺满整行）压住 ——
  "刚拖完想确认怎么退出，说明却被盖住"是最不需要它出现的时刻。
