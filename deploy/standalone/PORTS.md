# ==============================================================
# UVP 绿色安装包 —— 端口规划
#
# 目标：① **整段连续、无空洞**（51000-51064，一个端口都不浪费）
#       ② 每个端口有唯一归属，不出现「两个组件抢同一个端口」
#       ③ 需要对外的与仅本机的分开标注（决定防火墙开不开）
#
# ==============================================================
#
# ## 规划段：51000-51064（65 个端口，全部用上、中间没有断点）
#
# ⛔ 为什么不用更低的段：
#   · 1024 以下是特权区，非 root 起不来（实测 RTSP 554 会报
#     "Listen on :: 554 failed: permission denied"）
#   · 系统与常见服务已占用：ssh 22、mysql 3306、redis 6379、
#     zlm 默认的 80/1935/554/8000/9000/10000/10554/3702 等等
#   · 49152-65535 是 Linux 的**临时端口范围**（客户端出站随机占用），
#     把服务放这里会和 `connect()` 抢端口，出现偶发的 bind 失败
#     ⇒ 规划刻意避开（ZLM 自己的 `[rtp_proxy]` / `[rtc]` 等池化端口默认就落在
#       这一带，不挪出来就是"文档写一段、实际跑另一段"）
#   · 50000-50999 虽是高位段，但在目标机上极易被占
#     （实测某机器：50051/50352/50665/51108…；hbase/zookeeper 常驻这一带）
#     ⇒ 规划刻意避开，落在 51000-51064。
#
# ⛔⛔ 为什么要**连续**（老板 2026-10-10 定）：
#   · 客户防火墙**一条规则**就能覆盖全部对外端口，不用一列一列地抄
#   · 中间不留空洞 ⇒ 不会有「这个端口到底归谁」的疑问，
#     也不会因为随手把别的服务放进空洞里而互相冲突
#   · 旧规划有 4 处大空洞（51002-51009 / 51012-51099 / 51110-51199 /
#     51200 之外的 51300+），已全部压平
#
# ⛔⛔ 换段**不能替代端口预检**：任何一段都可能被客户现场占掉。
#   所以 `uvp-ctl.sh start` 会**先逐端口检查占用**，发现被占就报出
#   「哪个端口、被谁占了」并给出处理办法，**不启动任何服务**。
#   （今天真实踩过：30000/30001 已被同机另一套服务占着，而 nginx 判活
#    只看「端口能不能连」⇒ 客户的浏览器看到的是**别的系统**的页面，
#    而包这边所有自检都显示「运行中」，全程零报错。）
#
# ==============================================================

# ---------------- ① 对外服务（防火墙需要开）----------------
# 客户侧设备/手机/浏览器要能访问的就是这一段
#
#  51000      nginx HTTPS            （浏览器访问管理页面）
#  51001      nginx HTTP             （跳 HTTPS；并为 /api/ 与
#                                      /gb28181/ 保留明文转发，
#                                      供模拟器 App 等只用 HTTP 的客户端）
#
#  51004      ZLM HTTP API           （平台调用：开关流、取配置）
#  51005      ZLM RTSP               （设备拉流播放）
#  51006      ZLM RTMP
#  51007      ZLM HTTP SSL           （ZLM 自身 HTTPS）
#  51008      ZLM WebRTC 媒体
#  51009      ZLM WebRTC 信令 WS     ⚠️ 键名是 signalingPort，不叫 port
#  51010      ZLM WebRTC 信令 WSS
#  51011      ZLM SRT
#  51012      ZLM ONVIF
#  51013      ZLM STUN/TURN          （icePort / iceTcpPort）
#  51014-51063 ZLM RTP 动态端口（UDP+TCP，成对占用 ⇒ 50 路会话）
#              ⚠️ 这是**设备把流推到平台**的入口，防火墙必须开 UDP
#              ⭐ 默认 50 个；不够时改 UVP_ZLM_RTP_RANGE 放大，
#                但**别越过 51063**（51064 是 SIP 预留位，放不进去）。
#              ⛔⛔ 真源是 `bin/zlm/config.ini` 的 **[rtp_proxy] port_range**
#                （ZLM 源码 `src/Common/config.cpp`: `RtpProxy::kPortRange`），
#                由 `uvp-ctl.sh` 的 `sync_zlm_ports_ini()` 写入 ——
#                写的是 **[rtp_proxy] 段**，不是 [rtp] 段（后者压根没有这个键，
#                2026-10-10 之前一直写错 ⇒ 实际跑在 ZLM 默认的 30000-35000）。
#                该函数末尾有**读回断言**，写不进去就中止启动，不会再静默放过。
#
#  51064      SIP（GB28181 设备注册）   ⚠️ UDP + TCP 双栈都要开
#              ⭐ 端口值由**管理员首次登录的引导页**录入、存进 gb_sip_config 表
#                （2026-07-20 起 SIP 明文配置从 YAML 移到了 DB，所以它
#                 **不经过 config.env**，改不了 config.env 那一套）。
#                出包时已把 51064 作为向导默认值注入前端
#                （build-standalone.sh 的 VITE_DEFAULT_SIP_PORT，见文末「SIP 端口怎么定」）。
#              ⚠️ 设备侧必须配成**同一个端口**（国标设备默认 5060，不自动跟随）。
#                扫码接入（二维码）会把平台当前的 SIP 地址:端口下发给设备，
#                支持扫码的设备不用手工填。
#              ❗ 它**不在 `uvp-ctl.sh` 的端口预检清单内**（脚本无从预知向导里最终填了什么）；
#                若该端口被占，保存引导页时会直接报 bind 失败。
#
# ---------------- ② 平台内部（防火墙不用开）----------------
# 同机进程之间通信，走回环；开到外网等于把内部接口暴露
#
#  51002      后端 HTTP              （API + 扫码落地页 + 二维码地址）
#  51003      Redis                 （仅监听 127.0.0.1，无密码）
#
# ---------------- 数据库 ----------------
#    SQLite 是**单个文件**（./data/uvp.db），不监听任何端口。
#    ⇒ 防火墙不需要为它开任何规则，这也是选它做绿色包默认库的原因之一。
#    （若客户改用 MySQL/PostgreSQL，3306/5432 走它们自己的规则，
#      不在本表内—— 那是外部依赖，不属于本包。）
#
# ==============================================================
# SIP / GB28181 的约定（与上面两段都不同，务必注意）
# ==============================================================
#
# ⛔ SIP 端口**已经并进规划段**（51064，见上表）—— 不再是 5060 的"段外例外"。
#
#   为什么以前不敢动：国标设备的 SIP 服务器端口**默认 5060**，设备侧是**逐台配的**；
#   平台一旦改端口，所有设备都得跟着改，现场几百台不可能手工改。
#   ⇒ 本包的对策：① 向导默认值就填段内端口（无需手工想）；
#                ② 扫码接入会把平台的 SIP 地址:端口**下发**给设备
#                   （不支持扫码的设备仍需手工配一次，且必须与平台一致）。
#   ⚠️ 也就是说：**改了 SIP 端口，存量设备就必须重新配置**。
#      新现场（先用本包后配设备）不受影响；老现场升级要评估。
#   ⇒ 若客户现场根本用不上 SIP 注册（只推流/录像查询），可以整段不放行 SIP。
#
# ⛔ SIP 用 UDP + TCP **双栈**，两个都要开。
#
# ⛔ hook 回调（ZLM → 平台）是**平台内部**方向，由 ZLM 主动连
#   127.0.0.1:51002，不需要开防火墙。
#
# ==============================================================
# 客户防火墙只需开这几条
# ==============================================================
#
#  1) TCP 51000-51064      一条规则覆盖全部对外端口（含 SIP 的 TCP）
#                          （内部的 51002/51003 也落在这段里，想精确排除就拆成
#                            TCP 51000-51001 + TCP 51004-51064 两条）
#  2) UDP 51011,51013,51014-51064
#                          SRT / STUN-TURN / RTP 收流 / SIP（都必须开 UDP）
#
# 💡 最小集 = ① + ② 两条就够（不用 SIP 注册时，把两条的末位截到 51063 即是原范围）。
#
# ==============================================================
# 改端口的办法
# ==============================================================
#
# 改 `config.env` 里的对应键（改动后 `./uvp-ctl.sh start` 生效）：
#
#   UVP_HTTPS_PORT=51500            nginx HTTPS
#   UVP_NGINX_HTTP_PORT=51501       nginx HTTP
#   UVP_HTTP_PORT=51502             后端
#   UVP_REDIS_PORT=51503            Redis
#   UVP_ZLM_HTTP_PORT=51504         ZLM 各协议（键名见上表端口右侧说明）
#   UVP_ZLM_RTP_RANGE=51514-51563   ZLM RTP 动态段（默认 50 个）
#
# ⛔ **SIP 例外：它不读 config.env**（见上「SIP 端口怎么定」）——
#   改它在**引导页**里改（存 gb_sip_config 表）；改了要重启后端生效。
#
# ⛔ 只改 config.env 的值还不够：ZLM 的端口最终写进 `bin/zlm/config.ini`，
#   由启动脚本按同名环境变量同步 —— 键名必须对应，否则改不动。
# ⛔ 改完先跑 `./uvp-ctl.sh start`，它会**先做端口预检**再启动；
#   端口冲突时会明确报出「哪个端口被谁占了」，按提示处理即可。
# ⛔ 若把整段平移（如 51500 起），记得**保持连续**，并同步更新本文件。

# ==============================================================
# SIP 端口怎么定（它和上面所有端口都不一样，单独说清）
# ==============================================================
#
# 链路：出包时注入默认值 → 管理员在引导页确认/修改 → 存 gb_sip_config 表
#       → 后端按它 bind → 扫码接入把它下发给设备。
#
#   1) 出包：`build-standalone.sh` 用 `UVP_SIP_PORT`（默认 51064）注入前端
#      `VITE_DEFAULT_SIP_PORT`；**构建后立刻读回 dist 断言**，注入没生效就直接失败。
#   2) 前端：`useSipSetup.ts` 的 `defaultSipPort()` 读该变量，非法/缺失回落 5061
#      ⇒ 只有本包预填 51064，其它构建形态（开发、其它交付包）行为不变。
#   3) 现场改端口：引导页里改（**不是** config.env）。
#      ⚠️ 改完必须让设备侧也改成同一端口，否则设备注册不上（平台日志里
#         表现为设备"从未上线"，而平台侧看不出任何错）。
#
# ==============================================================
# TURN：已关闭（2026-10-10 决议）—— 不是"用不到"，是"根本没接上"
# ==============================================================
#
# 结论：`[rtc] enableTurn` 由 `uvp-ctl.sh` 每次启动**强制写成 0**。
#
# 判据（三条，都是代码级，缺一不可）：
#  1. 平台只会给浏览器发 STUN，从不发 TURN —— `app/gb28181/talk/ice.go` 的
#     `BuildICEServers()` 只构造 `"stun:" + endpoint`（该文件注释原文：
#     "TURN 凭据在启用中继时再补，**当前不下发**"）；全仓 `server/` + `web/src/`
#     搜 `turn:` **零命中** ⇒ 浏览器永远拿不到中继地址与凭据。
#  2. 而且只有**对讲上行**这一条路会下发 ICE 列表（播放侧 ws-flv / hls /
#     WebRTC 都不给浏览器配 iceServers）；默认播放协议本就是 ws-flv。
#  3. 门禁 = 节点登记了 `rtc.externIP`（顺带当"跨网段开关"）：没填就**直接不发**。
#     ⇒ 跨网段/公网要用 WebRTC，**必须把 `rtc.externIP` 填成公网地址**，
#       并放行 51013（UDP/TCP，STUN）。
#
# 为什么干脆关掉、而不是给它划段：
#  · `[rtc] port_range` 默认 49152-65535，占的是 Linux **临时端口区**
#    （客户端出站 connect 随机占用同一段）⇒ 开着就是一颗雷；
#    而它带来的收益是 0（见上面三条）⇒ 保留没有意义。
#  · 关掉后规划段仍是 51000-51064，不需要为它多开一段
#    （原「51065-51099」方案**作废**）。
#
# ⚠️ 将来真要开中继（浏览器在严格 NAT 后面 + 必须用 WebRTC 低延迟），
#   **三步缺一不可**：① `uvp-ctl.sh` 的 `ZLM_ENABLE_TURN` 改成 "1"；
#   ② `[rtc] port_range` 挪出临时端口区（如 51065-51099）；
#   ③ 防火墙上放开该段（UDP）。只做 ① 等于又埋一次同样的雷。
#
# ⚠️ 启动时会**回读校验** `[rtc] enableTurn`，但策略与 port_range 刻意不同：
#   键在、却写不进去 ⇒ **中止启动**（同步逻辑坏了）；
#   键根本不存在（旧版 ini / 手改过）⇒ 告警但继续启动（一个死开关不该拦住上线）。
#   另外平台侧**不碰**这个键（`zlm/service/config_service.go` 的 configCatalog
#   是白名单，里面没有 `enableTurn`）⇒ 不会被 UI 改回去。

## 附：ZLM secret（启动时自动对齐，无需人工填）

`config.yml` 的 `gb28181.zlm.secret`在示例里是占位符 `CHANGE_ME`，
而 ZLM 真正的密钥在 `bin/zlm/config.ini` 的 `[api] secret=`（构建时随机生成）。

**`uvp-ctl.sh start` 会自动对齐**：以 `config.ini` 为准，把真值写进 `config.yml`。
两条硬规则：

- 只在原值是占位符（`CHANGE_ME` / `TODO` / 空）时才写 ⇒ 运维手工填过的真值不被覆盖，重复启动也幂等。
- **绝不改 ZLM 那侧** —— 改它会让已在运行的 ZLM 与配置脱节、hook 全部失效。

⚠️ 对不齐的后果（实测踩过，报错完全指不到真因）：
平台调 ZLM 全被拒 `{"code":-100,"msg":"Please login first"}`
→ ZLM 节点配置恢复失败 → 录像缓存/点播/录像查询 runtime 全部跳过装配
→ 页面报「**录像缓存服务未装配**」，而 ZLM 进程本身活得好好的。

## ⛔⛔⛔ 绝不能用 ZLMediaKit 的官方默认 secret

```
035c73f7-bb6b-4889-a715-d9eb2d1925cc   ← ZLMediaKit 官方默认，禁止使用
```

二开版 `server/main.cpp:301` 有硬编码规则：secret **等于该默认或为空**时，
自动 `makeRandStr(32)` 换成随机值，并 `dumpFile` **写回 `config.ini`**。

⇒ 包里把这个值写死也没用：**装完启动一次就被 ZLM 自己改掉**，
而平台侧 `config.yml` 不知道 ⇒ 双方永久失配。

⭐ 症状极具误导性：ZLM 日志里所有成功请求都带着旧 secret
（它启动时已经把值读进内存了），只有配置文件变了 —— 表面完全正常，
**只有重启后才暴露**。这是本项目最隐蔽的一处"看起来对、实际错"。

绿色包使用的固定值：
```
secret          = uvp-9f3c7a1e5d84b206c1a9e4f7b2d6c805
mediaserverid   = uvp-media-server-0001
```
