# ==============================================================
# UVP 绿色安装包 —— 端口规划
#
# 目标：① 全部落在**高位连续区间**，客户只需开一条防火墙规则
#       ② 每个端口有唯一归属，不出现"两个组件抢同一个端口"
#       ③ 需要对外的与仅本机的分开标注（决定防火墙开不开）
#
# ==============================================================
#
# ## 总区间：30000-39999（1024 个端口，够用且不碰系统保留段）
#
# ⛔ 为什么不用更低的段：
#   · 1024 以下是特权区，非 root 起不来（实测 RTSP 554 会报
#     "Listen on :: 554 failed: permission denied"）
#   · 系统与常见服务已占用：ssh 22、mysql 3306、redis 6379、
#     zlm 默认的 80/1935/554/8000/9000/10000/10554/3702 等等
#   · 49152-65535 是 Linux 的**临时端口范围**（客户端出站随机占用），
#     把服务放这里会和 `connect()` 抢端口，出现偶发的 bind 失败
#     ⇒ ZLM 原本的 `[rtp] port_range=49152-65535` **必须改掉**
#
# ==============================================================

# ---------------- 对外服务（防火墙需要开）----------------
# 客户侧设备/手机/浏览器要能访问的就是这几个
#
#  30000-30009  UVP 前端与管理后台（HTTPS）
#               nginx 独占 TLS，后端不设 TLS ⇒ 扫码走明文也不碰证书
#    30000      nginx HTTPS            （浏览器访问管理页面）
#    30001      nginx HTTP             （跳 HTTPS；并为 /api/ 与
#                                        /gb28181/ 保留明文转发，
#                                        供模拟器 App 等只用 HTTP 的客户端）
#
#  30100-30999  ZLM 流媒体（设备推流 / 平台拉流）
#    30100      ZLM HTTP API           （平台调用：开关流、取配置）
#    30101      ZLM RTSP               （设备拉流播放）
#    30102      ZLM RTMP               （如需 RTMP 推流）
#    30103      ZLM HTTP SSL           （如需 ZLM 自身 HTTPS，默认关闭）
#    30104      ZLM WebRTC媒体         （如需浏览器 webrtc）
#    30105      ZLM WebRTC 信令 WS      ⚠️ 键名是 signalingPort，不叫 port
#    30106      ZLM WebRTC 信令 WSS
#    30107      ZLM SRT
#    30108      ZLM ONVIF
#    30200-30299 ZLM RTP 动态端口（UDP+TCP，成对占用 ⇒ 100 个会话）
#               ⚠️ 这是**设备把流推到平台**的入口，防火墙必须开 UDP
#
# ⛔⛔ ZLM 的端口**必须成体系地挪**：config.ini 里有 11 个段各带监听端口，
#   漏掉任何一个都会让 ZLM 整体起不来（它bind 失败即进程退出），
#   而 status 只看 HTTP 端口(30100) ⇒ 会报「运行中」但推流/录像全废。
#   ⚠️ 最隐蔽的是 **WebRTC 信令**（signalingPort/signalingSslPort）——
#   键名不叫 port，按"段名 + port"匹配抓不到；容器默认 3000/3001 在目标机上
#   常已被占用 ⇒ 实测报 `Listen on :: 3001 failed: address already in use`。
#
# ---------------- 平台内部（防火墙不用开）----------------
# 同机进程之间通信，走回环；开到外网等于把内部接口暴露
#
#    30010      后端 HTTP               （API + 扫码落地页 + 二维码地址）
#    30011      Redis                  （仅监听 127.0.0.1，无密码）
#    30012      SIP 5060 映射位         （GB28181 设备注册，见下方说明）
#
# ---------------- 数据库 ----------------
#    SQLite 是**单个文件**（./data/uvp.db），不监听任何端口。
#    ⇒ 防火墙不需要为它开任何规则，这也是选它做绿色包默认库的原因之一。
#    （若客户改用 MySQL/PostgreSQL，3306/5432 走它们自己的规则，
#      不在本表内—— 那是外部依赖，不属于本包。）
#
# ==============================================================
# GB28181 的特殊约定（与上面两段都不同，务必注意）
# ==============================================================
#
# ⛔ SIP 的 5060 是**国标协议规定**的端口，设备侧是写死的 ——
#   改端口就必须同步改每一台设备的配置，现场几百台设备不可能改。
#   ⇒ 平台侧监听 5060，做 NAT 转发把它映射到 30012。
#   ⇒ 若客户现场用不上 SIP 注册（只用推流/录像查询），可以不放行。
#
# ⛔ SIP 用 UDP + TCP **双栈**，两个都要开。
#
# ⛔ hook 回调（ZLM → 平台）是**平台内部**方向，由 ZLM 主动连
#   127.0.0.1:30010，不需要开防火墙。
#
# ==============================================================
# 客户防火墙只需开三条
# ==============================================================
#
#  1) TCP 30000         浏览器访问管理页面
#  2) TCP 30001         （可选）HTTP 入口，跳 HTTPS
#  3) TCP 30010         设备/客户端调API、扫码接入（若走明文入口）
#  4) TCP 30100-30104   ZLM 流媒体
#  5) TCP+UDP 30200-30299  RTP 收流
#  6) UDP+TCP 5060      GB28181 设备注册（按需）
#
# 💡 若客户嫌规则多，可只留 ① ④ ⑤ 三条（管理页面 + 拉流 + 收流），
#    其余在需要时再加。
